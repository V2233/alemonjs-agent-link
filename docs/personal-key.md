# 私聊个人 API Key

支持 DeepSeek 官方 Key。每个平台、用户单独保存，仅本人私聊可管理和使用，群聊、主动搭话识别及其他人的私聊不会借用它。原有私聊访问权限与全局 AI 开关仍然有效。

| 私聊指令                    | 作用                               |
| --------------------------- | ---------------------------------- |
| `/个人密钥 绑定 sk-你的Key` | 保存并启用个人 Key                 |
| `/个人密钥 状态`            | 仅显示绑定与启停状态，不回显 Key   |
| `/个人密钥 启用`            | 手动启用，下一次请求检查余额       |
| `/个人密钥 停用`            | 停用并恢复机器人额度模式，保留绑定 |
| `/个人密钥 移除`            | 删除绑定并恢复机器人额度模式       |

`/apikey` 是同义入口。只能操作自己的账户，不需要机器人主人权限。仍是手动管理，没有自动充值；绑定消息经过聊天平台，应仅在私聊发送。若误发到群中，请撤回并到服务商后台更换密钥。

## 选择和回退

启用时优先使用个人 Key，模型调用不扣机器人的个人免费、私聊免费或充值余额。每次请求前通过官方 `GET /user/balance` 查询；`is_available: false` 或模型请求返回 HTTP 402 才视为余额不足，自动持久化停用，后续回到原有额度预扣和结算流程。个人 Key 余额恢复、机器人重启或北京时间零点刷新，都不会自动重新启用；需要手动发启用指令（重新绑定也视为显式启用）。

绑定并启用个人 Key 后，本人私聊的主动搭话按拉满参数运行（空闲 20 分钟、每天最多 10 次、忽略随机间隔），详见[私聊主动搭话](modules.md#私聊主动搭话)。配置 `proactive.ownKeyMax: false` 可关闭这项提权，只保留 Key 的付费作用。

401、403、429、网络错误、超时和无法解析的余额返回不会被当成欠费，也不会偷偷使用机器人余额。未绑定或已停用时不再查询个人 Key。全局 AI 关闭时仍不调用模型。

普通模型请求收到 402 后，只重试这个尚未成功的模型请求并执行机器人额度预扣，不重新执行已完成的业务工具。工作区途中返回余额不足时自动停用个人 Key，并提示重新发送请求；不会自动重跑整个工作区，避免重复文件修改或其他工具动作。已在执行的调用可能继续完成；手动停用约束后续请求。

DSH 工作区的模型出口也使用当前私聊的个人 Key。真实 Key 仅保留在主服务和受认证的本机 Bridge 内存中，不放入模型提示词、工作区文件或子进程环境。独立配置的识图、语音识别和语音合成服务继续使用各自服务配置，不能用 DeepSeek 文本 Key 代替其他服务的凭证。

## 保存和迁移

使用 Redis 保存 AES-256-GCM 加密后的 Key 与启停状态，不新增 SQL。加密主密钥位于 `.data/agent-link/personal-key.key`，新文件权限为 0600，需与 Redis 数据一起备份并妥善保护；缺失或损坏会影响已绑定 Key 的解密。部署多个实例时必须安全共享同一加密主密钥。可信启动环境可用 `AGENT_LINK_PERSONAL_KEY_FILE` 指定文件位置。

已知的 `/个人密钥`、`/apikey` 管理指令不进入应用聊天归档、引用记录或主动搭话输入观察；管理回复不回显 Key。应用无法删除聊天平台已有的消息记录。重复投递同一管理消息不会再次绑定或启用；旧请求的欠费结果通过版本比较更新，不能关闭后来新绑定或手动启用的 Key。

服务商依据：[官方余额接口](https://api-docs.deepseek.com/api/get-user-balance/)与[官方错误码](https://api-docs.deepseek.com/quick_start/error_codes/)。

群共用 Key 的管理员临时码流程见 [群 Key 管理](group-key.md)。
