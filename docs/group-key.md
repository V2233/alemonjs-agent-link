# 我的钥匙与群授权

真实 Key 只在私聊提交。私聊钥匙仅本人私聊使用，群聊钥匙仅供授权后的群使用。

- `/我的钥匙`：私聊显示用途入口和群聊钥匙编号；群聊仅管理员可查看自己可授权的群聊钥匙编号。
- `/我的钥匙 私聊 添加 sk-你的Key`：保存私聊钥匙 1；支持 `启用`、`停用`、`移除`。
- `/我的钥匙 群聊 添加 sk-你的Key`：保存群聊专用钥匙，分配稳定编号。
- 管理员在目标群发送 `/授权钥匙 1`：复制对应钥匙到本群，不显示密钥、提供者资料。已有群钥匙时拒绝覆盖。
- 任一本群管理员在群内 `/我的钥匙` 点击“移除”（`/我的钥匙 移除`）：移除当前群副本，包括已停用和旧绑定的钥匙；不要求管理员是提供者。
- 提供者私聊 `/授权记录`：查看记录编号、群标识与钥匙编号；群管理员移除后显示“授权已失效”，可清理记录。
- `/授权记录 移除 记录编号`：撤销该群副本，保留原始钥匙及其他群授权。已发出的请求可能继续完成。

提供者与群副本通过授权标识关联；余额停用不会丢失归属，过期记录不能误删新授权。存储采用原有 Redis 和 AES-256-GCM 加密主密钥，授权写入与记录更新原子提交。

群响应不公开提供者身份，但平台仍显示指令发送者，不能保证社会意义上的匿名。旧群绑定不会自动推定提供者，需人工迁移；旧临时码入口不再开放。

这个设计让个人保管凭证、群获得使用权，减少群内明文泄漏，隔离私聊与群聊的付费用途，并让出资者保留撤销权。

## 流程回归测试

安装 Redis 后使用独立临时实例测试，不连接业务库：

```sh
npm run build
AGENT_LINK_TEST_REDIS_SERVER="$(command -v redis-server)" node --test --test-force-exit test/keyring.test.mjs test/command-bubble.test.mjs
```

测试覆盖用途隔离、管理员和账号边界、加密副本、私聊授权记录、并发授权、余额停用后撤销、跨群不受影响及旧记录不误删新副本。未指定 Redis 服务端可执行文件时，存储集成测试明确跳过。

## 扫码预备两种用途

私聊 `/个人登录` 完成微信扫码授权后，一次性准备私聊钥匙与一把有编号的群聊钥匙。群聊钥匙仅存入“我的钥匙”，不自动授权任何群；以后在目标群发送 `/授权钥匙 编号` 即可。暂时不用群聊钥匙不影响私聊，也无需到每个群重新登录或创建凭证。

两种用途共用一次账户授权，属于用途条目，不是平台创建了两把 API Key。已有私聊钥匙保留不覆盖；重复登录不会重复添加群聊钥匙。私聊启停和移除仅作用于私聊条目；`/授权记录 移除 编号` 只撤销对应群副本。明确发送 `/个人退出` 才移除该扫码账户全部用途及当前关联群副本并退出远端账户，保留手动添加的其他钥匙。

扫码钥匙沿用 Redis 和 AES-256-GCM 存储；准备两种用途原子提交，失败不留下半套条目。群授权保留账户认证类型，普通聊天使用账户令牌；沙箱工作区暂不支持。

## 额度保护

管理员可在本群 `/我的钥匙` 启用、停用钥匙；欠费后暂停，充值后需启用。普通 Key 与扫码账户均不自动换用机器人额度，显式停用或移除后才切换。

`/我的钥匙 上限 5` 设置本群钥匙每日模型预算为 5 元，0 表示暂停钥匙调用。上限跨钥匙替换保留，改上限不会清空当天用量；现有群默认未设置，不自动改变已授权的使用范围。预算采用请求前保守预占、完成后按 usage 结算，缺失 usage 或断流保留预占；未计量的图片和沙箱工作区在设置上限后拒绝调用。金额是模型预算，不是服务商账单担保，不限制同账户在其他应用中的消费。

机器人充值额度跨天保留；升级仅迁移当天旧账本未使用余额，旧待结算充值请求需先完成。免费与感知预算仍每天重置。
