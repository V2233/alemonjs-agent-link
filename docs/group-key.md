# 群 API Key

支持 DeepSeek 官方 Key。群管理员先在目标群申请临时码，再由同一账号私聊机器人完成操作；不在群里提交 Key。

| 操作       | 管理员在群中发送 | 同一管理员私聊机器人发送         |
| ---------- | ---------------- | -------------------------------- |
| 绑定或更换 | `/群密钥 绑定`   | `/群密钥 绑定 临时码 sk-你的Key` |
| 启用       | `/群密钥 启用`   | `/群密钥 启用 临时码`            |
| 停用       | `/群密钥 停用`   | `/群密钥 停用 临时码`            |
| 移除       | `/群密钥 移除`   | `/群密钥 移除 临时码`            |
| 查状态     | `/群密钥 状态`   | 无需提交密钥                     |

绑定也可简写为私聊 `/群密钥 临时码 sk-你的Key`。`/groupapikey` 是同义入口；`开启` 与 `启用` 同义，`关闭` 与 `停用` 同义。绑定会启用 Key；余额不足后恢复使用同样需要重新在群里申请启用码，再由申请人本人私聊提交。

## 身份与临时码

- 只有平台确认的群管理员或群主可在群里申请，不以机器人主人身份替代群管理身份。优先使用标准 `Role`（`admin`、`owner`），兼容可信的 `IsAdmin` 标记；缺少身份时，通过现有成员资料接口查询当前发言人的 `Role`，仅接受 `admin`、`owner`，并核对用户与群身份。查询失败或不支持时拒绝发码。
- 临时码绑定平台、群、申请人和操作，Redis 服务端计时，5 分钟有效。提交时必须来自同平台、同用户的私聊；仅凭群中看到的码无法替别人操作。平台需在群聊与私聊中提供一致的用户身份，不会用昵称猜测或放宽身份校验。
- 申请人在本群重新申请，会使其旧码失效；重复投递同一申请消息不会产生新码。管理员权限在群内申请时验证，临时码代表这 5 分钟内的单次授权。
- 验证与修改群 Key 在 Redis Lua 中原子执行。临时码只能修改一次；并发提交或重放不会再次绑定、启用，也不会让后来自动停用的 Key 重新启用。绑定码不能用于停用，停用码也不能更换 Key。

## 使用与回退

启用后，该群的聊天、业务模型调用、主动搭话识别和 DSH 工作区优先使用群 Key，不扣内部的个人免费、群充值或感知预算。群主动识别使用 DeepSeek 官方低成本识别模型；不会把群 Key 发往配置的其他服务商。

Key 只属于对应平台与群，不进入其他群或任何用户私聊。余额检查、402 欠费停用、网络故障不误判、手动恢复、工作区不自动重放等规则与 [个人 Key](personal-key.md) 相同。确认欠费停用后依次回退本群充值、个人免费；后台判断最后回退本群感知预算；服务重启、零点或服务商充值不会自动启用。

共享机器人凭证不因群绑定而更改，独立的语音、识图服务仍使用各自的服务配置。参与强度是例外：绑定可用的群 Key 会把本群"强度拉满"——关闭感知判断、插话冷却归零、每小时上限抬到 60 次，并自动开放网页与文件工具（终端始终禁止；主人可用 `groupChat.boundKeyTools: false` 只关工具、保留参与度）。这是运行时派生，不写回群密钥状态，也不改变 `/工具策略` 已保存的设置；按群设 `groupChat.overrides.<群ID>.boundKeyElevation: false` 可退出。细节见[群聊参与策略](config.md#自带-key-的群强度拉满)。`/额度` 会标明群 Key 优先模式，具体绑定、启停状态与权益由群管理员用 `/群密钥` 查询。

## 保存与隐私

Redis 保存加密的群 Key 与状态，复用 `.data/agent-link/personal-key.key` 加密主密钥，备份与多实例部署要求参见 [个人 Key 管理](personal-key.md)。群管理指令、私聊提交与包含这些指令的编辑消息不会进入应用聊天归档或模型引用；机器人不回显 API Key。临时码会在群内公开显示，权限还受申请人身份与操作绑定约束。
