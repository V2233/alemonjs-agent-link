# 问答库

问答库保存“为什么 / 为何 / 为啥”这类问因问题的标准答案。它和长期记忆是两条线：记忆描述人或群的事实与偏好，问答库保存“问题 → 答案”，用于在同类疑问出现时优先复用已经确认过的解释。

## 怎么工作

1. 每轮回复前检查用户消息是否包含问因词（为什么、为啥、为何、怎么会、什么原因、why、how come 等）。
2. 命中问因词时，在当前会话已记录的问答和全局内置问答中检索，按问题覆盖率、精确包含、关键词、来源可信度、命中次数与时间排序。
3. 有匹配时，把问题与答案作为本轮参考资料提供给模型，并要求优先采用，同时用大白话和日常比喻解释；`builtin` / `explicit` 视为已确认，`learned` 只是本会话此前的回答，可能过时。
4. 没有匹配时，提醒模型用大白话按实际配置、文档和已知事实回答，不要把“问答库没有”当成“没有答案”。
5. 回复成功送达后记录这次提问。若本轮没有命中任何条目，就把“问题 + 已送达的回答”写入当前会话，成为下次检索的 `learned` 条目；已有同问题的记录只更新答案与时间，不重复占名额。

检索门槛刻意偏严：短句里出现“为什么”并不等于同一件事。只有问题覆盖率足够、命中关键词、或问题文本精确包含时才进入候选，避免“为什么天空是蓝的”命中“为什么必须 AT 才回答”。默认每次最多注入 3 条，并且只保留与第一名得分接近的候选（不低于第一名约 80%），避免一个问题被拆成多条互相矛盾的答案。

## 内置问答

随包发布的内置条目覆盖首次使用时最容易误解的稳定行为与能力边界：

| 类别   | 内置问题                          |
| ------ | --------------------------------- |
| 唤醒   | 为什么必须@你（AT你）才回答？     |
| 不回复 | 为什么@你之后还是没有回复？       |
| 群参与 | 为什么你在群里不主动接话？        |
| 排队   | 为什么回复这么慢/要排队？         |
| 记忆   | 为什么你记不住刚才说的/没有记忆？ |
| 工具   | 为什么你不能上网/查资料/读文件？  |
| 媒体   | 为什么你不能发语音/画图/看图？    |
| 群管理 | 为什么你不能禁言/踢人/改公告？    |
| 私聊   | 为什么私聊你不回？                |
| 额度   | 为什么额度不足/没有额度？         |

其中“必须 @ 才回答”来自真实群聊里的重复疑问：

> **为什么必须@你（AT你）才回答？**
>
> 可以把它想成坐在隔音玻璃后面的店员：qq-bot 没给它开“接收全面消息”，群里普通聊天它听不见，只有你 @ 它、叫它或引用它时，才像敲了敲玻璃。想让它自然接话，就在 qq-bot 的机器人设置里打开“接收全部群消息”；用 OneBot 接入的话，检查转发消息的那一头是不是只把 @ 消息转给它。还要确认群聊参与没关。只想让它被叫到才回，保持现状也行。

这些条目只回答稳定的产品行为和权限边界，不包含实时状态。当前额度、模型是否在线、本群是否开放网页/文件、今天为什么特别慢等，应使用 `/额度`、`/状态`、`/工具策略 状态`、`/群设置` 查询；问答库不会猜当前原因。“为什么不能用”这类过于宽泛的问法不会命中任何内置条目，避免给出错误的具体原因。

答案面向普通群友，不假设对方懂代码。写法上先给一句人话或比喻，再说原因和最短操作；内部词能不用就不用，必须提命令时保留原样。比如把后台进程说成“后台店员”、把记账服务说成“记账本”、把隔离运行环境说成“单独的工作间”。不要照读配置键，除非对方是主人且确实需要改配置。

内置条目随安装包发布，全局生效，不随某个群的数据清理而删除。启动时只刷新 `origin=builtin` 的条目；主人在聊天里手动修正过的同问题条目不会被覆盖。维护者新增随包发布的问答时编辑 `src/qa/builtin.ts`，保持 `id` 稳定，并同步用于匹配的关键词。

## 配置

```yaml
alemonjs-agent-link:
  modules:
    settings:
      qa:
        autoRecord: true # 记录问因提问，并把未命中的问答写入当前会话
        recallLimit: 3 # 每次注入最多几条（1-10）
        matchThreshold: 3.5 # 匹配门槛，越高越严格（1-20）
```

停用模块使用 `modules.disabled: ['qa']`。停用后不再检索、注入或自动记录，已有 `qa.sqlite` 数据保留；重新启用后继续使用。

## 管理

- 所有人：对话里直接问“为什么……”，命中时会优先使用问答库；模型也可以调用只读工具 `search_qa` 主动检索。
- 机器人主人：明确说“记住这个问答：为什么…… 答案是……”后，模型可调用 `remember_qa` 保存。`scope: session` 只写入当前群或私聊；`scope: global` 写入所有会话共用的问答，适合机器人的能力说明、群规等公共问题。
- 自动整理的 `learned` 条目只在产生它的群或私聊里生效，不会跨群读取。
- `/清除群数据` 会删除当前会话的问答、提问记录和长期记忆；内置与主人写入的全局问答不受影响。
- 问答库跟随 `retentionDays`：长期没有问答活动的会话，其问答和提问日志会在启动及每小时清理时删除。

## 数据与边界

问答存储在 `workspaceRoot` 同级的 `qa.sqlite`，文件权限为 `0600`。提问日志每个会话最多保留最近 200 条，自动学习条目每个会话最多 200 条；超过上限后不再自动新增，但仍可检索已有条目和手动保存。

自动学习只保存已经成功送达的回复，不保存失败、超时、取消或内容安全拦截的结果。它不判断回答是否永远正确：模型可能给出过时或片面的解释，因此 `learned` 条目在注入时会明确标注“可能过时”。需要稳定口径的问题应由主人用 `remember_qa` 转成 `explicit` 条目。

问答库不是通用知识库，也不替代网页查询或文档。它只覆盖“有人问过、并且回答已送达”的问题；没有命中时应继续使用现有工具与事实回答，而不是编造库中不存在的内容。
