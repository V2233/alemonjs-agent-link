# Redis 每日额度保护

在已有 `alemonjs-agent-link` 配置内合并以下内容，保留 API Key 和其他设置。额度统计只用现有 `db.redis`，不需要 SQL 服务；不会改变已有聊天归档和记忆存储。

```yaml
alemonjs-agent-link:
  budget:
    enabled: true
    groupDailyYuan: 2
    privateDailyYuan: 1
    globalDailyYuan: 0 # 0 表示不设全局上限；例如 20 表示全局每天最多 20 元内部预算
    maxOutputTokens: 2048
```

首次安装代码需要重启服务。之后金额配置支持现有配置热更新。未配置 `budget.enabled: true` 的安装保持原有行为。该仓库的本机运行配置已单独开启；运行配置被 Git 忽略，不会随源码部署到其他机器，部署时也须合并以上配置。

## 规则和统计

- 同平台同群共享每天 2 元；同平台每个私聊用户独立 1 元，包括主人。以 Redis 时间确定北京时间日期，跨天使用新的账本，不依赖定时清零。跨天完成的调用结算回发起日。
- `/额度` 无需调用模型，可查询当前会话剩余金额、请求次数、计入的输入/输出/缓存 token（图片请求的输入为文字估算值）、预留及待核实金额。主人私聊还可看全局已计入金额。所有统计键保留 32 天。
- 直接聊天、业务工具的每一轮模型调用、情绪判断、记忆整理、主动搭话都走同一额度账本。智能回复判断不占用每日聊天额度，但执行前仍须检查会话与全局额度。作用域包含平台和会话，群之间、不同平台之间、群和私聊之间不混用。
- Redis Lua 原子检查会话和全局额度、预扣、统计请求数；完整响应中的 usage 用来结算并退还差额，每个请求最多结算一次。流式开启 `stream_options.include_usage` 并处理独立 usage 尾帧。
- 输出 token 设置硬上限；文本输入以 UTF-8 字节数加 8192 的格式开销保守预留。剩余额度不足以预留时会提前拒绝，请缩短上下文或等次日，不保证恰好花到限额。工具循环每一轮都需要重新预扣。
- 超时、取消、HTTP/网络错误、缺少有效 usage、进程崩溃，均保留本次预扣，计入“预留／待核实”；不会假定失败就是免费。手动清空会话、`/new`、数据清理、重启均不能恢复额度。系统不会自动退还无法核实的历史预扣。
- Redis 不可用、缺少会话身份或模型/服务商价格未知时，拒绝付费请求，不降级到内存记账。Redis 应开启 AOF，避免用带淘汰策略的缓存实例；删除账本、Redis 数据丢失仍会使额度重置。
- 原子预扣用于预算保护，并非提供商账单审计；若提供商返回的用量超过预留，也如实计入，不截断隐藏超额。账本不包含启用之前的历史消费。

## 限额后停止判断与提示频率

智能回复判断不预扣、不结算每日聊天额度。达到会话/全局额度，或聊天请求因预留金额不足被拒绝后，后续智能判断在调用模型前检查 Redis，额度不足就直接停止，不再请求判断模型。主人追加额度、结算退回预留、或次日额度刷新后，只要额度重新足够，判断可恢复。已有的短时并发和防循环保护仍保留。

对直接呼唤、显式聊天和私聊请求，额度不足提示按**平台与会话共享**的滚动窗口限制：最近 1 小时最多 3 次、最近 6 小时最多 5 次、最近 24 小时最多 7 次；任一达到上限就静默。普通群聊和主动搭话不会因为额度不足刷提示。三个窗口使用同一条 Redis Lua 原子判断，并对重复消息去重，群聊判断入口和正式聊天入口共用计数，重启不清零，零点也不清空仍在滚动窗口内的提示。发送前占用提示次数，发送失败不会自动返还，以免反复重试刷屏。额度查询与主人管理不受该提示限制。

## 主人手动管理

所有金额单位为元，最多两位小数，总额度范围为 0–10000 元。除 `/额度` 查询当前会话外，以下管理指令仅机器人主人可使用，群管理员不会自动获得权限。

| 指令                       | 作用                                            |
| -------------------------- | ----------------------------------------------- |
| `/额度 帮助`               | 显示指令说明                                    |
| `/额度 增加 2`             | 给当前群或本人私聊今天追加 2 元                 |
| `/额度 设置 5`             | 将当前会话今日**总额度**设为 5 元，并非剩余额度 |
| `/额度 查询 群 群ID`       | 查询指定群今天的额度                            |
| `/额度 增加 群 群ID 2`     | 给指定群今天追加 2 元                           |
| `/额度 设置 私聊 用户ID 3` | 将指定用户私聊今天的总额度设为 3 元             |
| `/额度 记录`               | 查看当前会话今天最近 5 次手动调整               |
| `/额度 记录 群 群ID`       | 查看指定群今天最近 5 次手动调整                 |

查询、增加、设置、记录均支持 `群 群ID` 或 `私聊 用户ID`，只管理发送指令的当前平台。QQ 官方机器人须使用该平台实际的群/用户 ID；不能假定它等于 QQ 号码。无目标参数时使用当前会话。

调整只影响今天，零点恢复配置中的每日默认额度；**不清除消费和预留，也不会突破已配置的全局预算**。例如已用 1 元，设置为 5 元后剩余 4 元；设置为 0 元会阻止新的调用，但不会撤回已经发出的请求。管理指令不调用模型。

使用 Lua 原子更新、按原始消息编号防重复加额；缺少可靠消息编号时拒绝写入。调整记录包含主人 ID、时间、操作、金额和调整前后总额，最多保留当天最近 1000 条、保留 32 天，查询指令展示最近 5 条。超时后可查询 `/额度` 和 `/额度 记录` 核实，不要盲目重新发送加额指令。

这些指令只管理内部预算，**没有支付接口、自动充值或向服务商充值的功能**。如需增加服务商余额，由主人自行操作服务商后台。

## 当前计费口径

以 2026-10-26 核验的 [DeepSeek 官方人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)为依据，统一按高峰价计算内部预算，空闲时实际扣款通常更低。金额用整数微元保存，不做浮点累计。

| 模型                                                            | 缓存输入／百万 token | 非缓存输入／百万 token | 输出／百万 token |
| --------------------------------------------------------------- | -------------------: | ---------------------: | ---------------: |
| deepseek-flash、deepseek-v4-flash、deepseek-v4-flash-vision-exp |              0.04 元 |                   2 元 |             8 元 |
| deepseek-v4-pro                                                 |              0.30 元 |                   9 元 |            27 元 |

仅允许官方 `https://api.deepseek.com/chat/completions` 或 `/v1/chat/completions`。未知模型、中转地址不会套用官方价放行。价格变动时需要更新价格表。

**图片聊天已恢复：预扣时排除图片 URL 和 base64，只计算文字及工具描述。** 图片请求的服务商输入 usage 可能混有图像 token，因此结算使用文字投影的 UTF-8 字节数除以 3 向上取整（不超过服务商总输入 token），输出仍按返回的 completion_tokens 统计。图片本身不计入内部额度；这是宽松的防刷计数，可能低于实际费用。图片数量、下载大小和输出上限仍保留。

**额度保护开启时，DSH 工作区、独立识图/ASR/TTS 暂停。** 这些路径目前不能完整限定或核算费用，不能宣称已经纳入每日限额。文字聊天与本地业务工具保留。官方 Search/Fetch 自 2026-11-01 起还将单独收费；工作区关闭时不会由该路径继续调用它们。第三方自定义模块不得自行绕过计费直接访问付费接口。

`globalDailyYuan` 默认 0。群和私聊人数增长时，即使单会话限额固定，总预算仍会增长；需要总成本封顶时设定该字段。

## 验证

`npm test` 覆盖基础预算逻辑与回归。真实 Redis 原子行为测试可显式运行：

```sh
AGENT_LINK_TEST_REDIS_CONFIG="$PWD/alemon.config.yaml" node --test --test-force-exit test/budget.test.mjs
```

测试只使用随机前缀隔离的键并清理自身数据，不请求真实付费模型、不删除业务账本。该测试需配置文件中的 `db.redis` 可连接。
