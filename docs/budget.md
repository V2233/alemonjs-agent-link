# 每日额度与付款顺序

在已有 `alemonjs-agent-link` 配置段中合并，保留其他设置和密钥：

```yaml
alemonjs-agent-link:
  budget:
    enabled: true
    personalDailyYuan: 1 # 同平台每人每天一份，跨群及私聊共用
    replyGateDailyYuan: 1 # 每群每天的后台回复判断预算
    replyGateGlobalDailyYuan: 0 # 全部群后台判断的每日总上限；0 不限制
    globalDailyYuan: 0 # 机器人公共 Key 的全部内部文字计数总上限；0 不限制
    maxOutputTokens: 2048
```

代码升级后须重启；之后金额支持配置热更新。额度账本使用现有 `db.redis`。`budget.enabled` 未开启时不启用内部预算保护，个人/群 Key 仍按绑定范围使用。

## 三个账本

| 场景                       | 付款顺序                                                           |
| -------------------------- | ------------------------------------------------------------------ |
| 本人私聊                   | 本人个人 Key → 本人私聊充值 → 本人免费额度                         |
| 群内正常回复               | 群共享 Key 池 → 发起人自己的 Key → 本群充值 → 发起人的个人免费额度 |
| 群后台判断是否回复         | 群 Key → 本群充值 → 本群感知预算                                   |
| 无用户新请求的系统主动发言 | 对应会话绑定 Key → 对应会话充值；不扣成员个人免费额度              |

没有共享的群免费聊天额度，也没有额外一份私聊免费聊天额度。个人免费按平台与用户 ID 记账，群与私聊共享。个人 Key 可用于本人私聊及本人触发的群回复，不会借给其他群友或后台判断；群共享 Key 只用于授权群。私聊充值保留兼容，独立于群充值。

群 Key 启用且有余额时，正常回复直接使用该 Key，不扣内部免费或充值账本；该群同时进入"强度拉满"，不再发起感知判断，因此也不消耗感知预算（见[自带 Key 的群](config.md#自带-key-的群强度拉满)）。确认 Key 欠费时停用该副本并继续下一把共享 Key，共享池耗尽后转到发起人自己的 Key，再回退内部额度；网络错误和余额查询错误会停止请求，不误判为欠费。已执行工作区工具后遇到 Key 欠费，不会自动重放任务，提示充值后启用，或显式停用、移除以使用内部额度。

群内多位管理员可以分别 `/授权钥匙 编号` 分享钥匙，按加入顺序供全群使用。同一人同一把钥匙不能重复分享到同一群。`/授权记录 移除 编号` 只撤销自己的对应授权；群内 `/我的钥匙 停用/启用/移除` 操作整个共享池。扫码登录准备的个人钥匙无需群授权，即可用于本人在群中发起的回复；主动分享才会让其他群友使用。

未充值时，私聊链路是「本人 Key → 本人免费额度」，群聊链路是「共享池 → 本人 Key → 本人免费额度」。已有充值账本继续兼容，不清空余额。共享钥匙的提供者上限与群上限仍按群累计用量保守限制，达到上限会停止请求，不以轮换绕过金额限制。

机器人公共 Key 的一次请求可先预留剩余充值，不足部分再预留个人免费或群感知预算；后备额度也不足时整次拒绝，不先扣一部分。结算先使用该请求预留的充值，退回未用的免费及充值预留。多个群成员的合并消息按最终触发回复的发言人记一次实际请求，不能向所有参与者重复扣款。

额度不足提示会列出本次请求预计需要和当前可用金额。两者都是预扣口径，可能高于实际结算；剩余额度小于预扣时，即使账本还没归零也会拒绝。

## 感知与明确呼唤

@机器人、`/chat` 不经过地址/上下文分类器。关键词可能只是成员在谈论机器人，因此预算充足时保留语义判断与反循环判断。群感知预算耗尽后，普通消息停止分类；关键词呼唤回到本地唤醒路径，继续按个人/群付费额度处理，不会因后台感知没钱而失联。本地机器人来源、停止回复、等用户说完、频率与循环保护继续生效。

感知预算不足，每个平台每群每个北京时间自然日只提醒一次，重启、当天充值和发送失败都不重置提醒次数。次日或充值后可恢复判断。个人免费耗尽不会耗尽群感知预算；分类通过后的正式回复仍需按发起人进行额度检查。

`replyGateGlobalDailyYuan` 只限制后台判断，达到后明确呼唤仍可使用；`globalDailyYuan` 则是机器人公共 Key 的整体内部文字计数上限。两者默认 0，**0 表示不设上限**，只有显式写成大于 0 的金额才会参与拦截；绑定用户/群自己的 Key 不扣这两个账本。

额度不足的提示会写清是哪一本账拦住的：全局上限用满时补一句「今日全局每日上限也已用满。」；个人可用不足时只报本次预计所需与当前可用，不再冒充全局原因。主人私聊 `/额度` 会显示「全局今日已用 X 元 / 上限 Y 元」，没设上限时显示「（未设上限）」，方便核对线上实例到底读到了什么配置。

## 查询和主人管理

`/额度` 不调用模型，显示当前付款来源、个人跨会话免费额度、本群感知预算和当前会话充值。仅主人可以管理和查看其他目标；群管理员仅能按群 Key 授权流程管理群 Key。

| 指令                             | 作用（仅当天有效）                                  |
| -------------------------------- | --------------------------------------------------- |
| `/额度 增加 2` 或 `/额度 充值 2` | 给当前群或私聊充值 2 元                             |
| `/额度 设置 5`（群内）           | 将本群今日感知总预算设为 5 元                       |
| `/额度 设置 5`（私聊）           | 将该用户今日个人免费总额度设为 5 元，跨群和私聊生效 |
| `/额度 增加 群 群ID 2`           | 给同平台指定群充值                                  |
| `/额度 设置 私聊 用户ID 3`       | 设置同平台指定用户的个人免费总额度                  |
| `/额度 查询 群 群ID`             | 查询指定群                                          |
| `/额度 记录`                     | 最近 5 次调整记录                                   |

查询、增加、设置、记录均支持 `群 群ID` 或 `私聊 用户ID`。使用平台真实 ID，不按昵称或 QQ 号码猜测。金额最多两位小数，0–10000 元，充值必须大于 0。设置总额度不会清除已有消费；个人免费设为 0 不影响群充值或其他用户，群感知设为 0 不影响明确呼唤。充值不是接入支付，只是主人内部记账。

## 一致性与升级

Redis Lua 原子预扣、按完整 usage 结算并最多退款一次；并发不能重复花费同一笔充值或个人额度。金额用整数微元，不浮点累计。日期按 Redis 时间的北京时间确定，跨天结算回发起日；账本保留 32 天，调整记录保留最近 1000 条。指令按原消息 ID 防重放。

沿用已有个人消费和充值账本，不补发或抹除额度。旧 `groupDailyYuan` 不再限制聊天；`privateDailyYuan` 仅在未配置 `personalDailyYuan` 时作为个人默认值的兼容项。旧会话免费覆盖值不再参与准入；新版 `/额度 设置` 写入个人或感知账本。升级前没有发起人身份的消费不回填个人账本。

超时、取消、网络错误、5xx、缺少 usage、进程崩溃保留预扣，不能认定没有计费。服务商以 4xx 明确拒绝的请求没有产出，预扣会立即按 0 结算退回；否则每次重试都会再压一笔预扣。`/new`、数据清理和重启不能恢复额度。Redis 故障、身份缺失、价格未知均拒绝付费请求。Redis 需持久化；删除账本或 Redis 数据丢失会使额度重置。

正常聊天额度不足提示仍使用共享滚动上限：每会话 1 小时最多 3 次、6 小时最多 5 次、24 小时最多 7 次。后台判断的每日一次提醒独立于这些窗口。

## 当前计费口径

以 2026-10-26 核验的 [DeepSeek 官方人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)为依据，统一按高峰价计算内部预算，空闲时实际扣款通常更低。金额用整数微元保存，不做浮点累计。

| 模型                                                            | 缓存输入／百万 token | 非缓存输入／百万 token | 输出／百万 token |
| --------------------------------------------------------------- | -------------------: | ---------------------: | ---------------: |
| deepseek-flash、deepseek-v4-flash、deepseek-v4-flash-vision-exp |              0.04 元 |                   2 元 |             8 元 |
| deepseek-v4-pro                                                 |              0.30 元 |                   9 元 |            27 元 |

仅允许官方 `https://api.deepseek.com/chat/completions` 或 `/v1/chat/completions`。未知模型、中转地址不会套用官方价放行。价格变动时需要更新价格表。

**图片聊天已恢复：预扣时排除图片 URL 和 base64，只计算文字及工具描述。** 图片请求的服务商输入 usage 可能混有图像 token，因此结算使用文字投影的 UTF-8 字节数除以 3 向上取整（不超过服务商总输入 token），输出仍按返回的 completion_tokens 统计。图片本身不计入内部额度；这是宽松的防刷计数，可能低于实际费用。图片数量、下载大小和输出上限仍保留。

**额度保护不再强制纯聊天或移除工作区/媒体工具。** DSH 按 `runtimeMode` 与原有群/主人权限运行，不因为额度开关提升文件、终端或群管理权限。工作区每次执行前预扣，再按可见的输入和最终回复文字（UTF-8 字节数除以 3 向上取整）结算；它的内部历史、多轮模型调用和 Search/Fetch 费用不作精确账单核算，超时/失败保留预扣。独立识图/ASR/TTS 恢复按既有配置提供，调用前检查额度，但不额外计算媒体费用。全局上限也是内部文字计数上限，不是服务商真实费用的硬封顶。

内置 `draw_image` 工具可将模型构图渲染成 PNG，随最终回复发送，不需要额外 API Key。支持插画、图标、示意图和海报，不是照片级扩散生图；每轮最多一张、画布最大 1024×1024，不能读取外部图片或执行脚本。模型生成图形参数的文字仍计入正常文本请求，PNG 本身不计费。

可配置的 `generate_image` 工具使用独立第三方服务，其图片费用不计入此文本预算，也不在本地预留；预算开启时只检查会话准入。第三方费用请在服务商侧另设额度，配置见[媒体能力](media.md)。

个人额度按平台提供的用户 ID 识别。如果平台在群与私聊提供不同作用域的 ID，不能只靠账本认出同一个真实人；需平台提供可信的统一身份。

## 固定日期迁移与异常预占核对

部署前停止旧实例接收请求并排空在途调用。构建后，在服务主机先运行迁移工具，再启动新服务（不要把真实配置提交进仓库）：

```sh
node scripts/budget-maintenance.mjs /path/to/alemon.config.yaml migrate YYYY-MM-DD
```

日期是切换时的北京时间日期，不是任意历史日期。迁移日期持久固定；批量扫描该日所有会话账本，原子迁入剩余充值，输出不含密钥的逐钱包核对报告并保存到 Redis。重复执行不重复入账。存在旧预占时报告 pending 并以退出码 2 结束，不宣称迁移完成。禁止旧、新进程同时扣款；首次普通请求也会固定日期，因此应先运行部署迁移命令。已经过期的旧账本无法凭空恢复。

```sh
node scripts/budget-maintenance.mjs /path/to/alemon.config.yaml pending
node scripts/budget-maintenance.mjs /path/to/alemon.config.yaml settle YYYY-MM-DD:request:UUID 实际金额 操作人
```

`pending` 只读列出预占金额、持续时间、原因与是否支持恢复。`settle` 只能在服务排空、向服务商核实实际费用后由运维执行：仅接受一小时前、有完整账本信息的记录，实际金额不得超过原预占；原子结算一次，保留操作人和金额审计。不要把超时等同于免费，不自动退款。旧版缺少账本定位信息的记录标为不可恢复，须结合旧账单单独核查，不能靠猜测解冻。

核对保护：Redis 配置了 keyPrefix 时仍按原账本结算；账本缺失、类型错误或预占金额不足时，整个结算拒绝执行，保留原预占供核查，不创建负数账本。迁移只接受真实且不晚于当前北京时间的日期，校验失败不会锁定迁移日。

未结算请求及仍有预占的账本不自动过期；最后一笔结算完成后，日账本保留 32 天，结算审计保留 90 天，充值钱包持续保留。升级前已有的预占应在旧 TTL 到期前执行以下保留操作（原子补齐旧凭证的待结算计数并取消过期时间，不更改金额；重复执行不会重复计数）：

```sh
node scripts/budget-maintenance.mjs /path/to/alemon.config.yaml retain
```

报告中的 `legacyWithoutLedgers` 表示旧凭证缺少账本定位信息：保留凭证，但仍需人工核查，不能自动结算。账本缺失或计数损坏时，该笔迁移会拒绝写入；应修复后重试。已经过期的数据无法由此恢复。

未设置群上限时，统计不改写原请求的 `max_tokens`，但仍要求可用的 Redis 和模型定价，校验失败会在调用服务商前拒绝请求；设置上限后才应用预算输出限制。授权记录展示提供者上限、群上限和最终生效值。

## 私聊广告奖励

后台「私聊广告」可维护广告标题、正文、HTTPS链接、奖励金额（0.01–10元）和上架状态，并单独控制总开关。总开关默认关闭：私聊额度不展示广告入口，`/广告列表`、`/广告详情` 静默；群内这些指令也不回复。预算账本未开启时不能领取奖励。

开启后，私聊 `/额度` 增加「查阅广告获得额度」，`/广告列表` 每页5条，`/广告详情 广告ID` 展示正文。详情确认发送成功后才尝试发奖，不能以此证明用户阅读外部链接。每个平台用户每条广告ID终身仅领取一次，奖励计入本人私聊充值余额、跨天保留；余额不能绕过全局预算限制，也不会自动替代已绑定的个人Key。

奖励和领取凭证通过同一Redis Lua操作提交，重复请求和重启不会重复发放；发奖结果未知时可重新查阅同一广告重试。依赖Redis持久化，删除账本或领取凭证会破坏防重保障。修改广告ID视为新广告，编辑内容、奖励或下架再上架不重置同ID的领取资格。配置保存沿用后台版本检查和备份。
