# Redis 每日额度保护

在已有 `alemonjs-agent-link` 配置内合并以下内容，保留 API Key 和其他设置。额度统计只用现有 `db.redis`，不需要 SQL 服务；不会改变已有聊天归档和记忆存储。

```yaml
alemonjs-agent-link:
  budget:
    enabled: true
    groupDailyYuan: 2
    privateDailyYuan: 1 # 私聊会话每日免费额度
    replyGateDailyYuan: 1 # 每群每天独立的主动搭话识别免费额度
    personalDailyYuan: 1 # 同一平台用户跨群及私聊共用
    globalDailyYuan: 0 # 0 表示不设全局上限；例如 20 表示全局每天最多 20 元内部预算
    maxOutputTokens: 2048
```

首次安装代码需要重启服务。之后金额配置支持现有配置热更新。未配置 `budget.enabled: true` 的安装保持原有行为。该仓库的本机运行配置已单独开启；运行配置被 Git 忽略，不会随源码部署到其他机器，部署时也须合并以上配置。

## 规则和统计

- 同平台同群共享每天 2 元免费额度；每个私聊会话每天 1 元免费额度。另有同平台每人每天 1 元个人额度，跨所有群和私聊共享，包括主人。群内免费消费同时计入群与个人，私聊免费消费同时计入私聊会话与个人（不扣某个实际群）。群充值仅用于对应群，私聊充值仅用于对应用户的私聊，二者互不挪用；充值优先扣除，不消耗个人免费额度；一次请求可以拆成充值与免费两部分。以 Redis 时间确定北京时间日期，跨天使用新的账本，不依赖定时清零。跨天完成的调用结算回发起日。
- `/额度` 无需调用模型，可查询当前会话剩余金额、请求次数、计入的输入/输出/缓存 token、预留及待核实金额。主人私聊还可看全局已计入金额。所有统计键保留 32 天。
- 直接聊天、业务工具的每一轮模型调用、情绪判断、有明确用户的手动记忆整理、主动搭话都走同一额度账本。智能回复判断单独计入每群每日 1 元的识别免费额度，不扣聊天免费额度或个人额度；有群充值余额时优先共享该群充值余额，也受全局预算约束。会话账本按平台与会话隔离，个人账本按平台与用户 ID 共享，充值只属于被充值的群或私聊会话。用户身份取平台事件的 UserId，不按昵称或群号生成；如果平台提供的是群内局部用户 ID，跨群识别需平台提供统一身份，不能仅靠账本推断。
- 开启预算后，无发起用户的自动记忆整理暂停付费处理；手动整理使用发起人的账本。升级前的群消费保留，旧数据没有付款用户身份，不回填个人账本；旧的总额度调整继续作为当日免费额度覆盖值，新增加额才记入充值账本。
- Redis Lua 原子检查会话免费额度、会话充值余额、个人和全局额度，再按资金来源预扣、统计请求数；完整响应中的 usage 用来结算并退还差额，每个请求最多结算一次。结算沿用该请求预扣的资金来源，实际用量先抵扣其充值预留，余下计入免费与个人账本；全局仅记一次消费，不把群和个人的计数相加。流式开启 `stream_options.include_usage` 并处理独立 usage 尾帧。
- 直接模型调用的输出 token 设置上限；文本输入以 UTF-8 字节数加 8192 的格式开销保守预留。剩余额度不足以预留时会提前拒绝，请缩短上下文或等次日，不保证恰好花到限额。工具循环每一轮都需要重新预扣。
- 超时、取消、HTTP/网络错误、缺少有效 usage、进程崩溃，均保留本次预扣，计入“预留／待核实”；不会假定失败就是免费。手动清空会话、`/new`、数据清理、重启均不能恢复额度。系统不会自动退还无法核实的历史预扣。
- Redis 不可用、缺少会话身份或模型/服务商价格未知时，拒绝付费请求，不降级到内存记账。Redis 应开启 AOF，避免用带淘汰策略的缓存实例；删除账本、Redis 数据丢失仍会使额度重置。
- 原子预扣用于预算保护，并非提供商账单审计；若提供商返回的用量超过预留，也如实计入，不截断隐藏超额。账本不包含启用之前的历史消费。

## 限额后停止判断与提示频率

群回复必要性分类器（主动搭话识别，包括其处理的呼唤识别）每群每天默认免费 1 元，由 `replyGateDailyYuan` 配置。它只按平台与群记账，不使用发言人的个人账本，也不消耗群聊天免费额度。群有充值余额时，识别与正式聊天共享该余额，优先原子预扣充值；余下部分使用独立的识别免费额度。预扣、按 usage 结算、异常保留预扣与聊天规则一致。`/额度` 单独显示识别免费用量和消耗的群充值。

识别额度或全局额度不足后，在请求分类器前停止；充值或次日恢复额度后恢复。群聊天或个人免费额度用尽不会关闭这个独立的识别账本，但识别通过后的正式回复仍按原聊天规则检查额度。已有短时并发和防循环保护保留。

主动搭话识别额度不足时，每个平台每群每个北京时间自然日只提示一次，普通群聊和呼唤入口共用这一次。提示明确说明仅主动识别暂停，不代表群聊天额度耗尽。Redis 原子记录，重启和当天充值不重置次数；发送失败也不重复尝试，次日重新计数。

对正式聊天的直接呼唤、显式聊天和私聊请求，额度不足提示按**平台与会话共享**的滚动窗口限制：最近 1 小时最多 3 次、最近 6 小时最多 5 次、最近 24 小时最多 7 次；任一达到上限就静默。普通群聊和主动搭话不会重复刷正式聊天额度提示。三个窗口使用同一条 Redis Lua 原子判断，并对重复消息去重，正式聊天入口共用计数，与主动识别提示完全独立，重启不清零，零点也不清空仍在滚动窗口内的提示。发送前占用提示次数，发送失败不会自动返还，以免反复重试刷屏。额度查询与主人管理不受该提示限制。

## 主人手动管理

所有金额单位为元，最多两位小数，单项额度范围为 0–10000 元。除 `/额度` 查询当前会话外，以下管理指令仅机器人主人可使用，群管理员不会自动获得权限。

| 指令                       | 作用                                    |
| -------------------------- | --------------------------------------- |
| `/额度 帮助`               | 显示指令说明                            |
| `/额度 增加 2`             | 给当前群或私聊今天充值 2 元（不扣个人） |
| `/额度 设置 5`             | 将当前会话今日**免费总额度**设为 5 元   |
| `/额度 查询 群 群ID`       | 查询指定群今天的额度                    |
| `/额度 增加 群 群ID 2`     | 给指定群今天充值 2 元（不扣个人）       |
| `/额度 设置 私聊 用户ID 3` | 将指定私聊会话今天的免费总额度设为 3 元 |
| `/额度 记录`               | 查看当前会话今天最近 5 次手动调整       |
| `/额度 记录 群 群ID`       | 查看指定群今天最近 5 次手动调整         |

主人可用 `/额度 充值 私聊 用户ID 2` 为私聊单独记入 2 元，不增加任何群的充值余额；仍为主人手动记账，普通用户不能自行执行加额。

查询、增加（充值）、设置、记录均支持 `群 群ID` 或 `私聊 用户ID`，只管理发送指令的当前平台。QQ 官方机器人须使用该平台实际的群/用户 ID；不能假定它等于 QQ 号码。无目标参数时使用当前会话。

调整只影响今天，零点恢复配置中的每日默认额度；**不清除消费和预留，也不会突破已配置的全局预算**。例如免费已用 1 元，设置为 5 元后免费剩余 4 元；设置为 0 元只关闭免费部分，已有当前会话充值余额仍能使用。增加只调整独立的当前会话充值账本，不改个人限额；充值同样仅当天有效。已发出的请求仍按原预留来源结算。管理指令不调用模型；`充值` 是 `增加` 的同义指令。

使用 Lua 原子更新、按原始消息编号防重复加额；缺少可靠消息编号时拒绝写入。调整记录包含主人 ID、时间、操作、金额和调整前后总额，最多保留当天最近 1000 条、保留 32 天，查询指令展示最近 5 条。超时后可查询 `/额度` 和 `/额度 记录` 核实，不要盲目重新发送加额指令。

这些指令只管理内部预算，**没有支付接口、自动充值或向服务商充值的功能**。如需增加服务商余额，由主人自行操作服务商后台。

## 个人 API Key

本人私聊可通过 `/个人密钥` 绑定 DeepSeek 官方 Key。启用时优先使用个人 Key，不扣下列内部额度；确认余额不足后自动停用并恢复额度模式，需手动启用才会再次尝试。详见 [个人 Key 管理](personal-key.md)。

## 当前计费口径

以 2026-10-26 核验的 [DeepSeek 官方人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)为依据，统一按高峰价计算内部预算，空闲时实际扣款通常更低。金额用整数微元保存，不做浮点累计。

| 模型                                                            | 缓存输入／百万 token | 非缓存输入／百万 token | 输出／百万 token |
| --------------------------------------------------------------- | -------------------: | ---------------------: | ---------------: |
| deepseek-flash、deepseek-v4-flash、deepseek-v4-flash-vision-exp |              0.04 元 |                   2 元 |             8 元 |
| deepseek-v4-pro                                                 |              0.30 元 |                   9 元 |            27 元 |

仅允许官方 `https://api.deepseek.com/chat/completions` 或 `/v1/chat/completions`。未知模型、中转地址不会套用官方价放行。价格变动时需要更新价格表。

**图片聊天已恢复：预扣时排除图片 URL 和 base64，只计算文字及工具描述。** 图片请求的服务商输入 usage 可能混有图像 token，因此结算使用文字投影的 UTF-8 字节数除以 3 向上取整（不超过服务商总输入 token），输出仍按返回的 completion_tokens 统计。图片本身不计入内部额度；这是宽松的防刷计数，可能低于实际费用。图片数量、下载大小和输出上限仍保留。

**额度保护不再强制纯聊天或移除工作区/媒体工具。** DSH 按 `runtimeMode` 与原有群/主人权限运行，不因为额度开关提升文件、终端或群管理权限。工作区每次执行前预扣，再按可见的输入和最终回复文字（UTF-8 字节数除以 3 向上取整）结算；它的内部历史、多轮模型调用和 Search/Fetch 费用不作精确账单核算，超时/失败保留预扣。独立识图/ASR/TTS 恢复按既有配置提供，调用前检查额度，但不额外计算媒体费用。全局上限也是内部文字计数上限，不是服务商真实费用的硬封顶。

内置 `draw_image` 工具可将模型构图渲染成 PNG，随最终回复发送，不需要额外 API Key。支持插画、图标、示意图和海报，不是照片级扩散生图；每轮最多一张、画布最大 1024×1024，不能读取外部图片或执行脚本。模型生成图形参数的文字仍计入正常文本请求，PNG 本身不计费。

可配置的 `generate_image` 工具使用独立第三方服务，其图片费用不计入此文本预算，也不在本地预留；预算开启时只检查会话准入。第三方费用请在服务商侧另设额度，配置见[媒体能力](media.md)。

`globalDailyYuan` 默认 0。个人额度限制同一个用户通过建群领取多份免费额度；不同真实用户的数量增长时，总预算仍会增长；需要内部计数总量封顶时设定该字段。

## 验证

`npm test` 覆盖基础预算逻辑与回归。真实 Redis 原子行为测试可显式运行：

```sh
AGENT_LINK_TEST_REDIS_CONFIG="$PWD/alemon.config.yaml" node --test --test-force-exit test/budget.test.mjs
```

测试只使用随机前缀隔离的键并清理自身数据，不请求真实付费模型、不删除业务账本。该测试需配置文件中的 `db.redis` 可连接。
