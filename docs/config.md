# 配置指南

仓库独立启动器默认连接 QQ Bot；需要 OneBot 账号协议时可设置 `transport: onebot`，连接参数、戳一戳和白名单群管理见 [OneBot 接入](onebot.md)。修改连接类型后需重启。

所有运行配置位于本机 `alemon.config.yaml`。该文件包含 QQ 和 Redis 凭证，必须保持在版本控制之外。

## 默认开放与默认受控

默认开放：私聊（`privateChatAccess: all`）、群聊、网页查询、个人/群会话工作目录文件、B 站只读与主动浏览、长期记忆整理、心情、主动搭话自动订阅、自动语音与表情、表情自动收集、QQ 空间读取与预览。

默认受控：终端始终禁用；文件只能访问当前会话分配的目录，不能跨工作目录；B 站评论和空间发帖/互动默认开放，但仍要求主人本轮明确要求，并按每日次数与冷却执行；改 `dryRun: true` 可只预览。QQ 收藏同步默认关闭。主人验证、群管理和外部写操作仍按身份与平台回执校验。

## 最小配置

插件安装后，在 AlemonJS 宿主使用的配置文件中合并以下配置，已有同名段直接修改，避免重复 YAML 键：

```yaml
alemonjs-agent-link:
  apiKey: '<MODEL_API_KEY>'
```

仓库独立运行 `npm start` 时，QQ 凭证留空会显示终端二维码，使用手机 QQ 完成授权后由适配器保存凭证并继续启动。授权会更新机器人密钥，其他实例需同步更新。已有凭证可直接配置，跳过扫码：

```yaml
qq-bot:
  app_id: '<QQ_APP_ID>'
  secret: '<QQ_APP_SECRET>'
```

默认使用 DeepSeek。接入其他兼容模型服务时，在已有 `alemonjs-agent-link` 段中增加 `baseUrl` 和 `model`，不要重复创建同名 YAML 段：

```yaml
alemonjs-agent-link:
  apiKey: '<MODEL_API_KEY>'
  baseUrl: 'https://api.example.com/v1'
  model: '<MODEL_NAME>'
```

## 仓库独立启动与诊断

以下 npm 命令均在本仓库根目录执行；插件模式沿用宿主的启动命令、配置文件与平台登录方式，不会自动执行这些脚本。首次执行 `npm start` 时，独立启动器会生成缺失的配置并显示路径，已有文件保持原样。

`npm run doctor`离线检查 Node 22.13+、内置 SQLite、配置格式、必要字段和数据目录权限。检查与运行时共用 AgentLink 配置规则。`npm run doctor -- --json` 提供不含密钥的结构化结果；不连接模型、QQ 或 Redis，不创建数据目录，不安装依赖。缺失字段或 YAML 重复键、缩进错误会在启动前提示；只检查格式不表示网络与凭证有效。

可用 `npm run init` 单独生成最小配置，`--config 路径` 或 `CFG_PATH` 指定配置文件。启动器通过同一路径加载框架配置。独立启动器默认使用固定用户目录：Windows 为 AppData/AgentLink，macOS 为 Library/Application Support/AgentLink，Linux 为 XDG_CONFIG_HOME/agent-link（未设置时 ~/.config/agent-link）；可用 AGENT_LINK_HOME 指定。默认数据放在该目录的 data 子目录。

检测到工作目录已有配置或 .data/agent-link 时沿用旧目录，并记住成功启动的配置路径，之后换目录也会继续使用；不自动移动或覆盖已有数据。`npm start -- --portable` 强制当前目录模式。`--config` 的相对数据路径以配置所在目录为基准；AGENT_LINK_DATA_DIR 可显式指定默认数据目录。

`alemon.config.yaml` 已被 Git 忽略。应仅允许运行账户读取，并禁止复制到日志、镜像或公开位置。`/agentbind`、`/agentmodel` 与 `/agentunbind` 不会修改该文件。

## AgentLink 参数

### 配置动态生效

框架监听 `alemon.config.yaml` 并更新内存配置。修改 `apiKey`、`baseUrl`、`model`、媒体或模块配置后保存即可，后续请求重新读取，不需要重启机器人。未配置凭证时补填，或移除已有凭证，也按新配置处理。

DSH 沙箱子进程通过环境变量接收模型配置；插件检测配置/凭据变化后会停止旧实例并在后续使用时准备新实例，不重启 QQ 连接和整个机器人。当前机制不保证切换过程中正在执行的沙箱请求不中断，建议等待当前回复完成再修改。状态查询也可触发新实例准备。配置修改与安装新版本代码是两回事：新代码仍需通过运行器热重载或重新启动加载。

定时清理每次运行重新读取当前配置。修改数据目录只会切换到新路径，不会自动搬迁旧数据。环境依赖修复但配置未变化时，已经降级的实例仍需重新加载运行实例才能重新探测。

`runtimeMode` 默认为 `auto`，支持三个值：

- `auto`：普通聊天先就绪，后台准备沙箱；准备失败后自动退避重试（30 秒至 5 分钟）。实际请求仍需配置模型凭证。已开始的普通聊天会话保持原后端，`/new` 后可使用已就绪的沙箱。
- `sandbox`：严格要求沙箱，失败时拒绝服务。
- `chat-only`：直接使用纯聊天，不安装 Python 或启动本地 Worker。

纯聊天请求使用 `baseUrl/chat/completions`，需要兼容 Chat Completions 的 HTTPS 服务；不跟随重定向。当前整段接收回答后发送，私聊通过所选状态库保存有界的多轮文本历史，群聊保留调用方提供的近期群聊上下文、超时取消、输入输出关键词过滤。未填写模型凭证时不安装 Python 或启动 Bridge，填写并保存后，后续请求自动生效。环境恢复后会在后续自动重试中重新准备沙箱，无需为了网络暂时失败反复重启。纯聊天模式无法清除此前的沙箱磁盘数据；清理操作会报告失败，而不会假报成功。

未列出的参数应保留默认值。所有时长均为毫秒，除非名称以 `Seconds` 或 `Days` 结尾。

每个字段的类型、默认值、取值范围和生效方式见[配置字段参考](config-reference.md)。

带注释的完整示例见仓库根目录 [alemon.config.example.yaml](../alemon.config.example.yaml)：复制为 `alemon.config.yaml`，把 `<...>` 占位符替换成真实值即可。

## 多 Key / 端点轮转

最简单的写法：只列 Key，所有 Key 默认使用主配置的 `baseUrl` 和 `model`。

```yaml
alemonjs-agent-link:
  apiKey: '<MODEL_API_KEY>'
  baseUrl: 'https://api.deepseek.com'
  model: 'deepseek-v4-flash'
  modelPool:
    keys:
      - '<MODEL_API_KEY_A>'
      - '<MODEL_API_KEY_B>'
```

需要某个 Key 用不同模型或地址时，把字符串换成对象；`key` 等同 `apiKey`，`api` 等同 `baseUrl`：

```yaml
modelPool:
  keys:
    - key: '<MODEL_API_KEY_A>'
      model: 'deepseek-v4-flash'
    - key: '<MODEL_API_KEY_B>'
      model: 'deepseek-v4-pro'
      api: 'https://api.deepseek.com'
```

需要保留官方贵价 Key 兜底时，给该端点加 `fallback: true`：平时聊天只选主端点，只有主端点全部不可用、超并发或冷却时才用它；沙箱仍可直接使用该端点。

调度统一采用最少活跃任务：同组可用端点的任务数越少越优先，相同时按数组顺序。旧 `priority`、`weight`、`strategy` 和 `stickySeconds` 不再控制调度。

配置了 `modelPool` 后，外层 `apiKey` 只作为旧配置兼容，不再参与普通请求或沙箱兜底；沙箱必须在池里有一个 `provider: deepseek-official` 的端点。

`workspace: true` 可标记一个专用工作区端点；`agent_workspace` 会优先使用它，而不是聊天轮转选中的端点。它必须兼容 DSH 的 DeepSeek Messages 协议。

需要硬限流时给端点加 `account`、`rpm`、`tpm`：同一 `account` 共享 60 秒滑动窗口内的请求数和 token 数，达到 RPM/TPM 后不再选择该端点，不必等厂商返回 429。请求前会按估算 token 预留，响应后按真实 usage 结算；未完成的预留会在失败/取消时释放。`balanceAlertYuan` 控制 `/额度轮转` 的低余额提示阈值。`retryBudgetMs` 控制总重试时间，`retryJitterMs` 控制切换抖动。`queueMaxWaitMs` 让主端点并发满时短暂等待，超时才用 fallback，避免为了 200ms 的空档直接花贵价额度。

一次聊天任务绑定一个端点，工具执行与后续模型轮次保持一致，结束时释放并发槽。首次模型调用尚未输出或得到有效结果时，允许对网络失败、超时、上游暂不可用、限流及额度不足进行有限的静默切换；得到结果后固定成功端点，避免工具重复执行。取消、参数错误和本地预算失败不重试。新任务重新参与选择。管理页保存时清理旧策略与权重字段。

启动与周期探测仍按现有探测配置执行；这与管理页面轮询无关，页面仅手动刷新。`/models` 成功不能证明计费恢复。429 优先读取 `Retry-After` / `x-ratelimit-reset-requests`。具体调度、沙箱统计边界和任务生命周期见[额度轮转管理](quota-rotation.md)。

- Node 聊天、工具轮次和主动识别统一使用 **OpenAI-compatible `/chat/completions`**；OpenAI、OpenRouter、SiliconFlow、Gemini 的 OpenAI 兼容入口等都可以。
- 沙箱工作区任务仍走 DSH 的 `deepseek-official` 协议；只有 `provider: deepseek-official` 的端点会进入沙箱 Bridge。跨厂商端点可以参与普通聊天，但不能替代沙箱任务的模型。
- 带图轮次需要 `capabilities` 里加 `vision`；工具轮次默认已包含 `tools`。
- 开启额度时，非 `https://api.deepseek.com` 的端点必须提供 `pricing`（人民币/百万 tokens），否则额度保护会拒绝；DeepSeek 官方端点仍用内置价格。
- 个人/群绑定 Key 仍优先于池；池全部不可用时请求失败，不绕过健康或并发限制。

### 跨厂商示例

```yaml
modelPool:
  keys:
    - key: '<OPENROUTER_KEY>'
      api: 'https://openrouter.ai/api/v1'
      model: 'deepseek/deepseek-chat'
      provider: 'openrouter'
      pricing: { input: 2, output: 8, cached: 0.04 }
      capabilities: [chat, tools, replyGate]

    - key: '<OPENAI_KEY>'
      api: 'https://api.openai.com/v1'
      model: 'gpt-4o-mini'
      provider: 'openai'
      pricing: { input: 2, output: 8 }
      capabilities: [chat, tools, vision, replyGate]
```

`provider` 只是端点的标签/沙箱筛选依据；Node 侧按 OpenAI 标准发请求，不按厂商名做特殊协议转换。原生 Anthropic Messages、Gemini GenerateContent 等非 OpenAI 协议需要先用兼容网关转换。

每日请求数和 token 数会写入 `dshHomeRoot` 同级的 `model-pool-metrics.json`，重启后保留当天账本；跨天自动归零。沙箱 Bridge 的用量单独写入 `model-pool-bridge-metrics.json`，`/额度轮转` 会显示沙箱和个人/群 Key 的今日请求与 token。

主人私聊发送 `/额度轮转` 查看分页状态、余额和补货提示，`/额度轮转 2` 翻页；摘要会列出可用、冷却、停用、异常、在途和已知余额合计。DeepSeek 官方端点自动查 `/user/balance`；其他服务可配置 `balanceUrl` 模板，例如代金券查询页，`{key}` 会替换为端点 Key。

余额查询会把 Key 发给 `balanceUrl` 指向的服务；只配置你信任的地址。多厂商建议按 provider 映射，避免把 A 厂商的 Key 发到 B 厂商的余额接口：

```yaml
modelPool:
  balanceUrl:
    senseaudio: 'https://xiaofengaicp.xyz/voucher/api/query?key={key}'
    openai: 'https://你的余额接口?key={key}'
```

也可以写单个字符串作为所有非官方端点的默认值，或在某个 Key 下写 `balanceUrl` 单独覆盖。New API 网关（如 FreeToken）额外支持 `balanceStyle: 'newapi'`，显示已用金额而不是余额。

完整字段见[配置字段参考](config-reference.md#411-模型端点池modelpool)。

## 状态库与静默启动

没有配置 `db.redis` 时，默认 `stateBackend: local`，数据保存在 `dshHomeRoot` 同级的 `state.json`。本地模式串行执行状态事务、临时文件写入后原子替换，保留 TTL、去重所有权、会话代际与记忆限制；同一个文件只允许一个 Node 进程持有。异常退出后，下次启动检查锁的 PID；仍在运行或无法确认时拒绝抢锁。损坏的数据文件不会被静默覆盖。

已有 `db.redis` 配置时默认继续使用 Redis；可显式设置 `stateBackend: local` 或 `redis`。两者不自动迁移数据，也不会在 Redis 断线后切换为本地空库。Redis 不可用时拒绝新请求。

```yaml
alemonjs-agent-link:
  stateBackend: local
  runtimeMode: auto
  pythonPackageSources:
    - https://pypi.org/simple
    - https://pypi.tuna.tsinghua.edu.cn/simple
```

Python 安装只管理插件自己的虚拟环境，不修改自定义 `pythonExecutable`。先验证已有 SDK，无需安装时不访问下载源；否则尝试本机 `python3`、`python` 创建虚拟环境，按来源顺序安装固定版本的预编译依赖（不调用本地编译工具链），单源失败或超时自动换源，下次优先使用上次成功的来源；近期失败的来源在五分钟内降到后面。依赖准备另有 `preparationTimeoutMs` 总预算（默认 120000，范围 1000–600000 毫秒），每个子进程也受 `startupTimeoutMs` 限制，停止服务会取消正在执行的安装；pip 单次网络超时 10 秒、重试 1 次，保留 pip 自身缓存。未找到 Python 时直接使用 Node 纯聊天，不自动安装系统 Python。

来源必须为不含账号密码的 HTTPS 地址；每次只使用一个 index，不混用 extra-index。遵循系统 HTTP(S) 代理环境变量，不修改全局 pip/npm 配置。下载由 pip 验证 HTTPS 并处理安装包；当前未提供跨镜像独立 SHA-256 清单、Python 二进制托管或断点续传承诺。

运行状态与不含凭证的诊断写入 `dshHomeRoot` 同级的 `startup-status.json`，主人可用 `/agentstatus` 查看当前模式和原因。使用启动器时，常规框架日志和失败信息写入同级 startup.log，按大小轮转并隐藏配置中的已知密钥、Bearer 和 URL 凭证；终端只显示扫码、就绪和可操作的失败提示。主人验证码也保存在该日志。直接由其他 AlemonJS 宿主加载插件时沿用宿主日志。

插件的源切换只作用于 Python 依赖。首次安装插件时若 npm 默认源不可达，可为本次命令指定 `--registry=https://registry.npmmirror.com`，不要修改全局 registry。发布包包含构建产物，不需要用户运行仓库构建脚本。

本地模式适用于单进程、小规模机器人；读取不再写回快照，写事务仍原子保存。启动器在创建 QQ 适配器前取得实例锁，重复启动不会重复登录；异常退出的心跳锁约数秒后自动回收。旧版遗留的恢复锁也会检查持有进程后回收。

本地开发可启动仓库提供的 Redis：

```bash
docker compose up -d redis
docker compose ps
```

生产 Redis 应启用认证、持久化和备份。不要将 Redis 暴露到公网。

## 大肥鱼与私聊

默认启用内置大肥鱼人设（全局生效），主人可以直接私聊文字，也可继续使用 `/chat`。
显式设置的 `defaultSystemPrompt` 优先于人设预设；`persona: assistant` 恢复普通助手。

内置肥鱼是一只有点嘴硬、有胜负欲、会认错也能认真办事的电子小鲸鱼：闲聊通常一两句，认真问题完整解释，不靠撒娇或客服腔证明个性。群聊克制插话、分清引用与发言人；私聊承接上下文，依据实际记忆相处。识图、语音、查资料和执行任务均以当前工具与结果为准，不虚构后台经历或未开放的能力。人设是表达指导，不替代权限、回复判断或防循环机制。
在已有配置段中合并以下字段，保留模型凭证，保存后新请求自动生效：

```yaml
alemonjs-agent-link:
  persona: dafeiyu
  privateAutoReply: true
  privateChatAccess: all # 默认向普通用户开放私聊；普通用户可联网查询和操作个人文件目录，终端始终禁止
  privateHistoryMaxTurns: 10 # 0 关闭纯聊天私聊记忆，最大 100；压缩后保留该轮数，两次压缩之间最多增长到两倍
  privateHistoryTtlSeconds: 86400 # 每轮历史最多保留 24 小时，范围 1–2592000
  privateHistoryMaxChars: 12000 # 历史总字符预算，范围 1–100000
```

私聊按平台与用户 ID 隔离；缺少身份时拒绝创建会话。`/new` 清空自己的私聊会话与记忆，`/cancel` 取消自己的请求。
`privateAutoReply: false` 只关闭普通文字触发，仍可使用 `/chat`；以 `/` 开头的文字始终交给命令路由。
纯聊天记忆在全部回复获得平台成功回执后保存问答（平台接收不代表用户已读），超预算的单轮不保存，超时、取消或失败的模型回合不保存。
历史在排队请求实际执行时读取，重置后的旧回合不能写回。沙箱模式沿用 DSH 会话，不重复注入这份纯聊天历史；Worker 重启后不保证恢复上下文。
角色对话默认使用文字；表情包与语音可按媒体配置启用。用户私聊首次对话会自动订阅主动搭话（可用 `autoSubscribe: false` 或 `/主动搭话 关闭` 停止），实际发送能力以平台回执为准。

同一会话的串行队列覆盖模型生成和回复发送；`maxQueuedPerGroup: 0` 允许空闲时处理一条请求，但不接收等待队列。取消会丢弃尚未发送的缓存，已经交给平台的发送请求无法撤回。

## 群聊称呼与长期记忆

`groupWakeNames` 默认包含 26 个称呼和求助词：帮我、帮忙、帮一下、帮个忙、求助、求解、请教、肥鱼、大肥鱼、小肥鱼、肥鱼儿、肥鱼酱、鱼宝、鱼鱼、小鲸鱼、鲸鱼、deepseek、deep seek、deep-seek、深度求索、深求、dsh、ds harness、deepseek harness、agentlink、agent link。可自定义最多 64 个关键词，每个最多 20 字符；`[]` 关闭关键词唤醒。匹配整条消息，英文不区分大小写，不匹配无关英文标识符内部的片段。命中后仍判断是否需要回应，不直接强制插话。显式配置的词表优先，不自动合并默认词；因此旧配置需自行补充或移除该字段以采用新默认。
私聊和 `/chat` 不经过地址/上下文判断；明确 @ 机器人也跳过该判断，沿用同一个 Agent 回复链路。引用机器人、命中关键词仍只是候选信号，需要前置 AI 判断，不能因提及模型名字就强制插话。求助正文保持完整，其他斜杠指令仍由对应命令处理。权限、限流和群聊批处理继续生效。
群聊参考和当前请求会附带发言人 ID、昵称与主人标志；昵称是引用资料，不授予工具权限。机器人消息不触发对话。

私聊长期记忆不需要新模型或向量服务：

- `/记住 我喜欢简短回复`：明确保存一条资料，最多 20 条、每条 200 字；完全相同的内容去重。
- `/记忆`：查看自己的资料及编号。
- `/忘记 编号`：删除指定资料；`/忘记全部`：删除自己的全部资料。
- `/new`：仅重置对话和短期记忆，保留明确保存的资料。

资料按平台、用户隔离，群聊不会读取私聊资料。默认启用的 `memory` 模块也支持用户明确说“记住……”后由模型调用保存工具；未明确要求时拒绝保存，不能把聊天推测自动写入。
手动记忆修改在会话重置边界内串行执行，修改时会清空当前对话，避免删除后的资料继续留在模型上下文中。模型保存工具仅能新增或查询，不能删除；删除仍使用 `/忘记` 或 `/忘记全部`。
每轮执行时读取资料；纯聊天与沙箱都能参考，纯聊天短期历史不会重复保存资料块。
状态库中的资料无访问 30 天自动过期，读取会延长有效期；本地模式重启后保留；Redis 模式取决于 Redis 的持久化配置。
以上是明确保存的资料。另有当前会话的自动整理、关键词检索、人物资料、冲突版本和恢复能力，见[长期记忆](memory.md)。自动资料可能有理解误差，需核对来源；默认没有向量语义检索，可选配置 `memory.embedding` 做语义重排。模块设置与本地扩展见[模块与业务工具](modules.md)。

## 群聊参与策略

@、开头称呼、引用机器人的消息、`/chat`、`/语音` 共享群聊分段。默认短暂停顿 1.2 秒后回复；连续发言的聚合等待最多 4 秒。上一段正在回复时，新消息进入下一段，等待当前回复结束；该等待上限不包含模型执行和排队时间。

```yaml
alemonjs-agent-link:
  groupChat:
    activity: active # quiet / balanced / active；默认最积极
    enabled: true
    batchWindowMs: 1200
    maxBatchWaitMs: 4000
    maxBatchMessages: 24
    maxBatchChars: 12000
    interjectChance: 0.45
    cooldownSeconds: 30
    maxPerHour: 16
    quietHours: [1, 8]
    timezone: Asia/Shanghai
    minRecentMessages: 2
    activeWindowSeconds: 300
    minRelevance: 0.15
    interests: [吃饭, 美食, 游戏, 动漫, 猫, 鲸鱼, 天气, 奶茶]
    engagedSeconds: 600
    burstMax: 10
    burstWindowSeconds: 120
    overrides:
      '<实际频道ID>':
        enabled: false
```

`activity` 有三档：`quiet`（克制）、`balanced`（旧默认）、`active`（默认，最积极）。预设只提供一组起点，显式写出的数字字段优先；想恢复克制可设 `activity: quiet`，但不建议直接关掉判断。

`enabled: false` 或 `interjectChance: 0` 关闭自主插话和话题续接，关键词呼唤仍进入地址/上下文判断，明确 @ 和命令不经过该判断。`batchWindowMs: 0` 可以关闭主动等待；群内串行与容量上限仍生效。`quietHours` 使用指定时区，支持跨午夜；两个值相同时关闭静默时段。

普通群消息由在线直连 AI 判断“是不是在喊它、是不是接着它的上下文说”，替代随机概率、话题关键词门槛与参与期自动续接；明确 @、引用机器人和句首直接称呼属于高置信地址，直接进入回复链路，不再调用分类模型；只有句中出现名字、第三人称提及、普通讨论才走判断。普通消息还会先做本地粗筛：没有直接喊它、没有正在参与的话题、相关度低于门槛，而且不是问句/请求/链接时，直接沉默，不调用分类模型；问句、请求和命中话题仍进入判断。`帮我`、`求助` 等泛化求助词不算高置信地址，避免把普通群聊里的求助都当成叫它。`minRecentMessages`、`interests`、`minRelevance` 不再用于生产路径的放行，`interjectChance` 仅保留 0 为关闭自主参与的兼容开关。静默时段、插话冷却、每小时上限、突发上限仍生效。机器人刚刚在话题里说过话时，`engagedSeconds`（默认 600 秒）内的相关追问走 `engaged` 快路径，不再重复请求前置判断；静默、突发刹车、防循环和明确停止仍然优先。明确呼唤不受自主插话冷却影响，其中关键词或引用触发仍须通过 AI 判断，明确 @ 不需要；主人明确呼唤保留原有突发限额例外。

前置判断使用独立 `replyGate` 配置；未配置时复用主服务凭证，DeepSeek 官方接口优先用低成本模型。判断为一次性请求，不启动 DSH、工具或写入模型会话。发送最近最多 3 条短上下文和当前批次的短文本、匿名说话人编号、引用摘要、附件类型；不发送图片字节或长期记忆。机器人已送达的回复会作为短上下文，以判断“继续”“杭州”等接话。判断只回答两件事：

- `addressed`：是不是在喊机器人、直接对它说。取值为 `direct`（@、私聊、命令）、`name`（称呼）、`quote`（引用回应）、`poke`（戳一戳）、`follow_up`（直接接话或抱怨没回）、`none`。
- `related`：是不是接着机器人正在参与的上下文说。取值为 `my_last_reply`（接上一句）、`my_thread`（接同一串话题）、`none`。

任一项非 `none` 才回复。判断不评估“这条消息有没有价值、该不该帮忙”：群里的公开求助如果没喊机器人、也不在它的上下文里，默认不接。分类结果作为内部参考传给 DSH，不作为用户指令。

默认边界是：只在被喊到或接着它的上下文时才参与。其他成员定向互聊、广告刷屏、重复且无新信息、已经解决的问题、普通感叹、仅提到名字、要求安静或上下文不足均应拒绝。模型判断存在误差，不保证语义边界完全准确。超时（5 秒）、缺少凭证、异常、无效 JSON 或字段不一致均静默拒绝，不回退随机插话。群内批量串行判断，每群每分钟最多 12 次、进程最多 4 个并行请求；超额静默跳过。`/cancel` 可取消进行中的判断，`/new` 清除时会中止旧判断，迟到的正面结果不会触发回复。

模型对自主参与可选择 `[沉默]`，不会把这段文字发给群聊，也不将其保存成已发送的对话。失败和沉默不会开始或延长参与期。`/cancel` 可取消自己尚未开始的消息段；管理员或主人可取消其他人的等待段。`/new`、工具策略重置及彻底删除会取消等待段并清除参与状态。

### 自带 Key 的群：强度拉满

群绑定可用的群 Key 后，本群由群 Key 付费，参与强度直接拉满（[`boundKeyGroupPolicy`](../src/social/group-policy.ts)）：

| 项                          | 普通群               | 自带 Key                                |
| --------------------------- | -------------------- | --------------------------------------- |
| 感知判断（地址/上下文判断） | 每条候选消息调用一次 | 关闭，不消耗感知预算                    |
| 插话冷却                    | 30 秒                | 0 秒                                    |
| 每小时插话上限              | 16 次                | 60 次                                   |
| 插话概率                    | 0.45，上浮后最高 0.8 | 100%，不再掷骰子                        |
| 近期消息门槛 / 相关度门槛   | 2 条 / 0.15          | 1 条 / 0                                |
| 参与期续接                  | 600 秒               | 600 秒                                  |
| 突发刹车                    | 10 次 / 120 秒       | 12 次 / 60 秒                           |
| 网页、文件工具              | 按 `/工具策略`       | 自动开放（`boundKeyTools: false` 可关） |

拉满不等于没有边界，以下仍然生效：`quietHours` 夜间静默、`burstMax` 突发刹车、`loopGuard` 防循环、群内串行与排队上限、每用户每分钟 6 次、终端永久禁止、共享 Key 余额不足时停用该副本并尝试下一把；共享池耗尽后用发言人自己的 Key，最后使用内部额度。`@`、`/chat` 与关键词呼唤的处理链路不变。

不想让任何群拿到工具提权、但保留参与度提权时，把 `groupChat.boundKeyTools` 设为 `false`；它只影响网页与文件的自动开放，不改变感知、冷却与概率。

按群退出提权：在 `groupChat.overrides` 里给目标群设 `boundKeyElevation: false`，该群回到普通策略。显式配置的 `maxPerHour: 0` 或 `interjectChance: 0` 仍表示彻底关闭自主参与。提权只在运行时派生，不写回群 Key 状态，也不改写 `/工具策略` 的持久设置；群 Key 停用或余额不足时立即失效。在提权生效的群里用 `/工具策略 网页 关闭` 或 `文件 关闭` 会被拒绝并提示改用 `boundKeyElevation`，避免"命令生效但实际仍开放"的假象；`/工具策略 状态` 显示的是叠加提权后的实际权限。

普通群聊、私聊、`/chat` 和 `/语音` 统一传入引用上下文。仅带引用、没有附加文字的消息也可以进入对应处理流程。优先使用本机已观察内容、适配器提供的标准化原文或归档；OneBot 可在本地缺失时用 `get_msg` 查询当前引用，并核对群号或私聊双方后使用。已发送文字回复按成功回执建立引用索引，可用于引用唤醒。转发记录保留发言人，无法取得的原文不会编造。群回复可选择本段中的某一条进行引用，并提及该成员；引用对象不会改变本轮工具身份。

群聊参与、待处理消息段和引用索引均为有界进程内状态，重启后不恢复这些短时状态。正式对话、去重与手动记忆仍由配置的状态库管理。

### 机器人互聊与循环保护

普通群消息的前置判断同时返回 `source: human | automated | unknown` 与 `loopRisk: boolean`。这只是来源迹象推测，不是身份认证：仅凭文风、长文、AI 辅助写作或正文自称机器人不能确定来源；信息不足使用 `unknown`。固定自动客服模板、反复复述回答、无新任务却互相邀聊等是风险线索。`automated` 或 `loopRisk: true` 强制不回复，即便模型同时给出非 `none` 的 `addressed`/`related`；缺少字段或字段类型不符也拒绝。

平台明确标记 `IsBot` 的消息直接忽略。群协调器还独立设置本地熔断，适用于普通消息、@、`/chat` 和主人请求，命令不能绕过：

- 同一发送者两分钟内重复已经回应过的正文（规范化后至少 8 字符），或复述机器人最近回复（至少 12 字符），静默拦截。
- 同一群、同一发送者两分钟内已送达 4 轮回复，下一次触发两分钟冷却；期间的新内容也不回应。真实用户快速连续交流也可能触发该限额。
- 发送前再次检查，防止排队期间形成循环；失败发送不累计已送达轮次。一个合并批次中的参与者各计一轮。
- 不发送“你是机器人”等提醒，不永久标记账号；记录仅在本进程内按群隔离，重启或清除群会话会重置。AI 分类和本地阈值只能降低循环风险，不能保证识别所有自动账号。

私聊继续使用已有平台机器人标记过滤；本节语义分类和群级熔断用于群聊。

### 回复延迟

普通群聊与关键词呼唤默认等待 1200ms，同一发言人的续句刷新等待时间，一段最多等 4000ms；其他人发言不延长已有直接呼唤的截止时间。`/chat` 不主动等待合并，但仍遵守群内串行、防循环和限流。显式配置的等待值保持优先。

前置识别访问官方 `api.deepseek.com` 时显式设置 `thinking.type=disabled`（[官方接口说明](https://api-docs.deepseek.com/guides/thinking_mode/)），只生成短分类结果；第三方兼容接口不自动追加此厂商参数。正式回复的推理配置保持原样。

`Group reply latency` 日志记录 `waitMs`（合并及群内排队）、`gateMs`（前置识别）、`responseMs`（后续处理及发送）、`totalMs`。不记录正文或凭证；数据用来区分本地等待与模型/发送耗时。当前正式回复仍有整段缓冲，以上调整不是首字流式输出，也不代表已验证线上响应时间。

引用上下文显式包含 `hasQuote`、引用 ID、原发言者 ID/昵称、正文和附件描述。原文不可用时传入“引用消息内容不可用，不能猜测原文”。引用中的图片若提供 URL，会与当前消息图片去重后进入 DSH 原生图片输入，继续遵守 CDN 白名单、大小、数量和格式检查；OneBot 引用图片有文件标识而地址缺失或失效时，可在附件处理阶段重新核对引用归属和附件标识，再通过 `get_image` 获取。引用图片获取失败会报告媒体错误。其他引用附件只带类型和“未读取内容”标记，不宣称读过音视频。引用内容不能修改当前请求的身份与权限。

OneBot 合并转发在实际处理消息时使用消息自身携带的转发 ID 调用 `get_forward_msg`，最多读取 3 个转发、合计 24 条和 6000 字，保留发言人及附件类型；嵌套转发只标记类型，不读取附件。接口失败会标记内容不可用。群聊先完成分段及去重，再按每条来源消息读取；该扩展的真实平台兼容性仍需验收。

引用索引在命令路由之前采集，因此私聊和命令消息也可被后续引用。机器人文字回复按原会话归档，不继承用户发送的附件。引用缓存默认保留 15 分钟、每会话最多 100 条；重启后或超出缓存范围且平台查询不可用、返回信息不足以核对归属时，只能感知存在引用，无法恢复原文。真实 OneBot 实现的返回字段和权限仍需实测。

### 平台事件上下文

除消息创建外，已接入本机 AlemonJS SDK 定义的以下 16 种事件：

| 事件                                                                         | 处理                                                                     |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `message.update`、`private.message.update`                                   | 取消当前会话待处理回复，清理近期上下文和旧引用；平台提供新正文时重建引用 |
| `message.delete`、`private.message.delete`                                   | 取消当前会话待处理回复，移除该条引用缓存，告知模型原文已撤回             |
| `message.reaction.add`、`message.reaction.remove`、`message.pin`             | 记录目标消息发生表情回应或置顶事件；缺少详情时不猜测表情含义             |
| `member.add`、`member.remove`、`member.ban`、`member.unban`、`member.update` | 记录成员进退群、禁言和资料变化，不修改成员权限                           |
| `channel.update`、`guild.update`                                             | 记录频道或群资料变化，不猜测未提供的字段                                 |
| `notice.create`、`private.notice.create`                                     | 记录通知存在，不直接转发原始通知载荷或猜测是戳一戳、申请等               |

这些事件默认不发言、不单独调用 AI，仅在后续正式回复时提供最多 8 条参考。每个会话最多保存 20 条、保留 10 分钟，进程最多 1000 个会话；按平台、Bot 和平台会话标识隔离，不跨频道传播 guild 事件。没有足够会话标识时无法关联，必须由适配器补全。昵称和事件正文仍是不可信资料，不能授予工具权限。

编辑/撤回采用保守策略，取消整个会话当前及排队回复（因为其他消息可能引用它），而非只取消同 ID 请求。已发出的消息无法撤回。此处理不等于删除持久聊天归档、模型历史或已形成的长期记忆；需要清除记录时使用相应清理命令。引用缓存重建只依据适配器提供的新正文，不主动拉取平台历史。

交互按钮确认、好友/入群申请批准、登录二维码和连接控制尚未接入模型动作；它们需要各自的确认协议和权限处理，不当成普通聊天自动执行。

### QQ 官方机器人私聊原生流

当消息来自 `Platform: qq-bot`、私聊 C2C、携带 `MessageId` 且框架提供 `message.stream` 时，文字回复自动尝试原生流。其他平台和群聊保持原发送方式，不把频道私信当成 C2C。

直接模型和业务工具模型支持读取 SSE 增量，首个片段可在模型完成之前发送。平台更新使用 `replace` 更新同一条消息，索引递增、复用返回的流消息 ID 和固定 sequence；参照本机 qq-bot SDK 的流助手，每次更新至少间隔约 500ms，期间合并最新片段。结束发送 `complete`，成功后才记录完整回复及引用索引。缓存完整文字用于最终状态和历史，不是等待全文生成后才开始发送。

语音、整段关键词审核、静默判定、引用回复标记和回复改写模块需要先完成处理，不能承诺这些路径的首字流式。模型服务若忽略 stream 参数并返回普通 JSON，只能在收到全文后发送，不伪造上游增量。工具流中的 reasoning_content 不发给用户；工具调用参数仍按原权限校验后执行。

流失败不自动重发全文，避免部分内容已送达后的重复；取消后停止后续更新，已经提交的请求无法撤回。平台还可能因账号权限、消息配额或长度限制拒绝原生流。当前验证使用模拟 SSE 和平台回执，真实 QQ 账号收发需要现场验证。

## 自主回复判断模型

判断是不是在喊机器人、是不是接着它的上下文，以及机器人循环风险，使用独立的一次性文本请求，不调用工具。未配置 `replyGate` 时复用主服务凭证：DeepSeek 官方接口固定优先使用低成本 `deepseek-flash`，关闭思考，不跟随主聊天模型升级到 Pro；其他兼容接口沿用主模型（不同服务的价格和模型名称无法统一推断）。

在已有配置段中增加以下内容可单独指定判断模型；只填 `model` 就会复用原接口和密钥：

```yaml
alemonjs-agent-link:
  replyGate:
    model: 'deepseek-flash' # 可改成服务支持的便宜文本模型 ID
    # baseUrl: 'https://api.example.com/v1'
    # apiKey: '<REPLY_GATE_API_KEY>'
```

空字段等同未配置。切换到不同域名的服务时必须填写该服务的 `apiKey`，不会把主服务密钥发给新服务；第三方服务还需填写其支持的 `model`。独立凭证可在主模型尚未配置时用于判断，但正式回复仍需主模型配置。判断配置随后续请求读取，无需为配置修改重启。

请求限制为 80 个输出 token、5 秒超时，最近上下文压缩到 3 条，并保留并发限制及严格 JSON 校验。失败时不升级到昂贵模型重试，按无需回复处理。模型价格会变化；默认选择依据 [DeepSeek 官方价格表](https://api-docs.deepseek.com/quick_start/pricing/)，不承诺自动搜索全网最低价。此配置只影响自主回复判断，不改变正式聊天模型。

默认肥鱼的背景、社区参考与体验检查见 [肥鱼的群友人设](dafeiyu-persona.md)。新增回声港背景、冲浪与游戏偏好、具体说话示例；这些是虚拟人物设定，不是后台真实经历。

### 主人追加人设

验证过的主人可在私聊中使用：

- `/人格 追加 dafeiyu 喜欢简短直白地说话，偶尔讲冷笑话`：累积追加，保留原人设。
- `/人格 查看追加 dafeiyu`：查看已追加的内容。
- `/人格 清空追加 dafeiyu`：只清空追加设定，不删除原人设。

`dafeiyu` 是肥鱼人格编号，也可换成已有的其他人格编号。追加内容持久化保存，累计最多 4000 字符，对使用该人格（包括默认肥鱼）的所有会话下一轮生效，不修改进行中请求的快照。未切换人格时，自定义 `defaultSystemPrompt` 仍作为基础，追加设定叠加在其后。此功能需要启用人格模块，不能通过追加设定授予工具权限或冒充主人。

### 活跃、个性、工作、专业四种程度

默认是 **活跃**：先接眼前这句，短、快、敢接梗，像群里最会接话的那个人；一到两句为主，多件事才用 `|||` 分条，有合适素材时可用表情包或短语音。**个性**更偏稳定的人物交流；**工作**重目标、执行和结果；**专业**重准确、依据与不确定性，语气克制。四种程度都不虚构现实身份、能力、记忆或操作结果。

主人可在目标群或私聊中发送 `/人格 程度 活跃`、`/人格 程度 个性`、`/人格 程度 工作`、`/人格 程度 专业`，只改变当前会话；`/人格 程度` 查询当前生效值，`/人格 程度 默认` 恢复继承全局默认。普通群管理员和其他用户不能修改程度。

主人在私聊中用 `/人格 全局程度 工作` 修改全局默认，也可选“活跃”“个性”“专业”；`/人格 全局程度 默认` 恢复内置“活跃”。已有会话的单独设置优先。程度持久化保存，下一轮生效，不清空聊天记录、不替换人格或主人追加设定，进行中的回复保持原快照。此功能需要启用人格模块；同一人物的表达习惯与程度冲突时，以程度为准。

### 重启与上下文连续性

使用同一配置和数据目录正常重启时，人格文件、主人追加设定、表达程度、持久化记忆和聊天归档保留。本地状态文件或 Redis 中的有效聊天历史、近期群聊摘录也会按原有代际、条数、字数和过期时间读取；默认聊天历史最多 10 轮、24 小时，近期群聊摘录通常最多 15 分钟。保存的归档不等于每轮全部送给模型。

重启不会完整恢复运行现场：进行中的生成和工具任务、等待合并的消息、前置自主判断器的短期上下文及引用索引是进程内状态；DSH Python SDK 会话也是内存对象，目前没有恢复旧 SDK 会话的接口。这些状态会丢失，可能表现为重启后的接话判断变化或引用原文不可用，不能声称“完全无感续聊”。已持久化的正式聊天历史可供对应模型链路继续使用，但不能还原工具执行现场。不要在仍有任务执行时主动重启；配置、人设程度等已有热读取入口优先使用热更新。

### 群聊分句与“等我说完”

同一用户未获前置判断放行的消息保留最多 45 秒，后续续句到达时合并再判断，仍保留发言人、图片类型与引用。若新续句在 AI 判断期间到达，旧结果不直接触发回复，而是把两段合起来重新判断。不会因此绕过防循环、权限或判断频率限制。

用户可单独发送“肥鱼，等我说完”“先别回”“我还没说完”，然后分几条发送材料，最后单独发送“说完了”“可以回了”或“可以回答了”。这是精确的整句控制，不解析故事或引用中的同名短语；语义层也会考虑是否明确尚未说完。暂存按群和发言人隔离，别人不能替你结束。结束后再经过判断，并非无条件回答；`/chat` 可明确提交。

每人最多保留最近 20 条、6000 字符的材料，超限移除较早片段；等待模式两分钟无新消息过期，过期不自动发言。`/cancel`、会话重置或撤回导致的上下文失效会清除相应暂存。暂存为进程内状态，重启会丢失；已经开始生成或发送的回复不能由“等我说完”撤回，可用 `/cancel` 取消仍在运行的请求。本节机制用于群聊协调器，私聊普通消息仍按现有私聊入口处理。

## Redis 每日预算

在 `alemonjs-agent-link.budget` 设置 `enabled: true` 开启。个人免费额度跨群和私聊共用。群付款顺序为共享 Key 池 → 发起人自己的 Key → 群充值（已有余额）→ 个人免费，后台判断最后回退群感知预算。没有群共享的免费聊天额度。详细配置见 [每日额度保护](budget.md)。

### 减少额外判断与不必要工具调用

明确 @ 与 `/chat` 跳过“回不回”模型请求，私聊继续直接进入现有会话。关键词和普通群聊仍合并后使用轻量判断；不新增“聊天或 Agent”分类，不切换另一套历史。明确 @ 保留本地机器人识别、防循环、限流、分句等待和静默控制；单独的“@肥鱼 不用回复”不触发生成。`/chat` 作为显式提交命令保留原有优先级。

所有表达程度共用 `src/agent/tool-use-policy.ts` 的执行规则，并注入业务工具模型、DSH 工作区请求和直接模型请求：一般聊天、基于已有资料的改写等直接回答；需要外部信息或执行才能完成当前请求时才调用必要工具。连续任务的授权不要求重复表达；询问能力不等于授权操作。保持正常记忆加载，禁止以省调用为理由编造实时信息或执行结果。

这属于行为指导，无法保证模型绝不误用工具，权限和预算限制仍由代码执行。本次没有缩减会话历史或迁移会话存储，也不承诺固定节省比例。应观察实际判断次数、工具调用与账单；明确 @ 省下一次判断请求，但正式回复仍消耗 token。

群聊近期摘录的字数预算保持不变：先选最新三条，再补较早的重要问题，按优先级分配预算后恢复时间顺序。重复文本保留最新一次，避免旧记录挤掉最新纠正。完整当前请求和已解析引用仍走原有输入链路，不引入另一套 DSH 会话。

## 私聊个人 API Key

用户可在本人私聊中用 `/我的钥匙 私聊` 管理自己的 DeepSeek 官方 Key。它是独立的加密 Redis 记录，不修改这里的共享 `apiKey`；余额不足时自动停用，需手动恢复。指令、回退规则和加密文件备份要求见 [个人 Key 管理](personal-key.md)。

群管理员先私聊添加群聊钥匙，再到群里用 `/我的钥匙` 查看编号并 `/授权钥匙 编号`；提供者私聊 `/授权记录` 可撤销。具体流程见 [群 Key 管理](group-key.md)。
