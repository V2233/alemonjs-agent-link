# 肥鱼的相处机制

目标是让交流随着真实相处变化。提示词负责表达方式，程序负责证据、状态、是否适合打扰和回执；不能用增加人物台词代替状态管理。

## 已接入的第一段闭环

真实消息 → 保守识别当前用户的明确表达 → 持久化状态 → 当轮决策 → 生成回复 → 平台送达后记录 → 下一轮根据反馈调整。

- `history-capture` 在不消费事件链的前提下采集明确状态，未触发回复也能收到拒绝和晚安。机器人、个人密钥命令不参与。
- `InteractionStore` 使用独立 `interactions.sqlite`，不修改既有数据库表。按平台、机器人、会话、用户隔离，只保存状态及最近 32 个有效输入标识（用于重复事件去重），不复制原始聊天正文。接入会话清除和保留期清理。
- 当前状态包含休息/喝水需求、需求有效期、拒绝催促、准备休息截止时间、最近一次关心送达时间和角色扮演有效期。
- 初始策略：需求两小时过期；关心送达后四小时冷却；明确准备睡觉后八小时避免主动打扰，明确睡醒、不睡了或睡不着可以解除；喝水反馈不能解除休息状态。拒绝催促持续到明确恢复或记录被清除。上述时长是本次工程默认值，不是用户作息推断。
- `interaction` 模块按当前状态提供结构化决策原因及当轮行为；不要求主人身份、好感度或人工订阅。其他人物不注入肥鱼的交流策略。
- 普通回复完成发送后才记录关心；失败不扣掉机会。主动发送前再次检查休息状态，休息中取消发送。
- 明确角色扮演邀请进入两小时有效的会话状态，重启后保留，说“不演了”或“结束角色扮演”退出。期间生活台词不进入现实关心状态，但明确拒绝催促仍然生效。机器味反馈和玩笑解释目前仍是当轮策略。
- 只有当前需求可关心，且已送达文字包含对应建议时才记录关心；自述、引用和否定句不消耗机会。恢复催促不会复活拒绝期间积累的旧需求。

## 明确的能力边界

当前识别器是保守的短句规则，不是完整语义理解；只识别部分明确表达，复杂说法可能漏判。发送后的关心识别也采用规则，未覆盖所有表达。引用、假设及角色扮演文本不作为现实状态证据。不按服务器时间猜测用户熬夜。

冷却和拒绝通过生成上下文约束措辞，尚无可证明覆盖所有同义表达的输出拦截器；只有休息状态对主动发送有程序硬拦截。不能把本次测试通过说成模型每次都能说得自然，或真实平台投递已端到端验证。

## 完整系统后续扩展应遵循的结构

1. 证据识别：把说话人、原始消息标识、现实/引用/虚构、置信度与状态变更分开；语义识别只能提出候选，不能直接授予权限或发送消息。
2. 互动状态：分别管理生活需求、交流偏好、角色扮演开始/结束和告别状态。用户的纠正优先，临时状态有有效期，真实记忆不混入虚构设定。
3. 决策层：回应、陪着聊、接梗、入戏、轻量关心、告别或沉默。冲突优先级为明确拒绝与休息、当前任务、当前互动邀请、一般主动参与。
4. 表达层：依据决策生成自然语言；检测报告腔、违背拒绝和重复催促，有限次纠正，不能一味套固定句库。
5. 反馈层：分别统计识别漏判/误判、实际送达、重复提醒、拒绝后仍催和虚构状态污染。用真实场景回放推动规则或语义识别升级。

这轮实现的是关心与休息的状态闭环及当轮互动选择；角色扮演只保存是否处于场景及有效期，人物与剧情依赖现有对话历史；完整语义识别、管理页和上述质量指标尚未实现。

## 消息回应台账

归档库新增独立 `reply_ledger` 表，不改变原消息及本地收件箱已读进度。键为隔离后的会话范围加原消息 ID。真实私聊、明确呼唤和提及记录为待回应；斜杠命令先记作本插件未认领，不推断其他插件是否执行。

实际聊天入口记录 queued，首次收到模型正文记录 processing。通过已有发送回执校验后记录 partial，整个发送流程正常完成后才由 partial 转为 delivered；失败和取消分别记录。回复选中其他原消息时，只更新选中目标，不顺便结清当前批次的其他人。delivered 表示回复送达，不表示游戏命令或外部业务执行成功。

同会话有人正在输出时到达的消息保留当时的记录线索；这只支持核对当时存在其他请求，不证明具体漏接原因。旧 processing 状态可能是进程中断留下的，不能据此断言现在仍在忙。没有历史归档权限或关闭归档时不另外保存聊天台账。

明确对肥鱼说“别回了”会让该发言人在本会话的待回应聊天停止参与漏接修复，不影响其他人，也不声称取消其他插件命令。撤回、会话清理和保留期清理同步清除对应台账。收到漏接反馈时先查最近两小时台账，再用有限历史检索兼容旧记录；不主动重跑旧命令。

其他插件真实认领/完成回执、等待用户补充状态、自动补接调度及管理页尚未接入；当前不能展示完整的跨插件处理结果。测试使用真实框架处理器和可控模型/发送回执，不代表真实 QQ 投递验证。
