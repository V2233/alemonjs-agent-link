# 模块与业务工具

内置 `platform` 提供 OneBot 连接查询及当前发言人回戳；`group-admin` 默认对所有群、在本轮发言人为主人时提供群管理工具，执行时由适配器重新核对权限；设 `allGroups: false` 后才使用白名单。连接配置、回执和未知状态语义见 [OneBot 接入](onebot.md)。

AgentLink 在排队请求实际执行时加载模块。模块可以提供模型可调用的业务工具、每轮参考上下文、消息输入转换、完整回复转换，以及发送成功后的活动处理。模块文件由服务器管理员维护，是拥有 Node.js 权限的本机代码。

## 配置

```yaml
alemonjs-agent-link:
  modules:
    # 可省略，默认为 workspaceRoot 同级的 modules 目录。
    directory: '/absolute/path/to/agent-link/modules'
    disabled: []
    maxToolRounds: 8
    maxToolContinuations: 2
    settings:
      greeting:
        suffix: '咕噜。'
```

`maxToolRounds` 限制每段可执行工具的轮数，范围 1–16，默认 8；每轮最多 8 个调用，每段最多 32 个。首次触顶保留模型历史和回执，静默释放全局执行名额并排队续跑；同一会话继续串行，后续消息不会抢先进入原任务的上下文。`maxToolContinuations` 默认 2（最多共三段），范围 0–4；设为 0 可直接收尾。正常结束不额外续跑，排队期间不发送提示，也不重做已有回执的同编号调用。

连续用完所有续跑次数仍未结束时，最多请求一次不带工具的模型汇总，说明已有结果、未完成和不确定部分；汇总失败使用固定提示。超出单轮8项的待执行批次不执行，恢复提示要求模型分批处理。所有分段、排队和汇总共享原始总时限、取消信号及额度，续跑不会重置超时或绕过费用检查；`/取消`、会话重置同样中止等待中的续跑。每次模型请求和实际调用仍可能收费，增加续跑次数会增加潜在调用量。

模型参数在执行前再次校验。非法字段、缺少必需字段、类型/范围错误或无效JSON，向工具循环返回`error.code=INVALID_ARGUMENTS`、`outcome=not_started`及有界的field/reason；可提供允许的字段名，不回显参数值。校验失败不会进入实际工具处理器，模型可根据当前schema修正参数后发起新调用，仍受原轮次、权限和预算限制。处理器已经进入后发生的异常不标作not_started，也不把任意服务错误正文回传；即使处理器抛出同名校验异常，也保持这一边界。

内置 `memory` 模块默认启用。明确保存工具仅向私聊提供；当前会话还可检索自动整理的资料、核对来源与人物档案。停用该模块使用 `disabled: [memory]`，已有记忆及手动命令继续保留。自动整理、版本恢复和删除语义见[长期记忆](memory.md)。

内置 `qa` 模块默认启用，保存“为什么 / 为何 / 为啥”类问答。出现问因词时先检索当前会话和全局内置条目，命中后把参考答案注入本轮上下文；回复送达后记录这次提问，未命中的问答自动写入当前会话。模型可用只读工具 `search_qa` 主动查询；主人明确要求时可用 `remember_qa` 保存到当前会话或全局。自动学习的内容可能过时，注入时会标注来源。配置、隔离与清理规则见[问答库](qa.md)。

内置 `stickers` 模块提供 `list_stickers`、`send_sticker`、`make_sticker`、`collect_sticker`、`add_sticker`、`import_image_folder` 和 `manage_sticker`。查询及发送支持按编号或标签查找；收藏当前附件对主人在私聊和群聊开放，修改名称/标签和移除清单（并尝试删除 QQ 收藏）仅对主人私聊开放，均须有明确请求。`add_sticker` 只接受 HTTPS 地址或素材目录内的本地图片，可用 `kind: avatar|sticker` 和 `category` 分类；`collect_sticker`、`add_sticker`、`import_image_folder` 同样可指定 `kind/category`；`make_sticker` 把本轮/最近图片或素材库表情裁成方形 PNG，可上下配字并默认同轮发送；动图只取第一帧。发送每轮最多尝试一次，命令及自动表情均不设置插件层冷却，发送频率由框架控制。素材目录、收藏与二创限制见[媒体能力](media.md)。`modules.disabled: [stickers]` 停用模型工具，不影响手动命令或自动表达；后台自主搭话不开放这些工具。

### 私聊主动搭话

```yaml
alemonjs-agent-link:
  modules:
    settings:
      proactive:
        activity: active # quiet / balanced / active；默认最积极
        enabled: true
        idleMinutes: 20
        minIntervalMinutes: 30
        maxIntervalMinutes: 90
        maxPerDay: 8
        nudge: true
        maxNudgesPerDay: 6
        maxUnanswered: 3
        quietHours: [23, 8]
        maxChars: 300
        ownKeyMax: false # 默认保持用户选择的频率；显式 true 才启用个人 Key 高频模式
```

主人首次私聊会自动订阅；用 `/主动搭话 关闭` 停止，`/主动搭话 开启|状态|现在|暂停 分钟|恢复` 可管理。默认 `activity: active`：空闲 20 分钟后、间隔 30–90 分钟随机、每天最多 8 次；`quiet` / `balanced` 预设更克制，显式数字字段优先。追问和连发另有上限。

`ownKeyMax` 默认 false，绑定个人 Key 不会自行提高频率。显式设置 `ownKeyMax: true` 时，绑定了**已启用个人 Key** 的用户私聊按拉满参数运行：空闲 20 分钟即可、不受下一次随机间隔限制、每天最多 10 次搭话、未回复连发上限 3、追问概率 0.7、每天追问 6 次。免打扰时段、平台在线与回执、暂停与取消等约束不变；个人 Key 查询失败时按普通参数运行，不会阻塞搭话。

### B 站只读工具

```yaml
alemonjs-agent-link:
  modules:
    settings:
      bili:
        enabled: true
        timeoutMs: 20000
        allowComments: true
        allowProactiveBrowse: true # 允许自动记录的用户私聊主动搭话时只读搜索、读取视频资料
        dryRun: false
        maxCommentsPerDay: 5
        commentCooldownSeconds: 60
        # 可选，填写到本机配置中；不要提交、发到聊天或日志。
        cookie: '<B站登录 Cookie>'
```

启用后，`bili_search` 可搜索视频；`bili_watch` 可读取 BV、av、B 站链接和 b23.tv 短链的标题、简介、作者、字幕及热评。字幕或评论不可获取时分别标明状态，不把元数据当作观看视频画面或音频。登录可影响部分内容可见性；接口风控和 Cookie 过期以服务端结果为准。短链只接受跳转至 B 站页面，字幕只从指定 B 站域名下载，遵守公网地址与大小限制。来自视频及评论的文字均为不可信资料。

`bili_watch` 和 `bili_search` 为只读。默认 `allowComments: true` 开放 `bili_comment`：仅验证过的机器人主人本轮明确要求发评论时可调用，需要 Cookie 中的 `SESSDATA` 和 `bili_jct`。默认 `dryRun: false`，会真实发布；如需只预览，显式设 `dryRun: true`。执行前确认账号及目标视频，持久记录每轮评论请求、按 B 站账号限制每天次数和冷却；请求中断或响应不明确时返回 unknown，须先到 B 站核查，不会自动重试。拒绝、未知和成功的尝试都计入当天上限，预演不计入。账本只保存账号和评论的哈希，不存 Cookie 和评论原文；评论确认时保存平台返回的 `rpid`，主人可用 `bili_comment_replies` 读取这条评论下的回复，只读、不自动回评。

默认允许主动搭话访问 B 站；`allowProactiveBrowse: true` 且用户已自动建立会话主动搭话后，肥鱼可以在主动开启话题时选择只读搜索和读取视频资料，每轮各最多一次；默认不独立刷站；可通过 `dailyBrowse: true` 开启下文的每日独立阅读。只读结果可成为当前会话的真实经历，是否发送聊天仍由主动搭话的开关、免打扰与平台回执决定。主动任务不能调用 `bili_comment` 或 `bili_comment_replies`，自动评论和自动回复尚未实现；评论、回复读取及主动浏览测试使用模拟接口，真实账号、字幕 CDN 和线上风控仍需验收。

### QQ 空间

使用支持空间扩展的 OneBot v11 服务，并配置：

```yaml
alemonjs-agent-link:
  transport: onebot
  modules:
    settings:
      qzone:
        enabled: true
        allowPost: true
        allowInteract: true
        dryRun: false
        visibility: friends # all、friends 或 self
        maxPostsPerDay: 5
        maxInteractionsPerDay: 10
        cooldownSeconds: 60
        diary:
          enabled: false
          botId: '<机器人QQ号>' # 字符串，与 OneBot 登录账号一致
          ownerId: '<主人QQ号>' # 字符串，须是 OneBot 已配置主人
          hour: 20
          timezone: 'Asia/Shanghai'
```

主人在 OneBot 私聊中可使用模型工具 `qzone_read` 查看机器人自己的说说或可访问的好友动态。空间扩展不是 OneBot v11 的通用保证：服务须分别支持 `get_qzone_msg_list` 和 `get_qzone_feeds`，返回值以平台为准。

启用 `allowPost` 后，`qzone_post` 可以处理主人本轮明确要求发布的文字说说；默认 `dryRun: false` 会真实发布，设为 `true` 可只预览。设为 false 后适配器再次核对主人身份、开关和参数，再调用 `send_qzone_msg`。可见范围来自主人的明确要求，否则使用配置默认值。每轮一次，持久限制账号的每日次数和冷却；平台未返回可核验的说说 ID 或发送中断时标记为 unknown，先到空间核查，不会自动重试。尝试结果的账本只保存哈希，不保存正文。

`qzone_detail` 可读取最近通过 `qzone_read` 获得的动态详情和评论。`qzone_activity` 汇总自己或好友最近 3 条动态下的新评论，按主人私聊记忆已读，避免重复汇报；只读，不自动回复。启用 `allowInteract` 后，主人本轮明确要求时可用 `qzone_interact` 评论或点赞；需要 OneBot 服务支持 `get_qzone_msg_detail`、`comment_qzone` 和 `like_qzone`。只能操作同一主人私聊中最近 15 分钟读到、且平台提供了作者账号的说说；好友动态须由平台标为说说类型（appid 311），点赞还要求发布时间。目标缓存只在进程内保存，重启或模块重载后需重新读取。互动遵守同一试运行设置，按机器人账号单独限制每日次数和冷却；结果不明时应核查，不能自动重试。空间评论是对说说发表评论，尚未支持按评论 ID 精确回复。

主人明确要求配图时，可使用本轮消息或引用中已读取的图片，最多 4 张，每张不超过 8 MiB，编码后合计不超过 28 MiB；图片获取或校验失败时不会退化为只发布文字。图片仍受媒体输入的下载限制。

可选开启 `diary.enabled`：每天到达配置时区的整点后，从机器人与指定主人私聊的当日归档中取最近最多 20 条文字，交给已配置的聊天模型生成日记；没有内容或模型决定沉默则跳过。目前不读取群聊，也不自动配图。默认 `dryRun: false`；如果只想预览，设 `dryRun: true`，并保持 `allowPost: true`。可在主人私聊中询问自动日记状态，模型可调用 `qzone_diary_status` 查看最近结果与预览。每天按机器人账号持久领取一次，生成失败、预览、重启或发布结果不明都不会当天自动重试；`claimed` 可能代表仍在处理，也可能是中断后的未确认状态。自动与手动发布共享账号日限额和冷却。日记正文与状态保存在本机 SQLite，按配置的保留天数清理。

日记会根据私聊记录生成对外内容；模型不能保证完全去除私人细节，启用真实发布前应先通过预演检查内容和可见范围。

后台浏览与自动互动尚未实现。模拟测试不能证明特定 OneBot 实现、模型生成质量或真实 QQ 账号的空间扩展可用。

主人私聊发送 `/agentmodules` 查看模块加载结果，同时检查最新文件。正常聊天也会自动检查更新。坏模块会显示加载失败，其他模块继续加载；本地替换模块加载失败时不会偷偷启用同名内置模块。

## 本地模块

创建 `modules/greeting/index.mjs`：

```javascript
export default {
  id: 'greeting',
  name: '问候表达',
  version: '1.0.0',
  apiVersion: 1,
  setup(api) {
    api.on('reply', text => {
      const suffix = String(api.settings.suffix || '咕噜。');
      return `${text} ${suffix}`;
    });
    api.tool({
      name: 'current_time',
      description: '查询当前时间。',
      parameters: {
        type: 'object',
        properties: {},
        additionalProperties: false
      },
      execute: async (_args, context) => {
        context.signal.throwIfAborted();
        return { ok: true, iso: new Date().toISOString() };
      }
    });
  }
};
```

目录名和 `id` 必须一致，使用小写字母、数字和短横线。同名本地模块替换内置模块。不同模块不能注册同名工具；`agent_workspace` 为保留工具名。

模块目录的普通文件会一起生成版本快照，相对导入的依赖文件变动也会触发更新。每个模块最多 200 个文件、合计 5 MiB，最多嵌套 8 层，不接受符号链接。`.开头文件` 与 `node_modules` 不进入快照；第三方包需要安装到服务进程可解析的位置。

更新时，新请求使用新版本，正在运行的请求继续使用原版本。旧版最后一个请求结束后执行清理。删除目录会卸载模块；升级安装包不会覆盖用户模块目录。快照位于 `workspaceRoot` 同级的 `module-cache`，模块持久目录位于同级的 `module-data/<id>`。

## API

| 接口                                                     | 作用                                             |
| -------------------------------------------------------- | ------------------------------------------------ |
| `api.id`                                                 | 当前模块 ID                                      |
| `api.settings`                                           | 本模块设置的独立副本，不含其他模块配置或模型凭证 |
| `api.dataDirectory`                                      | 本模块持久数据目录                               |
| `api.tool(tool)`                                         | 注册业务工具，参数在执行前重新校验               |
| `api.on('system', (prompt, context) => string)`          | 转换本轮系统提示词；非空且最多32000字符          |
| `api.on('context', context => string)`                   | 追加本轮参考资料                                 |
| `api.on('prompt', (input, context) => input)`            | 转换文字或原生图片输入块                         |
| `api.on('reply', (text, context) => string)`             | 完整回答生成后、发送前转换回复                   |
| `api.on('activity', ({input, output}, context) => void)` | 回复完整发送后的活动处理                         |
| `api.onDispose(cleanup)`                                 | 模块卸载或替换后的资源清理                       |

`context` 包含 `channelId`、`userId`、`platform`、`private`、`owner`、当前原始 `userText`、本轮 `capabilities` 和 `signal`，以及可选的 `requestId`、原始输入 `inputId`、是否直接呼唤的 `addressed`。`owner` 来自事件的主人身份，不能根据昵称或模型参数判断。工具使用 `available(context)` 决定是否在当前回合开放，执行时还会复核。`activity` 只在完整送达后执行，主动沉默不触发。

工具参数支持 object、array、string、boolean、number、integer，以及必填、枚举、长度和数值范围。object 默认拒绝未声明的参数，除非显式设置 `additionalProperties: true`。工具返回可 JSON 序列化的业务结果；推荐 `{ok, message, ...data}`，不要返回凭证。异常给模型的结果统一为失败，不包含异常堆栈。

## 模型与历史

存在可用业务工具、回复转换模块或本轮系统提示词变化时，主模型通过兼容 Chat Completions 的 function tools 完成调用循环。存在工具时配置的模型服务必须支持工具调用；服务不支持时本轮报错，不假装执行成功。内置人格和心情见[人格、心情与自动表达](companion.md)。

网页任务通过隔离 DSH 会话的 `agent_workspace` 执行，需要沙箱就绪和网页权限。文件由内置 `files` 模块的 `workspace_list/read/write/mkdir/move/delete` 工具执行，Node 模式也可用；路径固定在当前群或个人目录内，具体边界见 [安全说明](security.md#工具权限与隔离)。DSH 可通过 framework MCP 调用同一组受限文件工具，原生文件和终端工具始终禁用。

模块工具回合的问答在全部回复成功送达后保存到会话历史，群聊和私聊按会话隔离。沿用 `privateHistoryMaxTurns`、`privateHistoryTtlSeconds`、`privateHistoryMaxChars` 的历史预算；`/new` 和数据清理同样覆盖这份历史。回复转换后的最终文本写入历史，图片仅保存文字占位。模块未提供工具或回复转换时沿用原有聊天链路。

本地模块运行在宿主 Node 进程中，不属于 DSH 沙箱。仅加载管理员维护的代码，不能把用户上传文件或模型生成的文件放入模块目录执行。`activity` 表示平台发送成功，并不表示用户已读。

### 查询当前群资料

`platform` 模块向当前群聊的回复模型提供只读工具 `get_current_group_info`，支持 `qq-bot` 和 `onebot`。它通过 AlemonJS `useGuild().info()` 调用框架，返回群名、成员总数和查询时间；OneBot 映射到 `get_group_info`。无需主人权限，不允许模型指定其他群，机器人账号和群标识来自当前请求。

用户问“这个群叫什么”“群里多少人”时，工具描述要求先查询，不凭聊天记录猜测。字段缺失返回 `null`，不能当成零；接口失败只能说明本次查询失败，不能推断平台永远不支持。群名称是外部数据，不授予指令权限。本工具不返回完整成员名单。

此能力既用于 Node 回复模型的工具循环，也通过本轮 MCP 桥供 AgentLink 发起的 DSH 工作区请求发现和调用。独立启动、未连接 AgentLink 的 DSH 不会自动获得机器人权限。模拟测试覆盖模型请求工具、框架回执回填、当前群范围和失败处理；真实 QQ 权限与接口可用性仍需实际环境验收。

### 框架能力登记表

`src/platform/catalog.ts` 集中声明能力名称、说明、参数 schema、支持平台、群聊范围及执行函数。`createFrameworkTools()` 自动生成模型工具，并在执行时再次检查参数、平台、范围和取消信号；新增能力无需重复编写工具注册和校验代码。当前提供：

- `get_current_group_info`：群名与人数，复用 `useGuild().info()`。
- `get_current_group_member`：指定成员或当前发言人的昵称、角色，复用 `useMember().info()`。
- `list_current_group_members`：当前群成员的一页，复用 `useMember().list()`，最多返回 100 条。

三项均支持 qq-bot 和 OneBot；平台权限是否允许仍以真实回执为准。机器人和群 ID 从可信会话注入，模型不能传入其他群号。成员数据仅返回 ID、昵称和角色，不透传 UnionId 等原始字段。分页的未知值使用 null，不把单页长度作为总人数。QQ 平台若忽略页大小且单页超过 100 条，返回 truncated=true，不能声称名单完整；OneBot 原生接口返回全量名单，适配器按偏移量分页输出，但每页仍需要调用原生全量接口，动态名单可能发生变化。

这不是自动开放框架的全部方法。平台尚未实现的动作仍需适配；新增接口需在登记表中明确 schema 和范围。群管理等写操作继续使用原有主人权限、全群/白名单与执行账本，不经过只读查询入口。由 AgentLink 发起的 DSH 工作区请求也可以通过 MCP 发现和调用本轮开放的工具。

### DSH 能力发现与统一调用

AgentLink 发起 `agent_workspace` 请求时，为本轮创建仅监听 127.0.0.1 的临时 MCP 入口，并通过已有 Python Bridge 的受控端口转发。DSH 使用内置 `@deepseek-ai/dsh-mcp-client`，获得两个稳定入口：

- `mcp__framework__discover({})`：返回当前平台、会话范围及精简能力目录。
- `mcp__framework__discover({name})`：按需读取一个能力的完整参数 schema。
- `mcp__framework__call({name, argumentsJson})`：使用该 schema 编码参数，调用后获得真实结果。

目录来自本轮模块租约中实际注册并通过 `available(context)` 的工具，包含平台查询及其他已开放业务能力，自动排除 `agent_workspace` 防止递归。新增模块工具无需另外编写 DSH 工具适配；未登记的框架底层方法不会被任意反射暴露。目录只表示本轮允许尝试，不表示平台账号权限已核验，也不是 AlemonJS 全部 API 的清单。

DSH 的每次模型请求只增加两个工具定义，完整能力 schema 按需读取。Node 在原有异步运行上下文中执行，复用 `executeTool` 的参数校验、可用性检查和主动消息限制；群管理继续使用主人校验、全群/白名单与账本。模型不能传入或覆盖可信会话身份。单轮最多执行 16 次业务调用，不允许并行重入；结束或取消后撤销入口。Python 中转仅接受当前回合的独立框架凭证，转发地址必须是经过主服务鉴权提交的固定格式回环地址，不跟随重定向。

验证：`node --test --test-force-exit test/framework-mcp.test.mjs test/group-info.test.mjs test/onebot.test.mjs`；Python 桥测试使用 `python3 -m unittest scripts/test_dsh_bridge.py scripts/test_dsh_worker.py`。安装本地 DSH 虚拟环境并完成构建后，可运行 `node scripts/test_framework_runtime.mjs`，使用真实 DSH Runtime、OS 沙箱、Python 中转与本地模型测试桩验证发现→schema→调用→回执→回答，不消耗在线模型额度或发送 QQ 消息。真实 QQ 账号的接口权限仍需部署环境验证。

### 自动发现其他插件的 Expose 能力

内置 `expose` 模块默认启用，要求宿主 AlemonJS 2.1.118 或更新兼容版本。其他插件与 AgentLink 由同一 AlemonJS 运行实例加载并注册 Expose 后，模型可以使用：

- `expose_discover({})`：分页读取精简目录，每页 30 个动作，可用 `protocol`、`provider` 筛选，`offset` 翻页。优先用 `query` 按动作名或描述搜索（例如 `{query: "资料"}`、`{query: "get_profile"}`），避免为查一项资料遍历整个目录。
- `expose_discover({protocol, provider, action})`：读取该动作原始输入、输出 schema 和读写类型，`callable` 表示桥是否允许尝试。
- `expose_read({protocol, provider, action, argumentsJson})`：执行只读动作。
- `expose_write({protocol, provider, action, argumentsJson})`：执行提供插件公开且声明为 write 的动作，无需 Link 逐动作配置。
- `expose_call({protocol, provider, action, argumentsJson})`：统一调用完整契约接口，包含声明为 unknown 或未标效果的查询。未知效果按可能改变状态的操作处理，保留防重与提供方授权。

目录每次从 `Expose.list()` 读取，后加载的插件和后续新增动作无需逐项修改 AgentLink。执行走 `Expose.call()`，保留框架对输入、输出、授权、超时和取消的检查，默认单次接口时限 15 秒。`argumentsJson` 为按接口 schema 编码的 JSON 值；原始 schema 直接呈现，不转换成 AgentLink 的较小 schema 子集，避免丢失 null、minItems 等约束。缺少完整输入/输出契约的动作可以查看但无法执行。`effect=unknown` 只代表提供方未明确标定效果，不代表权限拒绝；目录和动作详情返回 `executionTool` 与 `mayMutate`，模型应按推荐入口调用。目录声明不代表账号已绑定或已获授权。

工具同步进入既有 DSH MCP 目录，DSH 可先发现 `expose_discover`，再通过 `mcp__framework__call` 查询插件能力与调用。Node 回复模型也可直接使用同一组工具。模型无需接触游戏服务端凭据。

默认接入提供插件公开的完整读写契约。可选配置仅用于限制提供方：

```yaml
alemonjs-agent-link:
  modules:
    settings:
      expose:
        providers: [xiuxian-game] # 可省略；空数组拒绝全部提供方
```

Link 不再要求 `writeActions`；历史同名配置不再参与动作准入。提供方须在 Expose 授权和业务接口中落实玩家身份、操作权限、确认及持久幂等，模型或机器人主人不能替玩家授权。提供方筛选只是允许尝试。桥要求可信框架消息上下文与本轮平台、机器人、发言人及会话匹配，不接受模型传入 callerApp 或替换消息身份。后台自主搭话不开放 Expose 工具；每条待合并消息保存其原始异步上下文，回复所选发言人时恢复对应上下文。身份不匹配仍拒绝调用。主人的机器人管理身份不能代替其他玩家授权。可通过 `modules.disabled: [expose]` 停用整座桥。

同一请求对同一写动作或未知效果动作复用首次回执，主模型与 DSH 的上下文副本也共享该记录；若首次明确返回 INVALID_INPUT 且 outcome=not_started，允许本轮纠正参数；其余已尝试的操作更换参数会拒绝再次执行。记录在模块内保留 30 分钟，最多 1000 条，满时拒绝新的写入。该保护不提供跨进程重启、模块重载或跨请求的持久幂等；这些保证必须由提供插件及游戏服务实现。失败回执保留 `callId`、错误代码与 `outcome`；unknown 表示可能已执行，不自动重试，也不能当作已成功。

修仙插件当前的只读属性接口可按它实际注册的协议和 provider 调用，后续玩法是否开放以 Expose 目录为准。本桥不新增游戏玩法、不代替提供方实现确认流程或离线委托。

验证：`node --test --test-force-exit test/expose-tools.test.mjs`；本地安装 DSH 后可执行 `node scripts/test_framework_runtime.mjs --expose`，通过真实 DSH 沙箱、Python 中转与本地模型测试桩验证 Expose 的发现、schema、调用和回执，并检查提供方接收到原始玩家身份与真实调用插件名。

框架权限按回合隔离：每个带 MCP 的 DSH 工作区回合使用新的运行进程、独立 home 和一次性凭证，结束时撤销框架与模型代理凭证；成功回合先正常关闭 DSH，让原生日志刷盘，再结束进程组并保存快照。后续回合不复用旧 home 的 profile、插件或凭证，只从受保护快照恢复原生 sessions/attachments 数据，并通过 SDK `resume_session` 恢复历史；快照复制忽略符号链接，限制目录深度、文件数量和体积。用户文件位于独立的受限目录，通过 framework MCP 操作，不能直接访问。既有脱离进程组的后台进程也无法凭旧凭证调用后续回合。

此路径锁定 DSH SDK/Runtime 0.2.1rc2，使用其原生恢复能力；管理虚拟环境启动探针会识别旧 SDK 并按锁定依赖更新。真实两回合恢复验证可用 `node scripts/test_framework_runtime.mjs --expose --two-turns`，测试 Python 可通过 `AGENT_LINK_TEST_PYTHON` 指定。轮换运行进程会增加工作区请求的初始化成本，普通 Node 聊天和直接 Expose 查询不受影响。

该版本 DSH 的 DeepSeek 适配器使用 Messages 协议，桥支持其 x-api-key 鉴权并将官方默认地址映射至 `/anthropic/v1/messages`。第三方工作区模型网关需兼容 Messages；Node 普通聊天仍使用 Chat Completions。仅支持 Chat Completions 的网关可继续使用普通聊天，但不能据此声称新版 DSH 工作区兼容。

桥自身的入口类型错误返回 `EFFECT_MISMATCH`（origin=link），并给出正确 `executionTool`；未发现能力返回 `CAPABILITY_NOT_FOUND`，缺少结构化契约返回 `CONTRACT_REQUIRED`。这些错误不冒用提供方的 `FORBIDDEN`。真正的 Expose 拒绝保留 callId、原错误代码及 outcome，并标记 origin=expose；一次拒绝不能被解释为所有查询未开放。用户要求查资料不授权顺便签到、领奖或使用其他无关动作测试权限。注意：`effect=unknown` 是接口效果声明，`error.outcome=unknown` 是某次执行结果不明，两者含义不同。

回归验证可用 `node scripts/test_framework_runtime.mjs --expose --unknown-effect --two-turns`，检查真实 DSH 对未明确效果的查询经推荐入口调用，提供方收到可信身份并返回数据。

工具诊断日志仅记录 requestId、轮次、调用序号、工具名、结果分类、耗时和触顶原因，不记录参数、工具结果正文或思考内容。`tool-limit` 的 reason 区分 round-limit、call-limit、batch-limit；returned 仅表示获得回执，不等于业务成功。

### B 站阅读日记与 dsh-bili-whale 对标

可直接问“你今天看了什么”“看看最近三天的 B 站浏览日记”。只读工具 `bili_diary` 默认查询最近 24 小时，接受 1–168 小时，最多返回 20 条，并标明截断；内部最多检查当前机器人最近 2000 条有效记忆。结果仅限当前会话已保存的 B 站阅读经历，不跨群或私聊。空记录不等于从未浏览；关闭自动记忆或归档时不新增阅读经历，停用记忆模块后日记工具拒绝查询。删除阅读经历后日记同步不再显示。

日记返回记录时间、条目编号和来源资料。模型可据此整理成简短文字，但当前感想不等于当时的历史感受，不能声称看过未读取的画面或已发出评论。主动搭话可先查日记减少重复选题；是否调用及表达质量仍需真实模型验收。

对标 [dsh-bili-whale](https://github.com/Alterssss/dsh-bili-whale) 提交 `8b0009f8ce2ebdc421afcb2e727b19ac18912ec6`，参考其 `tools/commands/diary.mjs` 的叙事、事件和发送账分离思路，本轮独立实现，不复制上游代码。

| 上游方向               | 本项目当前状态                                                            |
| ---------------------- | ------------------------------------------------------------------------- |
| 按作息自主浏览         | 可选每日独立阅读，遵守暂停和安静时段；支持可配置窗口内的稳定分散安排      |
| 读取内容并留下经历     | 已有字幕、简介、评论资料及带来源经历                                      |
| 查看她今天做了什么     | 本轮新增当前会话阅读日记查询                                              |
| 两本叙事日记、偏好校准 | 未实现；不把模型临时感想写成历史事实                                      |
| 画面抽帧与深读         | 可选 `visualRead` 静帧采样与视觉描述链路已接通；真实 B 站及视觉质量待验收 |
| 自动对外分享           | 保持现有授权边界，未增加自动评论或联系他人                                |

主动浏览选题现已增加代码级过滤：`bili_search` 在自主轮次中排除当前会话、当前机器人最近七天已保存阅读经历的 BV；普通用户发起的搜索不受此过滤影响。读取索引使用最多 2000 条有效记忆，支持旧版经历格式，删除经历后不再排除；停用记忆模块时不读取该索引。结果返回实际排除数量，全为空时允许结束本轮，不强迫寻找分享。此机制减少重复选题，不代表已实现发送去重，也不阻止用户明确要求重读。

自主轮次成功阅读并完成生成后，会在同一会话保存一条“阅读感想”：包括视频编号、标题及本轮生成文字（最多 160 个 UTF-16 字符），明确标为主观表达、未证明已发送。它可随阅读日记查询并进入后续近期经历参考，不作为用户事实或视频事实。无读取、沉默、取消、停用自动记忆与归档时不新增；阅读后如发生记忆删除或修订，版本保护拒绝旧感想写回。独立阅读作息见下文；当前不使用两本完整叙事日记。

阅读感想采用独立的 `diary` 类型和来源，阅读事实继续使用 `event`。后续近期经历注入保留来源标记，明确日记不能作为视频事实、用户资料或发送成功证明。日记工具为每条返回 `type=reading/reflection`；旧版带“阅读感想”标签的记录按感想展示。两类条目沿用同一会话隔离、容量限制与删除版本保护。

普通聊天与主动搭话的`recentExperience`也携带`sourceEvidence`。最近24小时最多三条经历先按当前机器人、当前会话筛选，再直接补查每条至多三个来源ID（最多九次本地查询），避免来源较早而被近期100条候选挤掉；补查不会将其他主体原文或较早来源全文注入。范围复用日记解析规则：只有同主体、有效、时间不晚于感想的实际阅读事实可提供依据；缺失/无关联/旧记录保持未知，故事板保留低清预览标记。感想原文保留，不将旧误述改写为新事实。近期经历还提供ISO格式`recordedAt`和阅读条目的`evidenceRole=reading_reference`：阅读只证明取得内容，不证明照教程执行、保存或配置生效；无独立回执不能肯定“做过但不确定成功”，未核实也不补“昨晚”等相对时间。未来时间的经历不注入当前回合，删除来源后的关联感想沿用删除联动，不再进入后续上下文。记忆模块按实际序列化结果限制在16000字符内；超限时先省略低相关的近期备用原话和近期备用事项，关键词命中的原文、匹配对话/事项、人物资料与阅读参考优先保留。按完整条目裁减，不截半段JSON，不拆开感想与sourceEvidence，也不修改原始存储。contextOmissions说明各数组省略条数，省略不代表不存在；需要更多依据时仍使用原有查询工具。此机制不证明模型每次正确理解或纠正旧说法。

### 每日独立阅读

设置 `modules.settings.bili.dailyBrowse: true` 后，后台每分钟检查自动记录的用户会话。当会话不忙且处于非安静时段时，每个会话按所配置时区每日尝试一次独立阅读。它使用已有模型与预算，最多 60 秒，只开放 `bili_diary`、`bili_search`、`bili_watch`；搜索最多一次，独立阅读默认最多读取两条候选。模型选择兴趣主题、查看旧记录、搜索和读取，成功后留下资料与主观日记。这轮没有 QQ 发送通道，不增加未回复次数，不消耗主动消息次数。后续主动搭话可参考这些经历。

每日尝试日期持久化，重启不会重复；暂停或取消订阅后停止调度，收到主人消息会中断当前活动。失败与超时也消耗当天尝试，避免每分钟重试计费。默认关闭；关闭记忆/自动整理/聊天归档时可能无法留下日记，阅读模型调用本身仍计费。真实模型是否选题和调用工具、B 站接口及长期效果尚需实测。已支持下文的窗口作息；已支持多候选资料阅读；视频抽帧和基于具体分享的反馈校准尚未实现。

每日阅读现在另存最近尝试结果，可在 `/主动搭话 状态` 查看：已启动但没有结束记录、已保存阅读经历、已结束但未确认新增记录、失败、取消。阅读凭证来自本次新增的当前机器人阅读事件，不以模型口头声称为准；沉默也可能已经留下阅读事实。进程意外退出保留“尚无结束记录”，不据此声称仍在运行。结果跨重启保存，旧尝试的晚到结果不能覆盖新一天的活动。

配置 `dailyBrowseWindow: [18, 22]` 可把独立阅读限制在 18:00–22:00，结束时间不包含在窗口内。时区沿用主动搭话配置。系统按会话、活动日期和窗口计算一个稳定分散的分钟时刻，到达后在窗口内择空闲时运行；重启不重新抽取，也不会在窗口外补跑。`[22, 2]` 等跨午夜窗口归属于开始那一天，避免午夜前后重复计次。安静时段、暂停和正在进行的聊天仍优先，整个窗口被跳过时不强制补做。未配置窗口时沿用首次空闲检查即尝试的行为。

每日阅读可用 `dailyBrowseTopics` 配置希望多看的主题，用 `dailyBrowseExclude` 配置避雷词（各最多 10 个、每个 1–40 字）。主题作为数据交给选题模型，结合当前人格和已有记忆选择，不保证每次遵循。避雷词在所有自主搜索结果的标题、简介中执行规范化、不区分英文大小写的字面过滤，并返回排除数量；不分析视频画面，不能保证语义层面全部识别。普通手动搜索不受影响。此轮是显式偏好入口，尚未实现根据分享反馈自动校准偏好。

自主搜索过滤已读和避雷后，会按配置主题对候选标题与简介做字面相关性排序：标题命中优先于仅简介命中，多个不同主题可累计，同分保留平台原顺序。规范化相同的主题只计一次。每条候选附 `matchedTopics`，供模型了解排序依据；它不是视频质量评分，也不证明实际内容符合主题。没有主题或没有命中时保留原顺序，仍允许模型跳过全部候选。普通手动搜索保留平台顺序。

主动分享已增加近七天发送去重：仅平台确认送达的初次主动消息进入索引，保存规范化文字的哈希与正文中的 BV 编号，不保存消息原文。同一会话、同一机器人再次生成相同文字，或包含已分享 BV，即使换了说法，也会在进入发送阶段前拒绝发送；普通用户提问回复和后续轻提醒不受此规则影响。索引跨重启保留，过期与清除会话时删除。无 BV 链接、仅语义近似或图片重复尚无法识别；结果不明仍沿用原来的暂停核查规则，不擅自重发。去重不是“值得分享”的质量判断，内容是否有价值仍由生成模型决定。

已分享记录现在也参与选题：主动搭话提示包含近七天确认分享过的 BV；用户私聊的自主搜索会从候选中排除这些编号，并返回 `excludedAlreadyShared` 数量。该索引独立于阅读记忆，所以删除一条阅读记忆不会让它立即变成“从没推荐过”。仅查询当前平台、机器人和用户私聊对应的发送记录，最多读取 200 个编号；普通手动搜索和其他会话不受影响。发送前去重仍保留，防止模型绕过搜索结果重复推荐。

### 明确反馈与选题校准

主人可在自己的私聊直接说“以后多看独立游戏”“以后别看恐怖”“以后不要看恐怖”或“恢复推荐恐怖”。仅完整匹配的独立表达会保存为阅读偏好；引用、第三人称转述、模糊代词和普通情绪回应不自动计入。每个主人私聊最多保留 20 个主题，跨重启持久化，同一主题的新反馈替换旧反馈；“恢复推荐”删除该主题反馈，不覆盖配置文件里的避雷词。

喜欢主题参与每日选题和自主搜索排序，避雷主题参与自主搜索候选过滤；模块上下文也会提供已保存反馈，供正常交流核对。普通手动搜索不受过滤，其他群聊和私聊不能修改或读取这份偏好。该机制是显式反馈校准，未根据沉默、点击或任意一句“喜欢”自动猜测偏好。清除对应会话时一并清理反馈。

### 私聊管理每日阅读

主人可使用 `/主动搭话 阅读 开启`、`/主动搭话 阅读 关闭`，以及 `/主动搭话 阅读 作息 18 22` 管理当前私聊的每日活动。`/主动搭话 阅读 恢复默认` 清除本私聊的开关和窗口覆盖，重新跟随全局配置；`/主动搭话 阅读 偏好` 列出全局配置与本私聊反馈合并后的有效主题和避雷词。状态气泡提供阅读开关与偏好入口。

这些私聊覆盖也适用于管理页开启的爱好自主阅读：全局爱好开关可以停用能力，私聊可单独退出，全局开启不会覆盖该私聊的“阅读关闭”。恢复默认后，未配置爱好调度时跟随B站每日阅读设置，已配置爱好调度时跟随爱好开关；私聊“开启”不越过全局关闭。状态命令使用与工作线程相同的设置规则，并展示当前调度模式的最近结果。

爱好调度同样遵守私聊覆盖或全局配置的阅读窗口，在窗口内按原有稳定分散时点、活动间隔和次数上限执行；跨午夜窗口按起始日期计算作息日，不在午夜重新领取一份额度。窗口外不补跑。间隔、次数和设置跨重启保留，失败或取消仍消耗已领取的尝试。

每轮爱好活动持久化独立runId，完成结果只允许更新该轮的running记录。清除订阅数据会同时删除活动记录，旧轮次的晚到结果不能恢复记录或覆盖新轮次，即便两轮目标时间相同。旧表启动时增加runId字段，保留已有日期、次数和状态；定期清理也删除此前遗留的无订阅活动记录。此处是调度和数据生命周期约束，不代表模型跨日兴趣或真实平台访问已验收。

覆盖配置按平台、机器人和主人隔离，跨重启持久化，不改全局配置文件。开启阅读不自动开启主动搭话订阅，不绕过 B 站模块、主动浏览总开关、暂停和安静时段。修改设置立即中断已有自主任务，不会重置当天阅读次数，也不会立即产生一次模型调用。恢复默认不会清除反馈，反馈通过“恢复推荐主题”逐项移除。

### 字幕时间轴与读取范围

`bili_watch` 的可用字幕保留 `text`，并新增有来源的 `segments`（最多 120 段，每段包含 from/to 秒数与文字）。未提供、非数字、负数或倒序的时间点返回 null，不猜测。正文仍最多 6000 个 Unicode 字符、逐条最多 300 字，处理最多 2000 个原始字幕条目；`truncated` 表示正文片段不完整，`segmentsTruncated` 单独表示时间片段列表不完整，时间列表达到上限不会提前停止正文读取。

模型只能引用实际返回的片段，不把截断字幕当成全片，不把评论当成视频台词。长期阅读经历保留字幕正文截断状态，仍只存有限摘录，不保存完整时间轴。以上是字幕资料理解能力，不证明看过视频画面或听过声音；后续采样静帧和本地ASR片段见下文，仍不等于理解全片。

后台每轮处理到期搭话后，会再为其他会话提供一次独立阅读机会，避免某些会话持续离线使全局阅读停摆。同一轮已处理搭话的会话留到后续调度，不立即接着阅读；全局任务上限、每会话每日限制不变。两个阶段之间重新检查配置与关闭状态，AI 总开关关闭时不开始搭话或阅读，也不消耗阅读日期记录。

### 直接查看阅读日记

`/主动搭话 阅读 日记` 无需调用模型即可查看最近 24 小时的已保存阅读与想法；`/主动搭话 阅读 日记 3` 查看最近 72 小时，支持 1–7 天。只接受主人自己的私聊，查询当前平台、会话和机器人，默认显示最近 5 条及其记录时间、标题和已保存的 BV 编号。时间使用主动搭话时区。

命令检查最多 2000 条当前机器人记忆，到达检查上限会说明可能遗漏更早内容。阅读事实与主观想法分别标明，旧版想法按标签识别，无法解析的资料退回已有文字；空结果不表示从未浏览。记忆模块停用时不查询，删除的条目不会显示。该入口不会触发浏览、改动记忆或消耗模型额度。

阅读日记支持关键词查找：`/主动搭话 阅读 日记 7 鲸鱼` 查询最近七天的相关记录。模型工具 `bili_diary` 同样接受 `query`（最多 80 字）和 `hours`。在已扫描的当前会话记录中，先按时间和关键词筛选，再应用显示上限，避免较早的相关条目被最近的无关记录挤掉。检索对标题、BV 编号和已有文字做规范化、不区分英文大小写的字面匹配；BV、标题命中优先于正文命中，同类保留时间顺序。它不推断语义关系，未命中不代表事情没有发生；最多检查 2000 条机器人记忆的边界仍保留。直接命令不产生模型调用。

`bili_watch.evidence` 统一说明本轮阅读依据：`metadata` 表示只有标题简介等元数据，`subtitles` 表示取得字幕正文，`subtitle_excerpt` 表示字幕正文被截断。`hasAudienceComments`只表示本次取得非空评论文字；评论不会提升视频内容依据等级。`audienceCommentScope`区分returned_subset（本次取得的有限文字）、empty_response（本次未返回可用文字）和unavailable（结果不可用）；后两者不证明原视频零评论或无人感兴趣。`visualObserved`仅在取得实际采样帧及非空视觉描述时为true；`audioObserved`仍为false。本地ASR返回的文字另用`audioTranscribed`和`transcribedRange`标明，不作为直接听觉观察。模型只能据实际返回的资料形成看法，仅元数据时可表达对主题的兴趣或选择沉默，不应评价未读到的情节与视频质量。

长期阅读经历新增 `contentBasis`，在日后回忆时仍能区分来源范围。该字段是取得资料的客观描述，不是内容真伪或质量评分，也不能保证生成模型不会误读；相关测试验证了字段通过实际工具调用到达模型及持久记忆，真实生成质量仍需验收。

每日阅读在多个显式主题间按当地日期轮换建议主题，同一会话同一天建议稳定，避免每次随机选中同一类。建议不强制执行，模型仍可换题或沉默。开始阅读前，代码会从当前机器人最近 2000 条记忆中筛选近七天与建议主题字面相关的主观日记，最多提供三条，携带编号和记录时间；无主题配置时提供少量近期想法作为参考。阅读事实不冒充旧观点，跨会话资料不参与。

感想保存前会清理聊天显示分段标记|||，带该标记的单独[沉默]也不新增日记；保留实际阅读事实。独立阅读提示区分旧疑问、新资料与未解决部分，明确未取得字幕/画面不等于原片没有内容。受控时间的真实模型采样仍出现过“这条视频没有讲到”的越界推断，因此这段提示不是事实正确性保证；不因保存日记成功就认定模型理解或跨日陪伴质量达标。原始反例见采样复盘。

模型可据旧想法中未弄明白的问题寻找新资料，但旧观点不是当前事实，不要求继续赞同。单元与模拟模型链路已验证主题轮换、两天前的相关想法取回以及实际传入模型；真实模型是否自然续读、观点变化是否合理仍需长期验收。

新生成的自主阅读感想关联到那次成功保存的阅读条目，日记工具返回 `sourceReadingId`。写入时校验来源仍在同一会话、属于同一机器人且为有效操作事件；缺失或被删除的来源不能生成新的关联感想。记忆追溯工具会以 `reading_source` / `reading_reflection` 展示明确关联，与仅标签相似的 `possibly_related` 区分。

删除阅读来源会同时删除其关联感想，单独删除感想保留阅读事实。该行为只适用于本轮起带来源关联的日记；旧日记不根据相同 BV 猜测补链，以免把不同阅读轮次错误地关联。来源关联证明感想生成所依据的读取，不证明感想正确或消息已发送。

偏好冲突在选题前统一处理：凡建议主题本身命中有效避雷词，都会从建议主题中移除（例如避开“恐怖”时，“恐怖游戏”不再参与主题轮换）。规则与候选标题/简介的字面过滤一致；全角和英文大小写等价的主题合并，避免重复占用轮换机会。模型上下文保留原始明确反馈，同时标注合并后的 effective 规则，选题以避雷优先的有效规则为准。此机制不扩展为语义理解或内容安全判定。

### 每次模型请求的容量预留

工具循环的每轮请求（含最后一次无工具收尾）都会重新取得会话凭据或模型池槽位，不复用已结算的第一轮池凭证。这样后续轮次也计入RPM、并发和请求成功/失败统计，并按当轮usage结算；池无容量时遵守原排队规则，不绕过为旧Key直连。私人/群绑定凭据仍按当前预算作用域解析。

容量预估使用当轮完整消息（人设、保留历史、记忆、工具回执）及实际工具schema，按文本UTF-8字节数/3向上取整，再加输出预留；图片按每张6000 tokens估算，不把base64编码长度当成文本token。输出预留采用已有`budget.maxOutputTokens`或2048。此数值仅供准入估算，不是精确分词、服务商用量或费用上限；实际usage与既有会话预算仍分别结算。尚未提供服务商分词器或动态视觉计费精算。

### 独立阅读的模型轮次

独立阅读不沿用普通任务的静默续跑额度。按本次有效最大读取尝试数N，最多进行N+3轮模型请求（查日记、搜索、最多N次读取及最终感想）；管理员设置的`maxToolRounds`若更小仍优先，`maxToolContinuations`对这次阅读固定为0。工具批次和实际搜索/读取次数限制继续生效，不必凑满N次。

触顶后最多再请求一次不带工具的收尾，只基于已有阅读证据形成感想或输出`[沉默]`；收尾失败默认沉默，不将普通任务的“已有几份回执、请缩小任务”等提示存为阅读感想。取消与预算失败仍遵守既有规则。按默认N=2，最多5轮加1次收尾，替代原默认最多3段×8轮加1次收尾；这是工具循环层面的逻辑请求上限，端点故障重试仍受原预算和时限约束，不代表实际HTTP尝试数或费用上限。正常提前结束的阅读不会额外请求，也未因此证明每轮token用量下降。普通聊天续跑保持原规则。

### 多候选独立阅读

`dailyBrowseMaxReads`（默认 2，范围 1–3）限制每轮独立阅读全部读取尝试，失败也计入；普通主动搭话仍最多读取一次。搜索最多一次，可比较不同候选，也可在取得全幅采样概览后，将剩余次数用于同BV的一次视觉细读。默认两次可以读两个候选，或一个视频的概览和细节；不是两条视频再额外续读。整体仍限60秒，没有消息发送通道，详见文末有限续读条件。

每条实际读取资料独立保存为阅读事实，完成后生成一条综合主观日记，关联本轮全部已保存来源；不把综合感想分别伪装成对每条视频的独立评价。日记保留候选列表和多来源编号，可按任一候选标题或 BV 查找。删除任一来源会删除依赖它的综合感想，其他阅读事实保留。模拟模型链路已验证两条资料成功、第三条被限制以及多来源日记；真实比较质量与成本仍待实测。

## B 站视频静帧读取（2026-10-30更新）

设置 `modules.settings.bili.visualRead: true` 后，`bili_watch` 除原有字幕与评论外，会尝试取得单段 MP4，用 PATH 中的 `ffmpeg` 先粗略探测画面变化。默认按九段时间各选一处完整静帧，优先取靠近各段中点的变化点并向后偏移最多0.1秒；没有候选或探测失败时回退该段中点。指定 `visualAt` 或问题时段时仍只取1–3个指定位置，不额外追加九点概览。优先使用独立 `media.vision`；未配置时可复用已启用、明确声明 `vision` 能力的模型池端点。探测每秒两帧、最长边160、固定阈值0.25。默认关闭；需要可用视觉端点并承担费用。取样位置是解码目标时间，不能解释为动作边界或逐帧精确标注。

只接受播放接口返回的 HTTPS `bilivideo.com` 域及其子域；下载复用公网 DNS 校验和固定地址连接，不发送 B 站 Cookie，拒绝重定向。下载上限是 `media.maxBytes` 与 32 MiB 的较小值。只支持单段 MP4，不拼接多段，不读取 DASH 或播放列表。默认请求低清播放地址；指定局部框时改为请求qn=64，以减少先缩小整帧造成的细节损失。服务可能返回更低画质，两者都受相同32MiB/单段MP4限制，不保证视频可读或文字清晰。

ffmpeg 只读取本地临时文件，使用参数数组执行、限制协议/线程/时间；变化探测最长5秒、诊断输出最多128 KiB，每帧提取最长10秒，总画面下载与处理最长45秒。取消探测会终止整轮，不继续兜底解码。每处完整静帧最长边640。超过三处时，每三帧按时间自上到下拼图，最多三图、一次视觉请求；返回region=frame_grid，positions逐行对应时间，黑线只作分隔。单图最多2MiB；复杂画面拼图过大时保留所有行，将单帧最长边降至480，仍超限则失败。PNG拼图去除不必要的透明通道以遵守字节上限。解码成功但没有输出帧的位置不计入观察。结束、失败或取消后清理本轮临时文件。1–3处独立完整静帧描述最多输出600 tokens；完整帧拼图、字幕带拼图最多1200 tokens。更多采样增加解码、像素和输出预算，三张图不代表费用不变。结构有效的描述最多保留2000字符，不保留原视频或帧到长期记忆。若服务明确返回 `finish_reason: length`，本次视觉描述失败，不返回截断文本作为成功结果，也不自动增加预算重试；服务没有返回结束标记不等于已证明输出完整。

变化探测是粗粒度图像差异，不是语义切镜检测。低亮度差异、短促画面和快节奏转场可能漏检，长视频也可能因探测超时回退；它不证明完整扫描、覆盖所有场景或理解动作过程。

返回 `visual.status` 为 `disabled`、`unconfigured`、`unavailable` 或 `available`；失败阶段通过 `failedAt` 标明 `playback/download/decode/vision`，不回传签名下载地址、Cookie 或服务错误正文。缺失 ffmpeg 属于 decode 阶段失败。字幕或评论仍可单独成功返回，用户取消则终止整轮。

只有实际取得采样帧并收到非空视觉描述时，`evidence.visualObserved` 才为 true，同时给出 `sampledTimestamps`。没有字幕但有视觉结果时，依据为 `sampled_frames`；有字幕仍保留字幕依据，另外标明画面采样。视觉描述是模型对有限静帧的解释，可能出错，不能证明帧间情节、音频、完整观看或视频质量。读取经历保存有限视觉摘录和时间点，并明确未听音频。

### 硬字幕带取样

`bili_watch` 可传 `visualFocus: "subtitles"`，用于画面内烧录字幕；省略或传 `frames` 仍是原有完整静帧方式。两种方式均需管理员开启 `visualRead` 并配置独立视觉服务或模型池视觉端点，模型不能借此参数自行开启画面读取。

字幕带方式在时长均匀分布的最多12个位置提取底部25%画面，每条宽高上限为1280×256像素；每四条按时间从上到下拼图，黑色细线分隔，最终最多三图、一次视觉请求。此方式替代完整静帧提取，不额外下载一次视频或同时执行变化探测。底部裁剪可保留更多横向文字像素，但不检测字幕实际位置；上方字幕、快速闪现文字和未采样台词可能全部遗漏，不能称作完整转写。

每个位置解码最长10秒，仍共享整轮45秒超时、单段MP4和下载大小限制。解码成功却未生成图像的目标不计入采样位置；整个解码失败或取消不返回半成品。每张拼图最多2 MiB，最大尺寸1280×1030；相较普通静帧，像素和文字内容更多，模型费用可能增加，不能按请求次数不变推断费用不变。

成功结果的 `visual.region` 与 `evidence.visualRegion` 为 `bottom_band`，`sampledTimestamps` 仅列成功生成图像的解码目标时间，最多12个，不是精确的帧PTS；低帧率时实际画面可能略晚于目标。各拼图的行序和目标时间交给视觉服务。视觉提示限定只读看清的字，不凭裁剪外内容推断场景，不将采样文字拼为完整台词或音频。阅读记忆同步保留裁剪范围，`audioObserved` 仍为false；官方字幕状态与截断字段不被视觉结果改写。

### 按时间点回看

`bili_watch`新增可选`visualAt`，传1–3个秒数（例如`visualAt: [148]`）定位完整静帧或硬字幕带。数组必须是有限数值、非负、至多86400秒，并严格小于当前第1分P时长；服务端排序、去重，不接收空数组。普通帧有明确位置时跳过场景吸附；硬字幕模式只裁这些位置，不再取默认12处。

`visual.requestedTimestamps`回显规范化请求位置，`visual.timestamps`和`evidence.sampledTimestamps`仍表示实际提供给视觉模型的采样位置。故事板只能选最邻近可用索引，可能少于请求数量；返回索引不能冒充请求的精确时刻。视频解码时间本身仍为seek目标而非逐帧精确标注，不证明帧间过程。超出当前分P时长时，视觉阶段返回selection失败及说明，不下载视频或悄悄改读其他位置；可用元数据、字幕和评论仍独立返回。

参数不能开启关闭中的visualRead，也不增加工具/主动阅读额度。普通主动搭话仍每轮读取一次；独立阅读可在原总次数内进行文末限定的一次同BV视觉细读。普通请求需要定位新片段时可回读，仍计入原有工具与费用预算。同回合不同指定位置/读取方式的事实分别保存，相同规范化位置不重复入库；默认frames且未指定位置沿用原阅读记录ID规则。日记与记忆依据仍取实际采样范围，不能把requestedTimestamps当作已看到的证据。

普通用户本轮明确引用单个视频，并以阿拉伯数字指定“最后10秒”“开头10秒”或“10秒到20秒”等单一范围时，首次读取会直接选择该区间10%、50%、90%的最多三个位置；模型显式传入的`visualAt`优先。只匹配本轮文本中的同一BV/av/b23标识，不从旧记忆或外部视频内容推断需求。多视频、多个时间条件、否定/假设、模糊或不支持的表达沿用原采样；自主活动不使用该规则。它是有限语法解析，不是任意自然语言时间定位。

相对开头/结尾范围长于分P时长时收窄到当前分P；绝对区间超出分P或缺少有效时长则返回selection失败，不读取其他时间。`visual.samplingReason=question_window`和`requestedWindow`说明选点缘由及有效区间，`requestedTimestamps`保留请求位置；实际索引仍以`timestamps`为准，故事板最近索引甚至可能落在区间之外，不能据此宣布整个区间已覆盖。该选择替代默认采样，不追加工具调用或视觉请求，沿用原有开关、时间、大小和费用限制；硬字幕带也只取这些明确位置。

### 低清预览故事板备用读取

普通 `bili_watch` 静帧模式在播放地址、MP4下载或解码失败时，会尝试B站`/x/player/videoshot`返回的预览故事板；依然需要`visualRead: true`和可用视觉服务。这条备用路径用已有sharp裁图，不依赖ffmpeg。读取前先检查本机ffmpeg：缺失时普通静帧直接尝试故事板，不请求播放地址、不下载MP4；可用时仍优先解码视频，失败后才尝试预览图。检查只执行有界的`ffmpeg -version`，合并并发探测并缓存一分钟；管理页手动环境检查强制刷新，安装工具后可立即重查。两条路径共用45秒视觉阶段时限。硬字幕带读取在解码器缺失时不下载MP4，也不以低清预览替代；原字幕接口和评论读取继续独立返回。

只取默认第1分P，优先用其时长验证索引。JSON时间索引缺失时可读取最多40KB的大端uint16索引；没有有效索引就失败，不凭帧数猜时间。兼容秒与毫秒索引的时长比较是启发式判断，不能把预览索引当作原视频精确帧时间。默认按故事板覆盖范围选最多九处、同时间去重；指定位置仍最多三处。最多下载九张源拼图，每张最多4MiB并受media.maxBytes约束，源图与时间索引合计最多32MiB，每张最多32Mi像素；同一源图只下载一次。裁出的静帧再按上述规则拼成最多三张视觉输入图。仅HTTPS hdslb.com及其子域，沿用公开地址DNS校验、地址固定和拒绝跳转；下载不携带B站Cookie。

有效裁图且视觉模型实际返回非空描述后，`visual.source`与`evidence.visualSource`标为`storyboard`，阅读事实、日记检索及续读也保留该来源。它是低清预览，不是完整画面、精确抽帧或字幕原文；不能据此转写整片、推断未采样部分或声称听过音频。硬字幕带模式不使用此备用路径，视觉模型失败也不额外换预览图重试。预览接口缺失、尺寸/索引异常、取消、无视觉服务等情况不升级观察证据。

### 复用模型池视觉端点

只有未配置 `media.vision` 时才尝试模型池；独立服务请求失败不会悄悄切换付费端点。必须有启用且声明 `vision` 的端点；普通聊天端点、旧单Key和会话绑定Key不充当备用视觉端点。配置预检不占用模型槽位，下载及解码成功后才选择端点，遵守模型池能力、健康、并发与令牌窗口限制。

池内请求使用机器人凭据并经过原有会话预算入口，沿用预算输出上限（可能进一步低于600/1200 tokens）和用量结算；不会因选用视觉端点绕过用户/全局额度。真实usage同时报告给模型池。内部 `robotKey` 选项防止通用预算入口改用个人/群绑定聊天Key；此选项不改变额度检查。成功、HTTP失败、正文无效、截断或取消后均释放本次池占用。每次视觉读取只尝试一个端点，不自动重试；没有可用容量时返回视觉阶段失败，字幕与评论可单独返回。

管理页环境检查会区分独立服务与模型池配置，但不预占容量或探测服务；“已配置”不保证端点当前健康或额度充足。未配置可用视觉来源时不下载视频；更改模型池不会自动开启默认关闭的 `visualRead`。

## 群聊按人续接与结束（2026-10-29）

群聊短时问答现在按平台和发言人分别保留，群内最多 100 个、每条两分钟；仅实际确认送达且有回复文字时保存。甲乙交替与肥鱼说话时，各自的后续短句取得自己的上一轮问答，不会因肥鱼回复另一人而丢失。模型用 `<reply:mN>` 选择较早的消息时，实际引用消息编号会从发送结果传回协调器，续接保存到实际接话对象；不能默认归给批次最后发言者。

“别回了”“不用回复”等原有停止语，以及独立整句“不聊了”“先聊到这”“先聊到这里”“下次再聊”，结束该发言人的短时续接与待回复片段。只识别当前完整消息，不把引号中的故事、提问或其他人转述当成控制指令。明确 @ 别人或引用其他消息会清掉该人的旧续接邀请；不影响其他人的问答。

会话上下文失效、重置或取消时清理对应续接状态。在生成回复期间收到结束/取消后，即使此前回复稍晚确认送达，也不能重新激活已经结束的续接。该约束只阻止旧续接状态恢复，不等于撤回已经发送的消息，也不承诺能停止所有已在进行中的平台请求。

这是收到消息后的短时续接机制，不是模型自行长轮询群历史、安排唤醒或给指定群友定时催回复。尚未实现竞品二代仿真的完整自主读/等/醒工具协议；已有频率、身份和防循环限制继续适用。

## 模型选择短时群聊等待（2026-10-29）

内置 `conversation` 模块提供 `set_group_wait`，只在经过群聊协调器的当前回合开放；私聊、后台自主阅读和没有真实协调器回调的回合不开放。可通过 `modules.disabled: [conversation]` 停用；之后收到群消息时清除旧等待。

模型可调用 `{ "action": "wait", "seconds": 120, "speakerId": "本批发言人编号", "keyword": "找到了" }`。默认等待当前发言人，期限 15–300 秒；只能选择当前批次或本回合收件箱实际读取、同一平台的发言人，不能猜其他账号。关键词可省略，否则最多 40 字、单行，按 NFKC 和英文大小写规范化后字面包含匹配。指定人和关键词同时存在时必须同时满足。`status` 查询本回合已设置的等待，`cancel` 取消。

群聊协调器的批次、消息去重、近期续接和等待按平台、机器人、群号组成的范围隔离，每个范围同时一份等待，新设置替换旧设置。机器人编号来自当前平台事件或规范化messageContext，未知编号单独归入该平台/群的未知范围，不从昵称推断。它是事件驱动的参与状态，不占用模型请求槽，也不轮询 QQ 历史：无关普通新消息只保留在有限近期上下文里，不触发分类模型或聊天模型。明确呼唤、@ 或命令可以打断本范围等待；原有停止语、取消和重置清理对应状态，并拒绝已失效回合迟到的设置请求。

平台消息编辑/撤回及当前取消入口携带可信平台/机器人范围，清理该范围的协调器状态。内部管理API省略范围时保留按群号清理所有匹配状态的兼容行为；现有底层会话重置、执行队列和会话存储仍有按群号管理的入口，本改动不构成整套会话系统的端到端隔离验收。定时批次只刷新自身范围，获取参与策略时仍使用原始群号和平台，不把内部组合键当作平台群号。

条件命中只提供新的接续线索，不升级成直接呼唤或额外授权。静默时段、关闭自主参与、限额和防循环仍然适用；按正常规则及模型判断决定是否回答，允许沉默。到期后恢复普通参与，不自动发超时消息、不催人、不承诺稍后联系。生产协调器已接通下述短时恢复；不表示已经实现竞品的自主历史轮询或无人发言时的定时唤醒。

记录开启时，有效等待保存到`workspaceRoot`父目录的`group-waits.sqlite`，文件权限600。工作目录/DSH目录组合、平台、机器人和群号分别隔离；最多1000份有效等待，不满额时才接受新范围。恢复的仍是原始15–300秒期限，不因重启延长。下次该范围收到新消息时读取，不主动扫描群或请求模型；正常关闭保留未到期等待，显式取消/重置删除，包括重启后尚未收到新消息的范围。模块停用后，下次该范围消息会清理等待。

停用`chat-history`时只使用内存等待，下次处理对应范围时删除其持久记录。处理记录开关或工作目录变更后的消息或回调时，旧回合失效；已经失效的回调不会因切回而复活；重新进入原工作目录只能按原期限恢复仍有效的记录。过期、时钟回拨、损坏或超出字段/容量边界的数据不恢复，额外未知字段不作为条件；过期记录在后续存储访问时清理，停机期间不运行删除定时器。文件包含等待对象编号、拥有者键和短关键词，不是聊天正文归档；范围索引和拥有者索引用哈希。

持久化失败不回执新等待设置成功；已有有效等待不被失败的新设置覆盖。取消/重置遇到磁盘清理失败时，仍结束本进程等待并记录故障，不能承诺重启后已删除；模型工具的cancel会明确返回ok=false及本地已取消的状态。该存储用于单个活动协调器恢复，不提供跨进程回复锁；底层会话队列、全部历史状态和真实平台重启仍需分别验收。

模型应在刚提出具体问题、确实需要对方补充时使用，不要求每轮设置。工具回执只证明等待状态已设置，不能证明已收到对方回答或已发出消息；等待开始时间可能早于本轮文字的发送确认。

## 群消息收件箱与读取进度（2026-10-29）

`conversation` 模块增加 `read_group_inbox` 和 `ack_group_inbox`，仅向有真实群聊协调器回调、有效平台/群/机器人身份的当前回合开放。私聊、后台阅读不开放；停用 `chat-history` 或 `conversation` 会关闭工具入口。范围由当前回合决定，参数不能选择其他会话或机器人。

`read_group_inbox` 顺序读取本群本地归档近 15 分钟、尚未由此工具确认的用户消息，每批 1–20 条、每条正文最多 600 字，带归档序号、发言人、接收时间、平台消息编号是否已知、回复关系及截断标记。不包含机器人的自述；附件仍只是归档占位，不能声称看过附件。更早的资料继续使用既有 `search_chat_history` / `read_chat_episode` 查询。

每批返回不透明的 `receipt`。翻页时将其传给 `previousReceipt`，沿用同一快照上界，后到消息不会混进该批。读取本身不推进已读位置；确认阅读时调用 `ack_group_inbox({receipt})`。只接受当前范围、当前机器人实际生成且 15 分钟内有效的回执，不接受模型猜测的序号。进度只增不减，旧回执重复确认不会回退，确认不会越过该回执的快照范围。

SQLite 按平台、会话和机器人保存读取进度，重启后保留。每个机器人/会话最多保留 100 份近期读取回执，过期或被淘汰的回执需要重新读取；清理历史同时清理进度与回执，撤回/删除单条来源会使该会话旧回执失效。来源删除与回执清理在同一事务中执行。

“尚未确认读取”不等于 QQ 平台未读，也不证明模型此前未在提示里见过这些消息；工具不修改平台已读、不自行回复、不执行历史指令。空结果不表示从未发生。它是接续背景的窄入口，当前仍没有进程外历史长轮询或无人发言时的自主唤醒。

## 明确保存回执与请求回显处理（2026-10-30）

`remember_private_fact` 先识别当前用户的明确保存请求，忽略引用/代码块中的指令，拒绝否定、假设、词义讨论和单纯询问是否记住。支持常见中文请求、句末“帮我记住”及英文 remember/save memory 请求；这是受限的请求识别，不是任意自然语言意图的完整判定。明确手动 `/记住` 命令的行为不变。

工具返回 `persistence.state`：`saved` 表示本次已写入；`already_saved` 表示相同正文原本已存在、本次未新增；`not_saved` 表示本次未保存。成功状态同时返回实际保存列表中匹配条目的 `recordId`，不凭模型口头说法生成成功编号；原有 `ok/status/notes` 字段保留。保留天数反映当前策略，不承诺永久保存。容量满和意图拒绝均明确未保存；异常或取消不伪造成成功回执。

明确保存列表的空结果只表示当前列表为空，不证明从未保存或说过，也不等于聊天归档/其他记忆机制不存在。普通补充主题只改变当前已知信息，不把“我记下了”当作普通应声，也不每轮追问是否保存。

本轮实际模型在停用记忆工具时曾只返回请求回显，即使增大输出预算仍以 stop 结束。现在对“私聊明确保存请求 + 本轮没有明确保存工具”缓冲最终文字；只有回复确实是原请求的回显（可带 user/human/用户 前缀）时，替换为未确认保存的说明和手动入口。实际结果与非回显回复不改写，其他聊天继续使用原有流式路径；此检查不是任意模型谎称成功或输出内部草稿的通用检测器。

## 收件箱读取与等待对象衔接（2026-10-30）

`read_group_inbox` 实际返回的发言人，现在会由服务端登记到当前群聊回合的已知对象中。模型可以先读收件箱，再用 `set_group_wait` 等待其中的人，即使该人不在本次触发批次中。只登记实际返回的用户消息发言人，不解析正文里自称的姓名或账号；每回合最多100个已知对象，不扩展到其他群或平台。

登记通过当前回合回调完成，不增加模型可填写的“登记人物”参数。未读取的人仍不能被设为等待目标，旧回合取消/重置后的等待票据仍然失效。等待条件命中只进入既有参与判断，不保证回复；此项未增加远端历史轮询或无人发言的定时唤醒。

## 等待候选列表（2026-10-30）

`set_group_wait` 增加可选 `speakerIds`，可等待1–5名已知发言人中的任意一人；与 `speakerId` 互斥。不提供目标时仍默认当前发言人。目标仍只来自本批消息或本回合收件箱实际读取的发言人，不能通过名单扩大范围。

关键词存在时，必须同时满足“发言人在候选名单中”和“正文包含关键词”；第一次命中即消费等待，不会对后续每位候选重复触发。重复编号会去重，非法名单返回失败并保留原有有效等待；返回的名单副本不能改变内部目标。单人回执继续返回 `speakerId`，同时提供 `speakerIds`，多人回执只使用列表。

静默、参与开关、取消、期限和后续回复判断不变。本轮仅扩展消息条件，不引入到期主动发言。

## 等待命中与打断的解释依据（2026-10-30）

群聊等待在条件命中或被当前直接对话打断时，将该次实际条件快照传入对应回复回合，区分 `matched` 与 `interrupted`。快照只包含已知发言人编号、关键词和到期时间，不包含内部票据；数组副本不会改变有效等待。过期等待不被标记为本次打断，后续新回合也不会继续带上旧事件。

事件只供用户询问“刚才为什么没接话”时据实解释，不要求模型主动播报协议，不把等待编成忙碌或网络故障。条件文字仍是引用数据，不授予操作权限；命中不证明相关任务完成，打断后原等待已结束。此项提供可靠上下文，并不保证真实模型每次解释都恰当。

等待解释还会直接核对候选名单是否包含当前发言人，避免将“等其他群友”说成“等你”。当前未提供触发记录时，不补造忙碌、网络故障等原因。这些约束来自真实模型探查发现的对象混淆和故障借口；模型仍可能添加不实的时间语气，具体反例见[采样复盘](companion-sampling-review.md)。

## 无字幕视频的本地ASR片段（2026-10-30）

`bili_watch`支持可选`audioRead`，默认关闭。开启且没有可用字幕正文时，尝试用PATH中的ffmpeg提取单个最多60秒音轨片段，发送到已配置的本地`media.asr`。已有字幕正文（包括已标注截断的节选）时不追加转写。此路径仅接受`localhost`、`127.0.0.1`或`[::1]`的服务地址，使用`audio/transcriptions` multipart接口；云端ASR未接入视频路径及对应计费。

合并到已有配置，服务需自行部署并接受这些接口字段；模型ID按本地服务填写：

```yaml
alemonjs-agent-link:
  modules:
    settings:
      bili:
        audioRead: true
  media:
    asr:
      baseUrl: 'http://127.0.0.1:8000/v1'
      apiKey: ''
      model: 'YOUR_LOCAL_ASR_MODEL'
```

默认取第1分P开头最多60秒。本轮明确单视频数字时间范围能解析时，转写该范围：结尾请求超过60秒则只取该范围最后60秒，开头/绝对区间请求则只取前60秒；不能把有限片段说成覆盖整个所问范围。范围越界或缺少有效时长不静默转写别处。模型的`visualAt`仅控制视觉采样，转写目标依据本轮已解析的问题范围或默认开头；重复调用不能绕过主动阅读次数限制；独立阅读的同BV视觉细读会跳过ASR，不重复转写这段音频。

抽帧与转写在同一次watch中共用一个MP4下载和45秒媒体阶段期限；不拼接DASH或多段视频。下载仍受media.maxBytes及原视频硬上限约束。先检查本地ASR配置与解码器，不满足时不为音频下载MP4。ffmpeg只读取临时目录中的本地mov/MP4，禁用网络协议，单次最长10秒，生成16kHz单声道16位PCM，音频总大小最多2,000,000字节；成功、失败与取消均清理临时文件。

`audio.status`区分disabled、unconfigured、not_needed、unavailable、available；失败可附failedAt阶段，不把空文本或错误计作成功。成功文字最多4000个Unicode字符，截断用`audio.truncated`标明。`startSeconds/endSeconds`是解码seek起点加实际PCM时长，不是原音轨精确PTS或逐字时间轴；短于请求的音轨只记录实际输出长度。它是服务识别文字，可能误识别，不证明理解语气、音色、未转写片段或全片。

`evidence.basis=audio_excerpt`、`audioTranscribed=true`和`transcribedRange`表示这项文字依据；`audioObserved`继续为false，其他视觉/官方字幕状态独立保留。阅读事实、日记关联来源和后续记忆上下文保留转写范围，字段未知或范围无效不推断。环境检查增加转写配置状态，不连接服务、不上传音频，也不把地址或密钥返回前端。

初次验证使用真实ffmpeg及HTTP夹具；后续又以真实faster-whisper tiny完成两条固定中英文合成语音的识别。英文关键词检查通过但并非逐字无误，中文出现“雨伞”识别成“魚散”的反例，不能据此承诺一般识别质量。机器人运行环境仍需具备ffmpeg及本地ASR服务；生产配置和服务尚未在本轮启用，详见下方可选服务和采样复盘。

### 可选的有界本地ASR服务

仓库提供`scripts/local_asr_server.py`及可选依赖`scripts/local-asr-requirements.txt`。服务只监听127.0.0.1，模型从显式指定的完整本地CTranslate2目录加载，不自动下载，不接受HTTP请求选择任意文件或模型目录。目录应包含model.bin、config.json、tokenizer.json及对应词表。本轮用Python3.12、faster-whisper 1.2.1、固定版本tiny模型验证；tiny仅作为小型测试模型，中文错词样本已保留，不作为中文质量推荐。

在项目根目录安装独立环境，再指定自己的本地模型目录启动：

```sh
python3.12 -m venv "$HOME/.local/share/agent-link-asr/venv"
"$HOME/.local/share/agent-link-asr/venv/bin/python" -m pip install -r scripts/local-asr-requirements.txt
"$HOME/.local/share/agent-link-asr/venv/bin/python" scripts/local_asr_server.py \
  --model-path /absolute/path/to/ct2-model \
  --model-id whisper-local \
  --port 8000
```

将media.asr设为baseUrl `http://127.0.0.1:8000/v1`、apiKey空字符串、model `whisper-local`。启动输出ready、监听端口及模型别名；配置可解析或启动成功不代表识别质量通过。按Ctrl+C结束；仓库不会注册系统服务或自动启用audioRead。

这个适配器仅接受视频路径产生的16kHz、单声道、PCM16 WAV，最多60秒/2,000,000字节，HTTP请求最多2,100,000字节；MP3/Ogg等不是它支持的输入格式。模型数组输入直接来自已验证PCM，避免重复走PyAV文件解码。单请求串行处理、默认2个CPU线程；拒绝浏览器Origin、分块上传、未知/重复字段和不匹配的模型别名，不记录音频、转写或凭据。精确全零PCM返回空文本且不调用识别；这不是一般静音/VAD检测。客户端断开不保证已经开始的本地原生推理立即结束，片段长度和线程限制仍然适用。

8项标准库Python回归已纳入npm test，不安装模型依赖也可运行。实际模型验证记录保留初次解码兼容错误、PCM输入修正、可选脚本同条件复测与原始错词；未修改参考句或关键词规则去提高分数。完整环境版本和模型文件哈希见本机.data/agent-link/validation/real-local-asr-product-20261030/，核验见real-local-asr-assessment-20261030.json。

## 阅读来源摘录与评论返回范围（2026-10-30）

阅读事实保存audienceCommentScope，后续日记来源和聊天参考沿用该范围，不从被裁短的commentExcerpt反推是否有人评论。旧记录没有这项范围时保持未知；状态与范围矛盾的值不作为评论依据。它描述本次接口结果，不是整条视频的评论总数或观众兴趣判断。

当前聊天关联旧日记时，会同时提供sourceEvidence中的有限excerpts：ASR文字、字幕摘录、视觉模型描述或观众评论，分别标注kind。只取当前会话、同主体、有效且时间不晚于感想的来源；缺失、删除、其他主体或未来来源不带摘录。每项最多120个Unicode字符，每条来源总共最多200个，来源原有截取边界仍然适用；这些引用资料不能授予工具权限，不代表完整内容。

readingSupport从来源范围概括取得的资料，以及这些资料未能证明的直接听觉、全片观看、照教程操作、零评论或整体观众兴趣。它是来源派生说明，不是新的独立执行回执，也不证明现实中从未发生过某件事。原有错误感想仍保留，不自动改写成正确事实。来源、摘录和感想作为同一条近期参考记录进入上下文容量装配，超预算整条省略，不单独留下错误感想。

这项改动修复了“有来源范围却没有关联原文”的信息缺口，未保证模型总能遵守。实际三题复测仍出现虚构后续知情过程、ASR与字幕混淆等反例，完整输出见采样复盘；不能把字段或单元测试通过当作聊天质量通过。

### 群聊定时自主唤醒（可选）

`conversation` 增加 `set_group_wake`，与 `set_group_wait` 的消息条件等待分开。它可预约60–3600秒后一次重新判断（省略秒数为120秒），也可查询或取消；schedule必须提供1–160字单行reason。每个工作目录/DSH目录、平台、机器人和群组合最多保留一个预约，新预约替换旧预约。普通群友参与的正常回合也可使用，由实际协调器批次决定范围；工具参数不能改收件群。私聊、后台自主回合、已失效或已有新消息的旧批次不开放，不能由自主唤醒链式预约。

默认关闭，下面是配置格式，身份均为占位值：

```yaml
alemonjs-agent-link:
  modules:
    settings:
      conversation:
        wakeEnabled: true
        wakeGroups:
          - platform: 'onebot'
            botId: '机器人账号'
            channelId: '允许自主唤醒的群号'
```

每个目标必须同时匹配platform、botId、channelId；最多1000个配置目标。启用后模块在插件启动加载，不需等到下一条群消息才启动后台计时，每15秒检查一次。预约持久化至workspaceRoot同级的私有group-wakes.sqlite；正常关闭保留未来预约的原期限，晚于原定时间超过60秒则过期，不批量补发。领取后不重试；重启不会重跑已经领取的任务，执行中断后标为interrupted。说明是引用资料，不是新的用户授权或动作完成证据。最多240字的自然接话可以沉默，不点名催回复，也不承诺定时提醒一定送达。

执行前与每次发送前重新检查AI、记录与模块开关、目标名单、当前群聊天权限、在线状态、静默时段和自主参与设置；沿用普通群小时上限、冷却及突发限制，另加每个范围每小时最多4次尝试、同一数据库所有范围每小时合计60次尝试。失败、离线、沉默也不返还尝试数；领取有SQLite事务，两个进程争抢同一任务只允许一个领取。只保证任务不重复执行，不承诺外部平台恰好送达一次。

协调器实际接收有效新群消息后取消本群预约，重复或被防循环拦截的消息不触发该动作。取消/重置/清理近期上下文会清理对应范围的持久任务；旧消息批次即使稍后调用工具也不能重建预约。启动或配置热更新会撤销停用AI、停用conversation/chat-history、关闭wakeEnabled或移出目标名单的任务；重新开启不复活已清掉的预约。生成期间撤销会在发送检查时阻止后续发送，已经进入平台发送的请求无法撤回。停止worker会中止其等待及生成信号；底层不理会取消的网络操作不保证立即终止。

存储最多1000个群范围（包含近期终态），到期超过24小时的任务说明及状态在下次访问时清理，离线时不保证定时删除；尝试计数按小时清理。时钟回拨会丢弃未来创建的预约，不返还已记录的尝试配额。该任务范围不等于整个聊天系统已完成跨平台/机器人会话隔离：当前排队、取消和忙碌查询已增加目录/平台/机器人范围；会话策略、世代及历史仍有原群channelId路径，尚未完成整体改造；正常消息去重已追加相同身份范围。

### 队列身份与重置边界
