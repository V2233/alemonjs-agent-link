# 长期记忆

长期记忆按配置目录组合（`workspaceRoot`、`dshHomeRoot`）、平台、机器人和当前会话隔离。私聊明确资料、SQLite 记忆、阅读经历及聊天归档沿用这个范围。未知机器人编号归入独立的空编号范围，不借用已知机器人的记录。

同一机器人在同一群内仍共享群资料，并保留发言人 ID；不会按每个人拆成互相不可见的群记忆。资料带时间、来源与置信度，均为模型参考，不能授予工具权限。

升级时，旧版未记录机器人或配置目录归属的资料保留原记录，不自动导入新身份；升级后这些记忆可能暂时不可见，需要核对归属后单独迁移。本次没有自动迁移或部署。底层策略、世代和部分管理重置仍按原会话号处理，不能据此宣称整个会话系统已完全隔离。

## 使用

| 命令                                   | 作用                                                         |
| -------------------------------------- | ------------------------------------------------------------ |
| `/记住 内容`                           | 私聊明确保存资料；也支持在对话中明确说“记住……”后调用保存工具 |
| `/记忆`                                | 查看自己私聊的近期有效条目，包含明确保存和自动整理的资料     |
| `/群记忆`                              | 查看当前会话近期有效资料及所属人物                           |
| `/记忆检索 关键词`                     | 检索当前会话长期资料                                         |
| `/记忆来源 编号`                       | 核对来源原文、时间、人物及取代的旧条目                       |
| `/过时记忆`                            | 查看已经被取代的旧版本                                       |
| `/恢复记忆 编号`                       | 恢复旧版本，将同一变更链中的当前版本标记过时，并开始新话题   |
| `/忘记 编号`、`/忘记全部`              | 删除当前私聊的指定或全部长期记忆，并开始新话题               |
| `/忘记群记忆 编号`、`/忘记群记忆 全部` | 删除当前群的指定或全部长期记忆，并开始新话题                 |
| `/整理记忆`                            | 手动整理当前会话尚未处理的聊天归档                           |

群里的整理、恢复和删除需要管理员或机器人主人；私聊只管理自己的资料。恢复和删除操作会清空当前模型话题，避免沿用旧版本。`/new` 保留长期记忆。

明确资料最多 20 条，每条 200 字，仍通过已有状态库保存。自动资料存储在 `workspaceRoot` 同级的 `memories.sqlite`。群内最多 2000 条有效自动资料，私聊最多 1980 条，并预留 20 条明确资料。过时版本不占有效资料名额，自动资料与其历史版本每会话合计最多 10000 条。有效名额满时仍能更正或合并已有事实（不增加有效条数）；达到历史总上限时会提示容量不足，不悄悄删除旧版本。来源按编号直接查找，删除和恢复覆盖全部保留版本。

## 配置

```yaml
alemonjs-agent-link:
  modules:
    settings:
      memory:
        automatic: true
        intervalHours: 12
        recallLimit: 8
        # 可选：OpenAI-compatible /embeddings；不配置时只用 BM25
        # embedding:
        #   baseUrl: 'https://api.example.com/v1'
        #   apiKey: '<EMBEDDING_API_KEY>'
        #   model: 'bge-m3'
        #   weight: 0.55
        #   maxItems: 200
        #   timeoutMs: 8000
```

默认每 5 分钟检查待整理会话，每个会话通常间隔 12 小时整理一次。每轮最多读取 40 条新消息、产生 8 项变更。存在积压时保留准确处理位置，后续继续处理，不会跳过中间记录。进程最多同时进行 2 个整理任务，每个任务限时 30 秒；失败后退避 30 分钟。`intervalHours` 范围为 1–168，`recallLimit` 范围为 1–20。

`embedding` 是可选的语义召回层：配置后，记忆文本会发送到该嵌入服务，费用由该服务商计；向量按模型和文本哈希缓存在 `memories.sqlite`，只有配置变化或文本更新才重算。BM25 词面命中保留原分数，语义相近但用词不同的条目以较低基础分补充；服务失败、超时或配置无效时自动退回 BM25，不阻塞聊天。`weight` 控制语义权重（0–1，默认 0.55），`maxItems` 限制单次最多补算向量的条目数（100–2000，默认 200）。已缓存且仍有效的向量全部参与语义排序，不受近期条目窗口限制；未缓存资料优先覆盖关键词命中、当前人物，再逐步覆盖其余资料。没有配置时仍使用 BM25。

`automatic: false` 关闭自动整理，检索和 `/整理记忆` 仍可用。停用 `memory` 模块会关闭自动整理、人物资料注入与新增的模型检索工具；已有的明确资料、手动查看和删除仍保留。停用 `chat-history` 模块会停止聊天来源采集及自动/手动归档整理，已形成的长期记忆可以继续查看和删除。

配置变动会触发模块配置刷新，下次请求也会重新核对配置。模块卸载会中止其后台任务；变更期间的旧结果还会经过版本校验，不能越过删除或恢复操作写回。

## 检索与人物资料

检索将中文切为相邻双字词，英文和数字按词处理，以 BM25 计算关键词匹配，再结合当前人物、重要程度、置信度、最近使用时间与被召回天数排序。经常被想起的条目衰减较慢；这是排序权重，不会因分数降低就擅自删除资料。配置 `embedding` 后会额外做一次语义重排，但 BM25 仍是基础召回；没有配置或服务失败时就是纯 BM25。

每轮可提供当前发言人的小档案、表达偏好和相关记忆。小档案由带来源的高置信事实组成，最多 8 条、约 600 字；其余召回资料有独立预算。用户只说“嗯嗯”“然后呢”等明确承接语时，只结合同一平台、会话代际和发言人在 5 分钟内的最近一次完整查询帮助召回，不借用其他群友的话题，也不让连续短句覆盖完整查询。自主搭话不会改写用户查询记录。当前查询相关记忆先占召回预算，再补表达偏好；已经进入人物档案的条目不重复注入。群内资料始终保留所属人物标记，不能把另一成员的资料当成当前人的。

模型工具 `recall_memories` 和 `inspect_memory_source` 只查询当前会话。`recall_private_memory` 和 `remember_private_fact` 只向私聊提供。最近 20 次召回的条目编号保存在本机，用于后续管理与排查。

## 自动整理与纠错

聊天自动整理只读取归档中实际收到的用户文字，跳过命令、机器人自己的回复和其他会话。不读取图片字节，不根据附件占位猜测事实。

启用自动记忆和聊天归档时，本会话成功调用 `bili_watch` 会另外记录机器人实际读取过的视频标题、BV 号、简介和可用字幕、评论的有限摘录及状态；这是一条有操作来源的经历，不代表看过画面或听过音频。最近 24 小时最多 3 条会在同一会话上下文中出现，可以在相关话题自然提及，不自动跨群或跨私聊传播。关闭自动记忆或 `chat-history` 后不新增这类经历；可通过现有记忆管理删除。删除或清空与正在进行的读取竞争时，旧请求不会把经历重新写回。空间等其他活动暂未接入经历记录。

变更必须引用当前批次中真实存在、属于同一发言人的来源编号，并提供能在来源中逐字找到的证据。低于 0.8 的置信度不写入。资料可能仍有模型理解误差，应通过原文核对；它们不会成为主人身份或工具授权依据。

新增事实会与相关旧资料比较。补充信息会保留旧文本并合并新内容；明确冲突会建立新条目，把旧条目标记为过时。旧版本仍可查证和恢复，默认召回只使用有效版本。明确保存的私聊资料不会被自动整理覆盖。用户可在私聊明确说“更正记忆：我住苏州”，由模型先查询原编号和完整原文，再调用 `correct_private_fact` 更正。新内容必须逐字出现在当前用户消息中；旧原文已变化或条目已删除时拒绝写入，不会重新创建。该工具不对群聊和主动搭话开放。更正沿用原编号、不增加名额；明确资料采用原位更新，暂不提供旧版本恢复（自动整理资料的版本链不受影响）。

删除会移除同一人物的相关版本、规范化重复项及共用来源的关联资料，清理召回记录，并跳过删除时已经存在的旧归档。后台任务带有资料版本和处理位置校验；删除、恢复、清空或重新建立会话资料库后，旧任务不能重新写入。

聊天归档与长期记忆是独立的数据。删除记忆不会删除聊天原文；需要同时删除原文时使用 `/清除聊天记录`。清除聊天归档也不会自动删除已有长期记忆。无活动资料默认 30 天清理；`/agentpurge` 覆盖当前群的长期记忆。

目前已验证本地 SQLite 持久化、来源与人物校验、检索、版本恢复、删除竞态、积压处理，以及模拟模型接入实际聊天编排。真实服务的抽取质量、长期运行和管理界面仍需后续验收。

询问过去记忆且长期召回未命中时，会在当前会话、当前人物保留期内最近 1000 条用户消息中按关键词相关性补查，返回最多 6 条原文（每条最多 600 字）；模型检索工具未命中也进行相同补查。原文不视为已确认事实，不跨会话，关闭聊天归档模块时不补查。没有关键词命中才退回近期原文，并以 match=recent 明确标记；这不代表问题已有相关证据。补查不能替代完整历史检索，截断原文可通过聊天历史工具展开。

## 本轮优化与公开方案参考（2026-10-29）

- [Letta 的记忆架构](https://github.com/letta-ai/skills/blob/main/letta/agent-development/references/memory-architecture.md)区分常驻核心资料、归档记忆与会话历史。肥鱼保留现有三层结构，改进原文补查，不将检索失败解释为没有发生。
- [LivingMemory](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory)是 AstrBot 的第三方长期记忆插件，公开介绍包含上下文召回、关键词与向量融合、会话与人格筛选。肥鱼本轮修复短句话题污染：“我不喝茶”这样的独立陈述不再继承旧话题，只有明确承接语继承。
- [Zep Facts](https://help.getzep.com/facts)区分事实有效时间与系统获知时间。肥鱼尚未实现该时间模型；本轮人物档案改为保留条目编号、保存时间和来源时间的结构化资料，辅助模型核对，不把保存时间当成事实发生时间。
- [Mem0 更新操作](https://github.com/mem0ai/mem0/blob/main/docs/core-concepts/memory-operations/update.mdx)提供独立的记忆修订能力。肥鱼继续保留来源校验、替换链与恢复能力；已补齐明确授权的私聊资料更正工具及旧原文比较保护；自动事实的属性级冲突处理仍未实现，不宣称已对齐。

以上是公开资料对照，不是对竞品的实测准确率排名。本轮不引入外部记忆托管，不变更跨会话隔离、自动整理周期或删除策略。

## 整理诊断与多人纠错

模型只读工具 `inspect_memory_status` 返回当前会话的整理开关、处理位置、最后整理时间和退避时间。原因区分归档关闭、自动整理关闭、预算缺少计费用户、退避、等待周期及可调度；不会触发模型调用或扣费。序号差不是待处理用户消息数，“可调度”也不是完成凭证。

当前开启预算保护时，未配置 `modules.settings.memory.backgroundUserId` 时，后台整理没有计费用户，会被阻止；可由有权限的用户手动 `/整理记忆`，仍受额度限制。系统不擅自把多人群聊整理费用归给某位成员。

自动纠错候选仅选本批发言人的资料，按各人消息的关键词相关性排序，再按人物轮流分配最多 30 个候选，优先照顾最近发言者。减少前面的密集发言挤掉后续人物旧资料的情况。它仍是有限候选，并不能保证发现所有语义冲突。

## 删除保护与后台计费配置

删除单条资料会持久化该人物的自动原文补查截止序号，清空记忆会设置会话级截止序号。截止之前的原文不再进入自动记忆补查，新的发言仍可使用；为防止同一事实换个说法被重新带回，单条删除也会抑制该人物此前其他原文的自动补查。这不删除归档，不影响主动调用聊天历史查询。规则只覆盖升级后的删除操作，无法从旧删除记录还原此前被删除的具体资料。

语义召回在外部请求返回后重新核对资料版本，删除或更正期间的旧检索不会写回旧向量；最终结果也过滤已删除、过时或内容已变的条目。整轮嵌入补算使用 8 秒总超时，超时退回关键词召回，用户取消仍向上传递。

预算保护下，运营者可显式设置后台整理的计费用户：

```yaml
alemonjs-agent-link:
  modules:
    settings:
      memory:
        automatic: true
        backgroundUserId: '<明确承担后台整理费用的用户ID>'
```

未配置不会自动选择主人或群成员。该用户用于后台整理的预算归属，仍调用现有额度检查；配置可能覆盖多个会话的整理任务。这里不是个人 Key 绑定配置，也不保证额度充足或模型凭证可用。当前本地配置未自动填写该值。

## 区分聊天中知道与已经保存

你补充一个主题后，肥鱼可以接着聊，但这不代表已长期保存。明确请求保存后，肥鱼应根据实际结果说明：本次已保存、这条原本已保存，或本次没有保存。容量满、保存入口不可用和失败都不能说成保存成功，也不承诺永久记得。

保存入口不可用不代表聊天结束就必忘；当前列表为空，也不能推断你从未说过。仍可通过 `/记忆` 核对当前记录，或用 `/记住 内容` 明确保存。
