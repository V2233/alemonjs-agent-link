# 气泡文案与长度

本次检查覆盖 `src/response` 下 37 个文件及公共错误提示、额度提示、模型回复规则。采集与事件入口本身没有固定气泡的，保留原流程。修仙等其他插件发布的气泡不属于这里的文案范围。

- 所有 QQ 结构化气泡统一走 `src/response/bubble.ts`：正文用 Markdown 引用块分组。**所有命令导航默认降级成正文里的 `<qqbot-cmd-input>`**：点一下只填入指令、不发送；不再按 1–3 个/4 个以上切换视觉通道，也不再为多入口菜单保留固定键盘条。
  - `layout: 'keyboard'` 是旧调用；只要动作是命令，仍会降级成行内 Markdown 输入。
  - 只有两类动作保留键盘组（`BT.group`）：**打开外部链接**（`url`）和**单选/二选一菜单**（`choice: 'single' | 'binary'`）。这两类无法用 Markdown 指令输入表达，继续用底部小按钮。
  - 键盘按钮仍最多 10 个、1–4 个字；命令行内按钮最多 10 个，标签保留完整说明，超出时截断而不是静默换回键盘。
  - 非 QQ 平台仍只保留文字卡片，不下发行内指令或键盘按钮。
- 列表页统一规则：一个对象一个引用块，局部操作的行内按钮放在该对象块末尾；页尾只做当前页需要的动作，不做全站固定 bar。`/人格`、`/记忆`、`/表情` 已按此排版；`/状态` 按「服务、模型、媒体、聊天记录、每日额度」分行；`/额度` 用 `来源 / 已用·上限 / 可用` 三列表格排版，`/额度 记录` 每次调整一个块；`/工具策略` 每个能力一行，开/关按钮就在该行；`/模型列表` 每页 8 个，用 `# / 模型 / 状态` 表格排版，页尾挂 `‹上一页› ‹下一页›`；`/表情` 同样每页 8 个，用 `/表情 列表 2` 翻页；`/模型池` 每个端点一个块，块内挂 `‹启用›`/`‹停用›`/`‹通测›`，启停只影响本次运行，页尾只放当前页的翻页与刷新。
- `/帮助` 目录改成每个主题一个短块，块内一个「查看」行内按钮；不再用键盘条。分项帮助用正文加一个「帮助目录」行内入口，不再套多个引用块。
- 其余管理页同样收敛：`/我的钥匙`、`/我的钥匙 私聊` 按状态、用途、下一步分行；`/主动搭话` 按订阅、节奏、暂停分行；`/当前模型`、`/模块状态` 用表格；`/心情` 用变化表；`/群记忆` 每条记忆一个块。
  - 按钮只由应用自己声明，用户内容一律转义、不会变成按钮；去重后更具体的指令顶替其前缀（`/人格 使用 编辑器` 优先于 `/人格`）。非 QQ 平台只保留文字卡片，不下发键盘按钮组，避免 OneBot 因不支持的格式整条发送失败。
- 系统提示也走同一套：额度不足、服务不可用、AI 开关、取消、新会话、聊天参考、语音与提问用法统一用 `noticeBubble`（等价 `commandBubble`）——多行才做卡片；所有命令下一步都用行内按钮，单行确认仍是纯文本。额度不足提示里的按钮必须和正文教程里的指令逐条对齐（`/我的钥匙`、`/我的钥匙 私聊 添加`、`/额度`），`test/command-bubble.test.mjs` 会逐条断言「正文提到 = 按钮存在」。
- 文案预算与写法：每张卡在按钮之上只保留“下一步做什么 + 不可逆边界”，不重复卡片标题（单主题帮助卡不再复述主题名），占位符提示只在正文真的出现“编号/关键词/内容/模型ID/分钟”时显示，有按钮的卡片统一用一句「按钮只填入，不发送。」说明点按不会直接执行。长度上限由 `test/bubble-copy.test.mjs` 的 “bubble copy stays inside its length budget” 锁定：帮助目录 ≤420 字，聊天 ≤180、记忆 ≤215、人格 ≤250、媒体 ≤235、数据 ≤205、管理 ≤380，隐私 ≤425，清除群数据确认 ≤110，人格列表 ≤170，状态 ≤185，记忆列表 ≤130，表情 ≤65。
- 每类状态卡自带下一步：`/状态` 的服务、模型、媒体、额度各行挂本行入口，`/额度` 的表格下方挂刷新、记录和密钥入口，`/模型列表`、`/模型池` 带翻页与刷新，`/工具策略` 每个能力挂开/关入口，`/主动搭话`、`/语音引擎`、`/我的钥匙`、`/我的钥匙 私聊`、`/清除群数据`、`/隐私说明`、`/记忆` 同理；`/人格` 列表按条目生成「使用 名称」按钮。可执行指令必须真实存在，占位参数（编号、关键词）不生成按钮。键盘短名集中在 `bubble.ts` 的 `KEYBOARD_LABELS`，只服务链接/选择按钮；`test/command-bubble.test.mjs` 断言每个键盘按钮 1-4 字且不出现省略号。
- 默认帮助按主题短块排列，每个块只挂一个「查看」行内入口；主人私聊追加管理入口。`/帮助 聊天`、`/帮助 记忆`、`/帮助 人格`、`/帮助 媒体`、`/帮助 数据` 分项查看；`/帮助 额度` 显示当前场景的密钥添加教程。主人私聊可用 `/帮助 管理`，`/帮助 全部` 按身份分主题发送，避免一个超长气泡。
- `/状态` 给出当前结果；主人私聊用 `/状态 详情` 查看平台和权限，不在日常提示中展开运行时名词和配置教程。
- `/人格` 列表只发送一次，管理操作移至 `/人格 帮助`。语音试听以语音气泡携带引擎信息，成功后不再单发文字确认。
- 记忆列表最多展示 10 条短预览，省略的正文明确标记，使用 `/记忆检索` 和 `/记忆来源` 查找与展开。模型列表预留提示和页尾长度。
- 默认 AI 回复先说结果，通常一到三句；完整清单、详细解释和复杂任务仍按需展开。群聊非直接回复另有 220 字软上限，在句末收住；代码、链接和表格不截断，明确提问的直接回复不受限。避免重复旧的失败信息、无关限制或发送第二条结语，不截断必要内容来压气泡数。
- 删除操作保留范围、不可恢复性、有效期和确认命令；额度保留金额、免费与充值区别、个人共享范围和重置规则；隐私保留数据流向、隔离及记录和记忆分别删除的区别。
- 发送失败、部分成功和结果不明仍须如实说明。只精简文案，不把“已配置”说成“已验证可用”，也不隐藏用户需要判断的操作后果。

## 修仙参考与近期卡片复盘

参考修仙机器人的 `/我的资料`、`/万宝楼`（不参考它的底部固定 bar）：

- 一张卡先给标题和当前状态，再按对象/字段拆行；
- 每个对象只有自己的局部动作，按钮贴着对应信息，不放一批脱离上下文的总菜单；
- `/万宝楼` 每件商品一个引用块：`【编号】名称 ×数量`、价格/限购各一行，购买和详情就在块内；
- `/我的资料` 把字段、本行操作和页脚分组分开，阅读顺序固定；
- 长说明拆主题，不用一个 1800 字的大气泡硬塞。

仍需真机确认：`/群设置 查看` 的 10 个行内按钮在手机上是否换行过多；`/群设置 记录` 的时间戳已缩成 `MM-DD HH:mm`。这些不影响指令正确性，但影响扫读。

验证：`test/bubble-copy.test.mjs` 使用框架事件和发送回执检查默认帮助、人设列表、隐私、清理确认与主人状态的气泡数量和必要信息；`test/agent-turn.test.mjs`、`test/companion.test.mjs` 等继续验证模型及流式链路。实际模型是否遵守简洁风格、QQ 客户端的最终显示仍需使用中观察。

固定命令的多行说明、列表和状态使用结构化 Markdown，强调字段并保留换行；短确认和单行错误仍使用 Text。用户提供的内容进行转义，不自动转成按钮。QQ 私聊增量流使用 text，仍即时发送首段。模型默认用普通文字交流，明确请求代码等内容时保留必要格式。额度不足直接展示个人或群密钥绑定步骤；个人密钥仅用于本人私聊，群聊钥匙需先私聊保存，再由管理员在群里按编号授权，不能在群里公开真实密钥。

QQ 群聊的首条回复含框架 Mention 时，正文使用框架 Markdown 消息封装，以确保 qqbot-at-user 被客户端正确解析；视觉上仍保持简短普通排版。帮助与多行指令说明使用 Markdown；模型私聊与后续流式分段仍保持 Text。真实适配器回归覆盖普通 Text 错误暴露标签及修复后 msg_type=2 的报文。

明确 @ 的消息合并等待最多 200 毫秒，/提问 等显式指令仍为零等待；等待该用户说完的规则保留。单一提问者的直接群问答不再为回复对象选择缓冲整段答案，模型流的完整句子可提前发送；多人目标选择、语音、沉默判断和内容审查仍按原规则处理。明确 @ 与指令不受自主参与的四轮对话和群发言次数启发式限制，仍保留机器人、重复复读、回声和正式请求频率检查。

指令气泡的适配器回归见 `test/command-bubble.test.mjs`：验证群聊与私聊 msg_type=2、按钮与说明同引用块、按钮不自动提交，以及用户内容不能注入 QQ 标签。OneBot 帮助保留可复制的文字命令。此验证不代表已在真实 QQ 客户端验收视觉。

性能补充：业务文本模型不等待 DSH 沙箱冷启动，工作区工具执行时仍等待真实沙箱就绪。绑定 Key 的成功余额确认仅在同一请求内复用，每次读取仍校验启用状态与版本；不同请求、不同作用域和更换密钥不共用确认，失败不缓存。日志通过 requestId 关联 Agent context prepared、Agent first content 和 Agent turn latency，分别记录上下文准备、排队、首段内容和整轮处理耗时，不记录密钥或正文。
