# 气泡文案与长度

本次检查覆盖 `src/response` 下 37 个文件及公共错误提示、额度提示、模型回复规则。采集与事件入口本身没有固定气泡的，保留原流程。修仙等其他插件发布的气泡不属于这里的文案范围。

- 所有 QQ 结构化气泡统一走 `src/response/bubble.ts`：正文用 Markdown 引用块分组，可点入口同时铺成两处——正文里的 `<qqbot-cmd-input>`（点一下只填入指令，不发送，标签保留「聊天用法」这类完整说明）和消息底部的键盘按钮组（`BT.group`，小号蓝框，最多 5 行 × 5 列，实际上限 10 个；按钮文字固定 1-4 个字，如「聊天」「人格说明」「清记录」，避免小按钮被挤断行）。按钮只由应用自己声明，用户内容一律转义、不会变成按钮；去重后更具体的指令顶替其前缀（`/人格 使用 编辑器` 优先于 `/人格`）。非 QQ 平台只保留文字卡片，不下发键盘按钮组，避免 OneBot 因不支持的格式整条发送失败。
- 系统提示也走同一套：额度不足、服务不可用、AI 开关、取消、新会话、聊天参考、语音与提问用法统一用 `noticeBubble`（等价 `commandBubble`）——多行才做卡片并挂可点入口，单行确认仍是纯文本。额度不足提示里的按钮必须和正文教程里的指令逐条对齐（`/群密钥 绑定`、`/个人密钥 绑定`、`/额度`），`test/command-bubble.test.mjs` 会逐条断言「正文提到 = 按钮存在」。
- 文案预算与写法：每张卡在小号键盘按钮之上只保留“下一步做什么 + 不可逆边界”，不重复卡片标题（单主题帮助卡不再复述主题名），占位符提示只在正文真的出现“编号/关键词/内容/模型ID/分钟”时显示，有按钮的卡片统一用一句「按钮只填入，不发送。」说明点按不会直接执行。长度上限由 `test/bubble-copy.test.mjs` 的 “bubble copy stays inside its length budget” 锁定：帮助目录 ≤420 字，聊天 ≤180、记忆 ≤215、人格 ≤250、媒体 ≤235、数据 ≤205、管理 ≤380，隐私 ≤425，清除群数据确认 ≤110，人格列表 ≤170，状态 ≤175，记忆列表 ≤130，表情 ≤65。
- 每类状态卡自带下一步：`/状态` 带「状态详情、今日额度、帮助」，`/额度` 带「调整记录、个人/群密钥、额度教程」，`/模型列表`、`/当前模型` 带「密钥配置」，`/工具策略` 带开启/关闭入口，`/主动搭话`、`/语音引擎`、`/群密钥`、`/个人密钥`、`/清除群数据`、`/隐私说明`、`/记忆` 同理；`/人格` 列表按条目生成「使用 名称」按钮。可执行指令必须真实存在，占位参数（编号、关键词）不生成按钮。键盘短名集中在 `bubble.ts` 的 `KEYBOARD_LABELS`，`test/command-bubble.test.mjs` 断言每个键盘按钮 1-4 字且不出现省略号。
- 默认帮助使用结构化 Markdown，按聊天、记忆、人格、额度与隐私分组，附操作示例和仅填入指令的按钮；主人私聊追加管理入口。`/帮助 聊天`、`/帮助 记忆`、`/帮助 人格`、`/帮助 媒体`、`/帮助 数据` 分项查看；`/帮助 额度` 显示当前场景的密钥添加教程。主人私聊可用 `/帮助 管理`，`/帮助 全部` 按身份分主题发送，避免一个超长气泡。
- `/状态` 给出当前结果；主人私聊用 `/状态 详情` 查看平台和权限，不在日常提示中展开运行时名词和配置教程。
- `/人格` 列表只发送一次，管理操作移至 `/人格 帮助`。语音试听以语音气泡携带引擎信息，成功后不再单发文字确认。
- 记忆列表最多展示 10 条短预览，省略的正文明确标记，使用 `/记忆检索` 和 `/记忆来源` 查找与展开。模型列表预留提示和页尾长度。
- 默认 AI 回复先说结果，通常一到三句；完整清单、详细解释和复杂任务仍按需展开。避免重复旧的失败信息、无关限制或发送第二条结语，不截断必要内容来压气泡数。
- 删除操作保留范围、不可恢复性、有效期和确认命令；额度保留金额、免费与充值区别、个人共享范围和重置规则；隐私保留数据流向、隔离及记录和记忆分别删除的区别。
- 发送失败、部分成功和结果不明仍须如实说明。只精简文案，不把“已配置”说成“已验证可用”，也不隐藏用户需要判断的操作后果。

验证：`test/bubble-copy.test.mjs` 使用框架事件和发送回执检查默认帮助、人设列表、隐私、清理确认与主人状态的气泡数量和必要信息；`test/agent-turn.test.mjs`、`test/companion.test.mjs` 等继续验证模型及流式链路。实际模型是否遵守简洁风格、QQ 客户端的最终显示仍需使用中观察。

固定命令的多行说明、列表和状态使用结构化 Markdown，强调字段并保留换行；短确认和单行错误仍使用 Text。用户提供的内容进行转义，不自动转成按钮。QQ 私聊增量流使用 text，仍即时发送首段。模型默认用普通文字交流，明确请求代码等内容时保留必要格式。额度不足直接展示个人或群密钥绑定步骤；个人密钥仅用于本人私聊，群密钥需管理员在群里申请临时码后由本人私聊提交，不能在群里公开真实密钥。

QQ 群聊的首条回复含框架 Mention 时，正文使用框架 Markdown 消息封装，以确保 qqbot-at-user 被客户端正确解析；视觉上仍保持简短普通排版。帮助与多行指令说明使用 Markdown；模型私聊与后续流式分段仍保持 Text。真实适配器回归覆盖普通 Text 错误暴露标签及修复后 msg_type=2 的报文。

明确 @ 的消息合并等待最多 200 毫秒，/提问 等显式指令仍为零等待；等待该用户说完的规则保留。单一提问者的直接群问答不再为回复对象选择缓冲整段答案，模型流的完整句子可提前发送；多人目标选择、语音、沉默判断和内容审查仍按原规则处理。明确 @ 与指令不受自主参与的四轮对话和群发言次数启发式限制，仍保留机器人、重复复读、回声和正式请求频率检查。

指令气泡的适配器回归见 `test/command-bubble.test.mjs`：验证群聊与私聊 msg_type=2、按钮与说明同引用块、按钮不自动提交，以及用户内容不能注入 QQ 标签。OneBot 帮助保留可复制的文字命令。此验证不代表已在真实 QQ 客户端验收视觉。

性能补充：业务文本模型不等待 DSH 沙箱冷启动，工作区工具执行时仍等待真实沙箱就绪。绑定 Key 的成功余额确认仅在同一请求内复用，每次读取仍校验启用状态与版本；不同请求、不同作用域和更换密钥不共用确认，失败不缓存。日志通过 requestId 关联 Agent context prepared、Agent first content 和 Agent turn latency，分别记录上下文准备、排队、首段内容和整轮处理耗时，不记录密钥或正文。
