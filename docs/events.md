# 事件库（第一版）

管理页「事件库」支持新增、编辑、停用、删除事件，字段为事件名称、触发词、应对方式。管理员接口沿用词典的认证边界与乐观锁。数据独立保存到 events.sqlite。

聊天命中启用事件后将应对方式加入上下文，由人物结合当前情况决定表达，不代表执行了动作。实际聊天预算拦截会读取启用的「实际额度不足」事件，将其直接发送台词加在原有额度明细前，不再调用模型；沿用已有通知冷却。事件模块停用或存储读取失败时退回原提示。后台感知预算提醒仍使用独立原提示。

预置元旦、劳动节、国庆节提前七天按北京时间提供节日准备上下文。管理页可配置公历 MM-DD 日期、提前 1—30 天、应对方式，并支持停用或删除。默认事件只初始化一次，删除后重启不再补回。只有已有聊天或主动回合运行时才生效，没有新增节日定时任务；不覆盖春节、中秋等农历节日，不保证主动发送。

模型可调用 record_external_evaluation，将当前发言人明确针对人物的评价原文保存下来。工具校验引用必须存在于当前消息；语义是否为评价由模型判断。按平台、会话、人物隔离，保留评价历史，上下文读取最近十条有效记录。按当前消息与原话幂等保存，支持直接评价、转述、玩笑和纠错；同一句旧消息不会让撤回记录重新生效。只保存外部观点，不自动修改人格，不把观点作为可信指令。管理页「外部评价历史」支持分页查看和撤回，撤回后不再进入上下文。旧版最近评价会一次性迁移到历史表。

节日前准备与当天祝福分别记录：正常回复完成后，回复包含事件名称（去掉末尾“准备”）才记入当前会话和人物的当年送达记录；后续不再注入该阶段提示。它是名称匹配去重，不是语义保证，并发回合仍可能同时获得提示。沉默或发送失败不记录。未新增独立定时器。

新增被认真纠错、对方需要安静、久别重逢、被具体夸奖的行为参考。安静事件目前指导表达，并不直接更改主动消息订阅设置。默认“你好”评价触发词已移除，仅迁移仍保持原始词表的条目，不覆盖管理员修改。
