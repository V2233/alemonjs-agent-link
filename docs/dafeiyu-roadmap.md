## 表情包：Aurabot 的做法与取舍

核对 Aurabot 的 [表情功能源码](https://github.com/accomplish07zrh-eng/dsh-aurabot-qq/blob/main/src/features/stickers.js) 和 [模块入口](https://github.com/accomplish07zrh-eng/dsh-aurabot-qq/blob/main/src/modules/stickers/index.js) 后，可以看到它把表情包当成一条完整的产品链路：

- **只收真表情**：`sub_type=1`、`mface` 或带 `emoji_id` 的图片才算；再用宽高比、尺寸、体积、MD5 去重和每小时限额过滤，普通照片不收。
- **写进 QQ 收藏**：收下后调用 `add_custom_face`，视觉模型起名后调用 `modify_custom_face` 把名字写回 QQ；还能用 `fetch_custom_face` 把机器人号“我喜欢的”批量导入。
- **可管理、可命中**：模糊匹配名字/标签，按回复文字自动挑图，按使用次数淘汰，面板支持上传、改名、删除；主人亲手加的表情只有主人能删。
- **发送形态**：本地图片按 `sub_type=1` 的图片段发出，并标注摘要。

AgentLink 采纳了“平台标记 + 内容哈希去重 + 锁定清单 + 视觉标签 + 主人权限”，并在此基础上做了三处不同：

- **普通图片静默审核**：不只认 `sub_type=1`，还会在启用的群里把普通图片先做几何/体积预筛，再让视觉模型判断“是不是表情包、适不适合普通群聊”，通过才入库。比纯几何门槛更准，也明确拒绝截图、隐私信息、广告和不适内容。
- **自己的表情库**：默认 300 项，带名称、来源、添加时间、使用次数、最近使用、尺寸、字节和置信度；超限只淘汰最少使用的 `auto` 条目，主人手动加入和工坊生成的不动。
- **配字二创**：`make_sticker` 把当前图片或库内表情裁成方形 PNG、上下配字，并可同轮发送。

仍需补齐或保持差异的部分：

- **QQ 收藏写回**：链路已接（`/表情 同步`、`/表情 删除`、`autoQQSync`），自动写入默认开启，可设 `autoQQSync: false` 关闭；仍依赖网关支持 `add_custom_face` / `modify_custom_face` / `delete_custom_face`。
- **模糊发送**：发错表情比“没找到”更伤体验，`send_sticker` 仍要求完整编号、名称或标签。
- **可视化面板**：已提供仅回环、token 鉴权的本地表情面板（查看/上传/改名/移除），其余配置和日志仍走 YAML/聊天命令；DSH 内嵌面板未做。最近图片缓存已做（内存、30 分钟、每会话 6 条）。

本次核对的 Aurabot 版本没有“把收到的图配字做成新表情”的能力；`make_sticker` 是 AgentLink 的差异项：本地渲染、可预期格式、不新增第三方服务与费用。它的真实效果仍要靠在部署机器上用中文字体、真实 QQ 图片和平台回执验收。

## 推进顺序

1. 聊天基础：人设、发言人、唤醒、显式长期记忆；保证保存和删除语义可信。
2. 媒体闭环：先实现一个视觉 provider 与一个 ASR/TTS provider，完成真实收发再加花样；表情素材单独配置。
3. 长期陪伴：在可纠错记忆之上加检索、话题续接、心情；主动消息必须有实际平台能力和用户订阅。
4. 管理与扩展：可视化管理、引用/转发、按适配器开放外部社区功能。

现在可选择 QQ Bot 或 OneBot 正向 WebSocket。OneBot 已接入戳一戳和白名单群管理，账号、操作回执和实时权限分别核实；QQ 空间、B站和翻唱仍需独立服务链路。不能因为模型说“已发送语音”“已发动态”就当作能力实现。连接配置见 [OneBot 接入](onebot.md)。

持续更新的逐项状态见[能力建设与验收](capabilities.md)，人格与心情配置见[陪伴能力](companion.md)。代码及模拟接口测试不能替代真实模型质量、provider 与 QQ 收发验收。
