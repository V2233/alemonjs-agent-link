# 大肥鱼能力对标

核对日期：2026-10-26。以下对标来自项目公开文档，未独立验证其他项目的全部功能；不能把功能清单当成当前插件的交付结果。

## 参照项目

- [Aurabot](https://github.com/accomplish07zrh-eng/dsh-aurabot-qq)：声明支持人格、心情、记忆、语音、图片与表情、主动搭话，以及空间、B 站等扩展，基于 SnowLuma / OneBot v11。
- [AstrBot 大肥鱼](https://github.com/whyever77/dafeiyu-astrbot)：提供人格与消息处理插件，图片、语音依赖对应模型，长期记忆与主动消息依赖配套插件。
- [dafeiyu-bot](https://github.com/SAKURAfan1023/dafeiyu-bot)：声明支持性格、独立记忆、图片/GIF、表情、联网与生图，并明确区分已有 QQ 接收证据和待验收功能。

## 当前差距

| 能力             | AgentLink 当前状态                                           | 追平所需工作与验收                                                   |
| ---------------- | ------------------------------------------------------------ | -------------------------------------------------------------------- |
| 人格与短句聊天   | 内置大肥鱼提示词，可自定义；有明确事实边界                   | 用真实多轮聊天验证口吻、重复率与复杂任务质量                         |
| 私聊与群唤醒     | 私聊直接文字；群 @、命令、开头称呼；附发言人资料             | 真实 QQ 验证群内多人身份、名字误触发和重复投递                       |
| 多轮对话         | 纯聊天有界历史；沙箱使用 DSH 会话                            | 验证 Worker 重启后的连续性，不能宣称全部模式均可恢复                 |
| 长期记忆         | 明确保存、查看、删除，私聊隔离；不依赖向量服务               | 尚缺自动提取、冲突处理、检索排序；必须能解释来源并纠错               |
| 引用与转发理解   | 尚未实现内容展开                                             | 核对适配器标准化引用字段与权限；只读可访问内容                       |
| 图片/GIF理解     | 静态图片兼容接口已接入；动图理解未实现                       | 独立视觉模型配置、附件大小与超时限制、格式与抽帧；失败时不得编造画面 |
| 语音输入/输出    | 兼容 ASR/TTS 接口、平台 Transcript、音频发送与文字回退已接入 | ASR/TTS provider、真实音频格式、平台上传发送回执与文本降级           |
| 表情包           | 本地清单、精确标签选择、冷却与平台发送已接入                 | 有授权的素材库、标签索引、冷却、平台图片上传及失败回退               |
| 主动搭话         | 尚未实现                                                     | 用户订阅、免打扰时段、未回复停止、次数限制、平台主动消息权限         |
| 心情与关系变化   | 尚未实现                                                     | 可解释的状态变化与恢复；避免把推测写成用户事实                       |
| 可视化管理       | YAML + 聊天命令                                              | 身份验证、配置修改、能力健康状态、记忆管理与日志脱敏                 |
| QQ 空间/B站/翻唱 | 尚未实现                                                     | 不是当前 QQ Bot 接口的同等能力；必须独立核实适配器、账号与服务依赖   |

## 推进顺序

1. 聊天基础：人设、发言人、唤醒、显式长期记忆；保证保存和删除语义可信。
2. 媒体闭环：先实现一个视觉 provider 与一个 ASR/TTS provider，完成真实收发再加花样；表情素材单独配置。
3. 长期陪伴：在可纠错记忆之上加检索、话题续接、心情；主动消息必须有实际平台能力和用户订阅。
4. 管理与扩展：可视化管理、引用/转发、按适配器开放外部社区功能。

当前使用 AlemonJS + QQ Bot 配置，参照项目多使用 QQ 小号 + NapCat/SnowLuma。不能直接复制它们的 OneBot 调用，也不能因为模型说“已发送语音”“已发动态”就当作能力实现。

媒体新增项已做模拟接口测试，不能替代实际 provider 与 QQ 收发验收。配置见 [media.md](media.md)。
