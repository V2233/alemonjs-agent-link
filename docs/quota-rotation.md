# 额度轮转管理

## 调度规则（当前实现）

依据 `src/credentials/pool.ts` 和 `src/model-pool/config.ts`：

1. 筛选用途、供应商、停用状态、冷却、并发容量与分钟 RPM/TPM；同账号限流还会影响多个端点。
2. 可用主端点优先于备用端点。主端点只是并发满时，可按排队窗口等待，再使用备用。
3. 同组端点由数组顺序生成软优先级，结合健康状态和调度策略选择。
4. weighted-round-robin 按权重轮询；least-busy 优先空闲和近期低流量；balanced 综合活跃请求、近期流量、权重和延迟；sticky 根据会话标识稳定选择。稳定模式还可能优先低延迟。
5. 401/402/403 可使端点停用并等待恢复探测；429 根据响应头和配置冷却；服务端错误按失败阈值进入冷却。
6. 轻量探测使用 /models。成功不能证明聊天额度恢复，也不会清除仍有效的 429 冷却。

## 页面功能与数据边界

- 当前进程状态、冷却截止时间、并发、分钟请求/Token、当日进程用量和沙箱日期统计。
- 供应商余额单独查询，使用已有查询适配和缓存；保留币种与查询时间，不汇总不同账号余额，也不把未知值当零。
- 列表“参与轮转”开关持久保存，刷新后保留；全局关闭轮转时仍可调整单个端点的参与状态。运行时因凭证失效等原因停用，单独显示为“运行时停用”。
- 全局关闭轮转或端点停用时，仍可单独和一键测活、查额度。关闭期间使用隔离诊断实例，不开启实际请求调度。
- 额度、连通、参与轮转支持分别筛选；低余额使用提醒颜色，未知额度不显示为零。
- 自定义额度查询地址支持新增、修改和清除，保存前校验 HTTPS 与 `{key}` 占位符；停止轮转也不能绕过校验。
- 配置保存复用版本检查、密钥占位符保留、备份与框架重载。
- 本地预算展示配置限额，不伪装成供应商剩余额度或 Redis 实际已用账本。
- 当前页面手动刷新。待调度状态不保证某个具体请求能通过账号共享限流或预算检查。
- 轻量探测不发送付费聊天请求。页面不提供账本充值或修改用户余额。

## 验证

`node --test test/admin-pool.test.mjs test/product-settings.test.mjs`：凭证不暴露、运行期启停、单 Key 状态、非法端点操作、配置保存及框架 API 挂载。

实际供应商余额、平台账号及 Redis 账本需在目标运行环境核实。

## 端点顺序

端点数组顺序是优先级的唯一来源，第一项优先级为0；旧配置中的显式 `priority` 不再参与解析，后台保存端点设置时移除该字段。列表和表单不再要求填写优先级。每项前的手柄长按300毫秒后拖动，释放保存顺序；「置顶」将该项移到数组首位。列表按完整数组展示，筛选期间禁用拖拽，避免隐藏端点导致顺序歧义。保存使用版本检查并保留密钥。

当前实现为软优先级：数组顺序影响端点评分，不保证首项独占请求；主备、健康、容量和调度策略仍生效。
