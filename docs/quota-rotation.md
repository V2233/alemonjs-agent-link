# 额度轮转管理

## 调度规则（当前实现）

依据 `src/credentials/pool.ts` 和 `src/model-pool/config.ts`：

1. 筛选用途、供应商、停用状态、冷却、并发容量与分钟 RPM/TPM；同账号限流还会影响多个端点。
2. 可用主端点优先于备用端点。主端点只是并发满时，可按排队窗口等待，再使用备用。
3. 同组可用端点只按活跃任务数升序选择；相同时按数组顺序。借鉴 NGINX `least_conn` 与主备、失败隔离机制，业务调度不提供权重、随机、哈希或其他策略。
4. 一次聊天任务持有一个端点，并贯穿工具执行及后续模型轮次；轮次完成不释放并发槽，整个任务结束、异常或取消时才释放。下一次任务重新选点，没有会话粘性 TTL。
5. 任务中已绑定端点遇到额度、限流或故障时，不切换端点拼接结果。后续轮次可在配置的等待窗口内等原端点恢复，超时结束任务。网络超时、空响应和流错误不自动重放；非绑定的独立请求仅对明确拒绝（401/402/403/429、明确计费拒绝）允许有限重试。
6. 401/402/403 可使端点停用并等待恢复探测；429 根据响应头和配置冷却；服务端错误与网络故障按失败阈值隔离。取消、本地预算失败不计供应商故障。
7. 配置重载保留进程内活跃计数；旧任务使用原凭证，后续任务使用新配置。删除后重新添加同 ID 端点也保留未释放容量。相同凭证、地址和模型继续共享健康状态，旧任务的限流或鉴权失败对新调度仍生效。
8. 轻量探测使用 /models。成功不能证明聊天额度恢复，也不会清除仍有效的 429 冷却。较晚返回的成功请求不能撤销冷却或手动停用；探测期间发生新的调用结果或启停操作时，过期探测结果丢弃。
9. 主端点排队窗口到期后允许选择备用端点；等待期间取消或结束任务会中断等待，并释放竞态中已获取的占用。同一任务禁止并发申请轮次。

旧 `strategy`、`weight`、`stickySeconds` 兼容读取但不生效，管理页保存时移除。并发容量是单进程统计，不是跨机器人实例的分布式锁。Node 聊天每轮进行 RPM/TPM 预留；沙箱按整体任务占用容量，内部多次模型调用尚不具备逐次 Node RPM/TPM 结算。

## 页面功能与数据边界

- 当前进程状态、冷却截止时间、并发、分钟请求/Token、当日进程用量和沙箱日期统计。
- 供应商余额单独查询，使用已有查询适配和缓存；保留币种与查询时间，不汇总不同账号余额，也不把未知值当零。
- 列表“参与轮转”开关持久保存，刷新后保留；全局关闭轮转时仍可调整单个端点的参与状态。运行时因凭证失效等原因停用，单独显示为“运行时停用”。
- 全局关闭轮转或端点停用时，仍可单独和一键测活、查额度。关闭期间使用隔离诊断实例，不开启实际请求调度。
- 额度、连通、参与轮转支持分别筛选；低余额使用提醒颜色，未知额度不显示为零。
- 自定义额度查询地址支持新增、修改和清除，保存前校验 HTTPS 与 `{key}` 占位符；停止轮转也不能绕过校验。
- 配置保存复用版本检查、密钥占位符保留、备份与框架重载。
- 本地预算展示配置限额，不伪装成供应商剩余额度或 Redis 实际已用账本。
- 当前页面手动刷新。待调度状态不保证某个具体请求能通过账号共享限流或预算检查。
- 轻量探测不发送付费聊天请求。页面不提供账本充值或修改用户余额。

## 验证

`node --test test/admin-pool.test.mjs test/product-settings.test.mjs`：凭证不暴露、运行期启停、单 Key 状态、非法端点操作、配置保存及框架 API 挂载。

实际供应商余额、平台账号及 Redis 账本需在目标运行环境核实。

## 端点顺序

端点数组顺序是优先级的唯一来源，第一项优先级为0；旧配置中的显式 `priority` 不再参与解析，后台保存端点设置时移除该字段。列表和表单不再要求填写优先级。每项前的手柄长按300毫秒后拖动，释放保存顺序；「置顶」将该项移到数组首位。列表按完整数组展示，筛选期间禁用拖拽，避免隐藏端点导致顺序歧义。保存使用版本检查并保留密钥。

数组顺序仅在同组端点活跃任务数相同时决定先后，不是严格的主端点独占。主备、健康、能力和容量筛选先于此排序。

## 一键健康检查

「一键健康检查」复用单端点健康检查：对全部端点（包括停用端点）发送小型模型请求，最多同时检查两个。确认提示说明可能消耗供应商额度。任务在后台执行，重复启动返回当前任务，逐项失败不阻断其他端点；成功与失败按实际检查结果统计。不会修改端点启停状态，关闭轮转时也可检查。

页面不轮询任务进度，点击刷新查看已完成数量、成功/失败数及各端点最新健康状态。该检查不同于免费连通测活，不代表余额查询。
