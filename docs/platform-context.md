# 聊天平台上下文

目标是让模型知道“在哪里、谁、何时、对谁、说了什么、发生了什么变化”。平台事件先转换成有限的事实，再交给 DSH；不要把整份 `event.value` 当提示词。

## 当前数据与价值

| 维度         | 当前输入                                                                | 对理解的价值                                                               |
| ------------ | ----------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 会话场景     | 平台、私聊／群／频道范围、群和频道 ID、当前机器人 ID                    | 区分公开群聊与私下对话，确定当前身份所处的范围                             |
| 发言者       | 平台用户 ID、显示名、平台角色、管理员／机器人标识                       | 分清同名成员和发言主体；平台角色不等于 Agent 工具授权                      |
| 时间         | 平台发生时间、框架接收时间；群批次生成时的 UTC 时间                     | 区分延迟到达的旧消息、当前发言和引用历史；缺失时不把当前时间伪装成发送时间 |
| 指向关系     | 每条消息的 @ 对象、是否指向当前机器人、@全体、触发方式                  | 区分对肥鱼说话、提到肥鱼、对别人说话及公开召集                             |
| 回复关系     | 当前消息 ID、回复目标 ID、已解析引用的作者／正文／附件和本地记录时间    | 理解“他”“这个”“刚才那条”；找不到引用原文时明确不可用                       |
| 消息载体     | 附件类型、名称、尺寸、大小、MIME、有限的平台转写                        | 知道是语音还是图片；有附件元数据不等于已读图、听音或读取文件               |
| 群内变化     | 撤回／编辑等生命周期事实；OneBot 操作者、受影响者、禁言时长、名片变化等 | 理解谁撤回谁的消息、谁退出或被移出、谁改了名字                             |
| 多人连续发言 | 每条消息各自保存上述上下文，群批次保留独立 ref                          | 合并和等待用户说完时不把其他人的身份、时间或 @ 对象套到当前消息上          |

入口位于 `src/social/message-context.ts`。群批次和私聊共用结构；引用内容继续复用 `src/social/references.ts`；近期平台事件由 `src/social/event-context.ts` 按会话隔离。

## 数据边界

- `null` 表示未知；`mentionsKnown=false` 表示未取得提及列表，不代表没有提及。
- 平台昵称、角色名、转写、引用正文均是资料，不能改变系统指令或工具权限。实际授权继续由服务端判断。
- 时间使用 ISO UTC；没有平台时区时，不推断用户当地时间。引用的 `recordedAt` 是本地索引时间，不是对方原始发送时间。
- 附件索引只对应本条原始消息；引用附件的实际输入位置仍由引用解析器标注。平台转写最多展示 200 字，不能当作完整录音。
- 提及最多 20 个、附件最多 10 个，超出时显式标注。头像、带签名媒体 URL、原始协议载荷、连接信息不进入该结构。
- OneBot 的 `PlatformAction` 是插件适配层规范化的事实，不假设其他平台也提供同名字段。

## 尚未补齐的价值数据

这些缺口不能用模型猜测填补，也不能宣称当前结构覆盖了所有聊天平台能力。

| 缺口                                  | 价值与后续获取方式                                                                                                                |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 群名称、频道主题、群公告              | 解释当前讨论背景；从平台群／频道接口按需获取并带缓存时间，避免每条消息查询                                                        |
| 成员群名片、昵称与角色更新            | 昵称变化后仍识别同一成员；通过成员资料接口及更新事件维护会话内缓存；不要默认跨平台 ID 是同一人                                    |
| 讨论串／话题 ID、转发原始作者与来源链 | 将回复关联到正确话题；当前仅有回复 ID 和已解析转发内容，需适配器提供真实线程及来源字段                                            |
| 消息段顺序、表情、卡片、投票、位置    | 区分文字和附件的位置、识别非文字消息；当前 OneBot 有些段未规范化，需逐类定义语义并保留“未解析”状态                                |
| 表情回应详情                          | “谁给哪条消息点了什么”有社交含义；目前只有事件种类，具体表情、操作者和目标需适配器补充                                            |
| 更完整的跨条消息链                    | 已将成功发送回执、引用别名、实际回复目标及本轮来源写入历史，并支持精确查询和直接关联展开；无平台回执的旧记录仍无法恢复真实消息 ID |
| 记忆整理中的结构化关系                | 历史归档已新增消息上下文并兼容旧库，冷引用可回查当前会话历史；记忆提炼仍主要消费文本，尚未升级为关系感知提炼                      |
| 上下文整体预算                        | 各字段已有上限，但批次字符预算主要统计正文和引用；进一步引入上下文成本计算，优先保留身份、时间和回复关系                          |

历史／回执关联已接通；下一步补平台资料缓存、消息段语义和记忆提炼的关系输入。这些比继续增加没有来源保证的字段更能改善连续对话。

## 历史关系读取

`search_chat_history` 支持 `messageId` 精确匹配平台消息 ID 或引用别名。结果返回 `messageId`、`referenceId`、`replyToId`、`sourceMessageId` 和可用的消息上下文。`replyToId` 是实际发送时的引用目标，`sourceMessageId` 是触发这一轮的输入，群批次中二者可以不同。

`get_chat_context` 同时返回相邻消息与 `related` 直接回复关系。相邻消息不自动视为互相回应。缓存中找不到引用时，按当前会话及保留期查询归档；关闭历史时不回查。收到编辑／撤回事件会使旧归档失效，编辑后的用户消息重新入库。已经提炼出的长期记忆不在本次自动撤销范围内。

旧数据库通过新增可空关系列及默认元数据列迁移，原始记录保留。旧记录和成功发送但未获 ID 的记录标记 `platformIdKnown=false`；不补造平台 ID。
