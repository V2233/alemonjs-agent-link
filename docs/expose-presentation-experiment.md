# Expose 角色化结果表达实验

日期：2026-10-30。范围：本地隔离协议实验，无真实玩家操作，无平台消息发送，无真实模型请求。未接入生产聊天链路。

## 问题与结论

让业务插件声明哪些执行结果可由 AI 用当前角色语气表达，同时保持服务端结算权威。实验使用已安装的真实 alemonjs Expose 注册、发现、调用与输出校验；业务处理器和模型叙述器为测试替身。

结论：可行，但正式通用协议需要框架扩展。现有框架的 describeActions 只选择 description、params、returns、inputSchema、outputSchema、effect，新加 presentation 元数据不会出现在 list() 结果中。本地真实调用证实这一点。另一方面，声明在 outputSchema 中的 presentation 对象可以正常随执行结果返回，足以做兼容性原型。

不能把“八项测试通过”理解为真人游戏体验或模型准确性已经验证。

## 当前实验协议

采用输出信封 `data.presentation`，不是已发布的框架元数据扩展：

```json
{
  "presentation": {
    "mode": "ai",
    "delivery": "pending",
    "outcome": "success",
    "text": "境界：筑基初期；消耗：筑基丹2颗；剩余：3颗。"
  }
}
```

- mode：raw 或 ai，表示本次结果是否选择角色化表达。
- delivery：pending、sent、unknown，由提供方报告本次实际发送状态。仅有发送意图不能报告 sent。
- outcome：success、failure、partial、unknown，是业务结果，不等于 Expose 的 ok。ok 仅表示调用和输出契约通过。
- text：插件生成的权威结果原文，适配器直接拼接保留，不要求模型重写。

适配器只返回发送计划，不发送消息，不重复执行业务。它只接受经过 Expose schema 校验的实验信封；不能直接用于未经校验的外部 JSON。正式接入应按协议版本显式选择解析器，不能把任意旧接口同名字段识别为新协议。

## 已验证结果

| 场景                           | 结果                                           |
| ------------------------------ | ---------------------------------------------- |
| 给动作增加 presentation 元数据 | 真实 list() 未返回该字段，证实框架需增加透传   |
| 完整输出 schema 中声明表达信封 | 真实 call() 返回通过校验的表达信封             |
| 成功结果且允许 AI 表达         | 模拟角色反馈后直接拼接权威原文                 |
| 叙述器抛异常                   | 回退权威原文，不重执行业务；执行次数保持 1     |
| 提供方报告 sent                | 返回 already_sent，跳过叙述                    |
| 提供方报告 unknown             | 返回发送状态待核对提示，跳过叙述               |
| 业务 failure、partial、unknown | 本阶段直接保留原文，不角色化                   |
| raw、旧结果、调用失败          | 分别走原文、旧协议、错误路径                   |
| 叙述器编造额外奖励             | 固定原文仍完整，但虚假叙述仍可出现：验证出限制 |

## 关键限制与设计修正

固定结果区能防止关键结果被改写或遗漏，不能保证 AI 前缀没有矛盾或虚构。测试故意让叙述器返回“额外获得一万灵石”，适配器仍会接受；该用例是限制的证据，不是准确性成功证据。

原型中仅通过提示词要求陪伴反馈不新增事实。要获得程序级保证，应让 AI 选择受限反馈意图，再由程序渲染经过审核的角色短句；自由表达可以作为另一种明确有生成风险的模式。二次模型审核只能降低风险，不能充当绝对保证。

sent 分支仅防止本次计划重复播报，不解决网络超时、进程重启和并发重试的端到端幂等。正式发送层需要以 callId 与目标会话建立持久发送记录；业务幂等和消息发送幂等分开管理。

原型没有叙述超时、取消信号、额度计费、数据最小化、模型提示注入防护验证，也没有真实平台图文发送验证；不得直接挂到生产链路。

## 正式落地修改清单

### alemonjs 框架

扩展 ExposeActionMeta 和 ExposeActionDescription，定义有版本号的静态表达声明；同步注册校验、克隆快照、list/schema 透传与类型导出。未知版本应回退既有流程。表达声明不能改变 authorize、effect、执行超时或幂等语义。

静态声明建议包含允许模式、权威结果路径、表达数据白名单。每次回执提供业务 outcome 和 delivery。初版优先让插件提供完整权威结果文字，避免 requiredFields 嵌套路径和格式化规则未定义就进入通用协议。

### 业务插件

选择一个无真实资产风险的动作试点，返回真实服务端结算与明确表达契约。插件已发送图文时准确报告 delivery；只返回数据时交给 AgentLink。旧动作默认沿用原行为。突破仅为本地模拟示例，本实验没有修改修仙插件。

### AgentLink

在 Expose 结果适配层识别显式版本协议，保留原始回执。表达阶段不得调用游戏工具，不再执行业务。统一提供超时、取消、额度限制和原文回退；固定结果由最终发送层追加，不能再经过自由改写钩子。MCP 和工具聊天路径应共享表达语义。

将 already_sent/unknown 送入最终回复决策，不能仅把提示放进模型上下文期待其自行避免重复。多个动作的结果按 callId 聚合，逐项记录发送状态。

## 下一阶段验收

先确定自由表达与受限反馈的产品选择，再修改框架源码和提供方协议。随后用真实模型验证成功、失败、部分成功、结果未知、恶意文本、重复请求与多动作组合；最后在测试账号和平台沙箱验证发送及重启幂等。

本实验结论支持继续实现通用协议，不支持声称框架扩展、真实修仙集成或线上拟人化体验已经完成。
