# 人格、心情与自动表达

人格选择和心情按平台与会话隔离；全局人格文件只能由主人私聊修改。它们只调整表达，不授予工具权限。

## 人格

- `/人格`：查看当前选择和可用编号。
- `/人格 使用 tea`：切换当前会话；`/人格 使用 默认`：恢复配置默认。群内需要管理员或主人，私聊本人可切换自己的会话。
- 主人私聊 `/人格 保存 tea 茶友|用温和简短的中文回应。`：创建或修改基础提示词。
- 主人私聊 `/人格 查看 tea`、`/人格 删除 tea`：查看、删除文件。删除前会将显式选择该人格的会话重置回默认；配置的 `defaultId` 使用它时，需要先修改配置。
- 主人私聊 `/人格 追加 tea 喜欢聊茶`、`/人格 查看追加 tea`、`/人格 清空追加 tea`：管理追加设定，保留基础提示词。

切换会取消旧生成与待处理消息，再更换选择并开始新话题，保留长期记忆与心情。编辑文件或追加设定仅影响下一轮；进行中的请求使用原提示词快照。追加设定按人格保存，对所有使用者下一轮生效。

未显式选择人格时沿用现有 `persona` 和 `defaultSystemPrompt`。只有会话选择或 `modules.settings.persona.defaultId` 指定编号时，才使用对应文件。

文件位于 `workspaceRoot` 同级的 `personas/<id>.json`：

```json
{
  "id": "tea",
  "name": "茶友",
  "tags": ["茶", "日常"],
  "prompt": "用温和简短的中文回应。不要编造经历。",
  "privateRules": "与已验证主人私聊时，可以采用更熟悉的称呼。",
  "socialRules": "与其他人交谈时，避免泄露主人私聊内容。"
}
```

规则顺序为基础提示词、场景规则、公共规则、主人追加设定。只有已验证主人私聊采用 `privateRules`；其他私聊与所有群聊采用 `socialRules`。标签用于管理列表，尚不按标签自动切换人格。

另有一条轻量语气画像：群聊从最近群消息、私聊从对方最近发言统计长度、标点和常见语气词，作为风格参考注入提示。它只跟随语气，不照抄原句、不改变权限；样本不足或读取失败时不注入。

群聊非直接回复（自主插话、已加入话题后的接话）超过 220 字时，会在最近句末收住；没有合适句末才加省略号。代码块、链接和表格不截断；明确提问的直接回复不受这个软上限限制。

编号为小写字母开头的字母、数字和短横线，最多64字符。基础提示词最多12000字符，场景规则各4000字符，公共规则及追加设定各4000字符。单文件最多64 KiB，内置与自定义合计最多102项。无效文件和符号链接不会静默回退。删除内置编号的覆盖文件后恢复内置内容。

## 心情

`/心情` 查看当前会话状态和最近5次变化。默认启用，基线60，范围0–100，每6小时将偏离基线的幅度减半，重启后按实际经过时间恢复。

直接表达的少量明确称赞或侮辱在生成前改变状态，每条最多 +4 或 -6，同一会话10秒内不重复叠加关键词变化。引用、明显否定、命令文本和用户自述的难过不作为关键词扣分。群内旁听不做此类判断。

可选模型复核在正文完整送达后执行，使用当前聊天模型，不传工具；最多2个并发任务，5秒超时，置信度至少0.8，单次总影响限定在 -6 至 +6。结果替代本条输入的关键词影响，避免重复加分。新消息、彻底清理或取消使旧判断失效。失败或低置信度保留原状态，不阻塞回复。

每个会话只保留20次变化和256个输入摘要用于去重，不保存判断原文或模型理由。模型复核启用后，最多2000字符的当前发言会发给配置的模型。关键词判断发生在生成前，生成或发送失败不撤销已观察到的直接表达。

## 配置

合并到已有配置；媒体服务、音色与表情目录见[媒体能力](media.md)。

```yaml
alemonjs-agent-link:
  modules:
    disabled: [] # persona 或 mood 可停用对应模块
    settings:
      persona:
        # defaultId: 'tea' # 省略时沿用现有默认提示词
        commonRules: '遵循事实，不编造已完成的操作。'
      mood:
        baseline: 60
        halfLifeHours: 6
        modelJudge: true
      expression:
        automatic: true
        voiceChance: 0.15
        stickerMode: either # either=只发文字或只发匹配表情；both=正文后再补一张
        stickerChance: 0.6 # 普通场景尝试相关表情的基础概率，两种模式均适用
        stickerFallback: false # both 模式普通补图无匹配时是否随机；不覆盖明确意图或引述/否定
        stickerIntentAlways: true # 在不在/晚安等明确意图优先尝试表情
        modelVoice: false # 允许模型用 <voice>...</voice> 主动选择语音；开启后会缓冲整段回复
        socialPolish: true # 群聊短回复疑似客服腔时，用便宜模型改写一次；失败回退原文
        delayMs: [0, 0] # 0–3000毫秒
```

自动表达默认开启；未配置语音引擎或表情目录时自然回退文字。`modelVoice` 默认关闭：开启后模型可以把要说的内容放进 `<voice>...</voice>` 主动要求语音，标签会被移除并合成语音；未配置 TTS、合成失败或回复过长时回退文字。开启会让该会话的回复先缓冲再发送，不再走流式首字，延迟更高，按需启用。

`socialPolish` 默认开启，只作用于群聊非直接回复，且只在出现“作为AI/我这边/希望对你有帮助/好的主人”等客服腔或模板结尾时触发一次便宜模型改写；代码、链接、表格和长文不送检。改写失败、超时、预算不足或结果不合格时保留原文，不阻塞发送。

按消息编号固定抽样；愉快时选择阈值略增，低落时降低，心情变化也会改变阈值。自动语音用于最多240字符且没有代码块、网址或表格的短回复，并遵守媒体字符上限。失败回退普通正文；显式 `/语音` 保留失败提示。

默认 `stickerMode: either`：**表情优先；表情能独立表达就不发文字，表情之外还有信息才补文字。**

- 用户说“在不在/在吗/晚安/笑死”等明确意图时，优先名称精确匹配（如“在呢”），也可匹配预定义的完整标签；如“大笑/爆笑/搞笑”可回应“哈哈哈”，“拥抱/心疼/拍拍”可回应“难过”。不做任意关键词或名称子串兜底，单独“日常/回应/问候”这类宽标签不够。
- 如果用户只说了“在不在”，或回复只是“在的呀/在呢”这类寒暄，表情发送后**不再发正文**。
- 如果用户还提了别的要求（“在不在，顺便看看服务器”），或回复包含数字、链接、步骤、建议等额外信息，**先发表情，再补一条文字**；不会把文字和表情合成一条。
- 没有匹配素材、近期去重或发送失败时，保留正常文字回复。
- `stickerIntentAlways: true` 让明确意图优先尝试，不再受 `stickerChance` 概率限制。
- `stickerIntentAlways: false` 时，`either` 模式下的明确意图按 `stickerChance` 抽样尝试匹配表情；`both` 模式仍按概率在正文后补一张。`stickerFallback` 只控制普通补图无匹配时是否随机：已识别明确意图却无相应素材时仍保留文字，引述/否定/解释问句中的已识别情绪词也不会触发随机兜底。
- 群聊自动接话也可用匹配表情回应；模型明确返回 `[沉默]` 时不发图。关闭 `stickers` 模块后自动选图停止。
- 自动选图避开当前会话最近 30 分钟成功发出的最后 3 张，找不到合适新图则保留文字；主动工具发送成功也纳入近期记录。近期记录仅存在进程内。
- 自动选择会参考用户意图、表情名称、分类、`context`、标签和心情；例如“在不在”优先“在呢”，“晚安”优先“晚安”。心情只给已有相关候选加权，不凭自身心情从无关素材中选图；已识别的用户意图要求具体名称或标签匹配，不能仅用分类/用途加分让无关图入选。
- 招呼与单一明确情绪同时出现时，先匹配情绪，例如“在吗，我好难过”选安慰而非“在呢”。同时命中多种不同反应或多个招呼时，自动选图保留文字，不按词表顺序猜测；普通补图和随机兜底同样遵守。它仍是有限词表规则，不能理解所有转折、反讽或隐含情绪。
- 显式让肥鱼发表情（`send_sticker` 工具）仍可能产生文字+表情，因为那是模型主动调用工具；自动表达默认走 `either`。

表情发送和 `/表情` 不设置插件层冷却，发送频率由框架控制；发送失败会回退文字，不会重发已送达正文。自动收藏和标签配置见[媒体能力](media.md)。

没有选中自动语音时保留现有 QQ 原生流式路径；选中时缓冲回复以便合成。延时在首次实际发送前执行，可被取消，默认0。低落时延长非直接插话的冷却，最多至原配置的2倍；不会缩短既有冷却或突破静默时段、小时限额和突发刹车，直接唤醒沿用原规则。

## 数据与验证

选择和追加设定在 `personas.sqlite`，心情在 `moods.sqlite`，均位于 `workspaceRoot` 同级。心情随 `retentionDays` 清理。会话彻底清理删除该会话的选择、心情及历史，保留全局人格文件和主人追加设定。`/new` 不删除这些长期状态。

测试覆盖本地文件与 SQLite、会话重置和取消、模型实际请求内容、迟到判断、媒体失败回退、静默不发送及无媒体时的 QQ 原生流式路径。模型及平台响应使用模拟服务与回执；真人多轮表现、真实 TTS 音质与 QQ 收发仍需实际账号验收。

### 表达方式的选择

文字是日常默认。问候、笑声等短社交回应有具体匹配表情时，可以只发表情；“肥鱼在吗”“哈哈哈”等称呼和语气词不会强制再补一句文字。表情优先固定名称，再用具体表达标签匹配，不因“日常”之类宽泛标签随便选图。用户难过时匹配安慰类表情；转述、否定和求解释不作为直接情绪触发。回复含有事实、步骤或其他表情无法承载的内容时保留文字。

自动语音仅在少数强烈情绪场景考虑：已有较低心情并受到直接冒犯，或愉快状态下分享明确的重大喜讯；实际生成的回复也必须在表达对应情绪。普通早晚安、重逢、一般难过不会单凭关键词触发语音。这里只选择表达媒介，不改变人物性格、关系定义或已有心情记录；低心情本身不等于愤怒，也不保证语音引擎能合成咆哮等情绪音效。

`voiceChance` 是满足场景后的基础抽样概率。自动语音遵守会话免打扰时段，至少间隔 10 分钟和两轮非语音回复，每小时最多两次，短回复上限 100 字。模型 `<voice>` 标签同样经过这些检查。频次记录在进程内，重启会重置，合成失败也保留本次间隔以避免连续重试。用户明确要求语音时可越过自动频次与时段限制，但仍尊重语音总开关；`speak_text` 仅用于本轮明确要求语音的请求。`/群设置 语音 自动关闭` 关闭自发语音。合适的表情能完整表达时，优先表情；有额外内容时补文字，不再追加自发语音。

去客服腔的二次改写仅用于简单闲聊措辞；包含数字、金额、版本、引用、否定、不确定性或完成状态的原文直接保留，改写候选新增这类内容也会被拒绝。此检查是保守拦截，不代表能证明任意两句话语义相同。

### 共同经历与事项追溯

记忆启用且自动整理打开时，回复前会从当前会话尚未处理的真实归档中整理约定、纠正、取消及有用经历。来源按序号分批处理；模型输出须通过原文、人物和版本检查，事项变更与处理进度一起提交。整理超时或失败不阻止当前回复，未提交部分留待后续重试。

事项保存 discussed（讨论）、agreed（约定）、cancelled（取消）、claimed_done（声称完成）及历史版本。这些状态都不证明外部操作成功。已有业务工具生成的 event 经历可通过 link_shared_execution 关联；主观日记不能作执行证据，关联也不会自动恢复取消的事项。当前适配的执行来源包括 bili_watch 实际取得的视频资料，未读取的画面和声音不会记成看过。

回复前提供当前发言人最近五项事项的简要内容、时间和来源序号；完整证据可用 inspect_shared_thread、read_chat_episode 逐步查阅。没有匹配的近期问答只是备用背景，不能强认与当前问题相关。

可运行 `node scripts/replay-shared-memory.mjs`，使用当前配置的真实模型与临时数据库回放约定、多人隔离、纠正、取消、重建上下文和执行状态追问。它会消耗模型额度，不向 QQ 发送消息；报告写入 `.data/agent-link/validation/shared-memory-replay.json`。该回放不是线上账号发送验收。
