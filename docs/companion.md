# 人格、心情与自动表达

人格选择和心情按平台与会话隔离；全局人格文件只能由主人私聊修改。它们只调整表达，不授予工具权限。

## 人格

- `/人格`：查看当前选择和可用编号。
- `/人格 使用 tea`：切换当前会话；`/人格 使用 默认`：恢复配置默认。群内需要管理员或主人，私聊本人可切换自己的会话。
- 主人私聊 `/人格 保存 tea 茶友|用温和简短的中文回应。`：创建或修改基础提示词。
- 主人私聊 `/人格 查看 tea`、`/人格 删除 tea`：查看、删除文件。删除前会将显式选择该人格的会话重置回默认；配置的 `defaultId` 使用它时，需要先修改配置。
- 主人私聊 `/人格 追加 tea 喜欢聊茶`、`/人格 查看追加 tea`、`/人格 清空追加 tea`：管理追加设定，保留基础提示词。

切换会取消旧生成与待处理消息，再更换选择并开始新话题，保留长期记忆与心情。编辑文件或追加设定仅影响下一轮；进行中的请求使用原提示词快照。追加设定按人格保存，对所有使用者下一轮生效。

未显式选择人格时沿用现有 `persona` 和 `defaultSystemPrompt`。只有会话选择或 `modules.settings.persona.defaultId` 指定编号时，才使用对应文件。

文件位于 `workspaceRoot` 同级的 `personas/<id>.json`：

```json
{
  "id": "tea",
  "name": "茶友",
  "tags": ["茶", "日常"],
  "prompt": "用温和简短的中文回应。不要编造经历。",
  "privateRules": "与已验证主人私聊时，可以采用更熟悉的称呼。",
  "socialRules": "与其他人交谈时，避免泄露主人私聊内容。"
}
```

规则顺序为基础提示词、场景规则、公共规则、主人追加设定。只有已验证主人私聊采用 `privateRules`；其他私聊与所有群聊采用 `socialRules`。标签用于管理列表，尚不按标签自动切换人格。

编号为小写字母开头的字母、数字和短横线，最多64字符。基础提示词最多12000字符，场景规则各4000字符，公共规则及追加设定各4000字符。单文件最多64 KiB，内置与自定义合计最多102项。无效文件和符号链接不会静默回退。删除内置编号的覆盖文件后恢复内置内容。

## 心情

`/心情` 查看当前会话状态和最近5次变化。默认启用，基线60，范围0–100，每6小时将偏离基线的幅度减半，重启后按实际经过时间恢复。

直接表达的少量明确称赞或侮辱在生成前改变状态，每条最多 +4 或 -6，同一会话10秒内不重复叠加关键词变化。引用、明显否定、命令文本和用户自述的难过不作为关键词扣分。群内旁听不做此类判断。

可选模型复核在正文完整送达后执行，使用当前聊天模型，不传工具；最多2个并发任务，5秒超时，置信度至少0.8，单次总影响限定在 -6 至 +6。结果替代本条输入的关键词影响，避免重复加分。新消息、彻底清理或取消使旧判断失效。失败或低置信度保留原状态，不阻塞回复。

每个会话只保留20次变化和256个输入摘要用于去重，不保存判断原文或模型理由。模型复核启用后，最多2000字符的当前发言会发给配置的模型。关键词判断发生在生成前，生成或发送失败不撤销已观察到的直接表达。

## 配置

合并到已有配置；媒体服务、音色与表情目录见[媒体能力](media.md)。

```yaml
alemonjs-agent-link:
  modules:
    disabled: [] # persona 或 mood 可停用对应模块
    settings:
      persona:
        # defaultId: 'tea' # 省略时沿用现有默认提示词
        commonRules: '遵循事实，不编造已完成的操作。'
      mood:
        baseline: 60
        halfLifeHours: 6
        modelJudge: true
      expression:
        automatic: true
        voiceChance: 0.15
        stickerMode: either # either=只发文字或只发匹配表情；both=正文后再补一张
        stickerChance: 0.35 # 仅 both 模式下的补发概率
        stickerFallback: false # both 模式下没有匹配时是否随机挑一张
        stickerIntentAlways: true # 在不在/晚安等明确意图优先尝试表情
        modelVoice: false # 允许模型用 <voice>...</voice> 主动选择语音；开启后会缓冲整段回复
        delayMs: [0, 0] # 0–3000毫秒
```

自动表达默认开启；未配置语音引擎或表情目录时自然回退文字。`modelVoice` 默认关闭：开启后模型可以把要说的内容放进 `<voice>...</voice>` 主动要求语音，标签会被移除并合成语音；未配置 TTS、合成失败或回复过长时回退文字。开启会让该会话的回复先缓冲再发送，不再走流式首字，延迟更高，按需启用。按消息编号固定抽样；愉快时选择阈值略增，低落时降低，心情变化也会改变阈值。自动语音用于最多240字符且没有代码块、网址或表格的短回复，并遵守媒体字符上限。失败回退普通正文；显式 `/语音` 保留失败提示。

默认 `stickerMode: either`：**表情优先；表情能独立表达就不发文字，表情之外还有信息才补文字。**

- 用户说“在不在/在吗/晚安/笑死”等明确意图，且库里有**名称精确匹配**的表情（如“在呢”）时，先发该表情。
- 如果用户只说了“在不在”，或回复只是“在的呀/在呢”这类寒暄，表情发送后**不再发正文**。
- 如果用户还提了别的要求（“在不在，顺便看看服务器”），或回复包含数字、链接、步骤、建议等额外信息，**先发表情，再补一条文字**；不会把文字和表情合成一条。
- 没有精确匹配、冷却中、发送失败等情况，回退为正常文字回复。
- `stickerIntentAlways: true` 让明确意图优先尝试，不再受 `stickerChance` 概率限制。
- `stickerChance` 和 `stickerFallback` 只在 `stickerMode: both` 下生效：旧行为是先发正文、再补一张表情（`stickerFallback` 控制没匹配时是否随机）。
- 自动选择会参考用户意图、表情名称、分类、`context`、标签和心情；例如“在不在”优先“在呢”，“晚安”优先“晚安”。
- 显式让肥鱼发表情（`send_sticker` 工具）仍可能产生文字+表情，因为那是模型主动调用工具；自动表达默认走 `either`。

表情发送和 `/表情` 共用冷却；发送失败会回退文字，不会重发已送达正文。自动收藏和标签配置见[媒体能力](media.md)。

没有选中自动语音时保留现有 QQ 原生流式路径；选中时缓冲回复以便合成。延时在首次实际发送前执行，可被取消，默认0。低落时延长非直接插话的冷却，最多至原配置的2倍；不会缩短既有冷却或突破静默时段、小时限额和突发刹车，直接唤醒沿用原规则。

## 数据与验证

选择和追加设定在 `personas.sqlite`，心情在 `moods.sqlite`，均位于 `workspaceRoot` 同级。心情随 `retentionDays` 清理。会话彻底清理删除该会话的选择、心情及历史，保留全局人格文件和主人追加设定。`/new` 不删除这些长期状态。

测试覆盖本地文件与 SQLite、会话重置和取消、模型实际请求内容、迟到判断、媒体失败回退、静默不发送及无媒体时的 QQ 原生流式路径。模型及平台响应使用模拟服务与回执；真人多轮表现、真实 TTS 音质与 QQ 收发仍需实际账号验收。
